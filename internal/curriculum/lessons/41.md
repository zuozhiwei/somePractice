# 在独立环境用 Compose 复建整套看板
沿用已经验收过的前端 dist、后端 app.jar 和完整 schema。用独立目录 `compose-lab` 开一份实验，沿用原 systemd 部署作为对照。准备 `web/dist`、`server/app.jar`、`database/01-schema.sql` 与 `web/site.conf`。使用完整 schema 及所需初始数据的练习副本。数据库、缓存、后端和网页之间用服务名通信。

后端文件 `server/Dockerfile`：

```dockerfile
FROM eclipse-temurin:17-jre
WORKDIR /app
COPY app.jar /app/app.jar
ENTRYPOINT ["java","-jar","/app/app.jar"]
```

前端文件 `web/Dockerfile`：

```dockerfile
FROM nginx:alpine
COPY dist/ /usr/share/nginx/html/
COPY site.conf /etc/nginx/conf.d/default.conf
```

在 `site.conf` 中使用 `server { listen 80; root /usr/share/nginx/html; location / { try_files $uri $uri/ /index.html; } location /api/ { proxy_pass http://server:8080; } }`。在 `compose-lab/compose.yaml` 中写下依赖关系。下面用额外的 Redis 延续前章缓存功能，通过 Docker 网络访问数据库和缓存，仅在本机 8090 发布网页。

```yaml
services:
  db:
    image: mysql:8.4
    environment:
      MYSQL_DATABASE: todo_db
      MYSQL_USER: board
      MYSQL_PASSWORD: ${DB_PASSWORD:?set DB_PASSWORD}
      MYSQL_ROOT_PASSWORD: ${DB_ROOT_PASSWORD:?set DB_ROOT_PASSWORD}
    volumes:
      - board-data:/var/lib/mysql
      - ./database:/docker-entrypoint-initdb.d:ro
    healthcheck:
      test: ["CMD-SHELL", "MYSQL_PWD=$$MYSQL_PASSWORD mysql -h 127.0.0.1 -u $$MYSQL_USER -D todo_db -e 'SELECT 1 FROM task LIMIT 1'"]
      interval: 5s
      timeout: 3s
      retries: 25
  redis:
    image: redis:7-alpine
  server:
    build: ./server
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_started
    env_file: ./server.env
    environment:
      SPRING_DATASOURCE_URL: jdbc:mysql://db:3306/todo_db
      DB_USER: board
      DB_PASSWORD: ${DB_PASSWORD:?set DB_PASSWORD}
      SPRING_DATA_REDIS_HOST: redis
      SERVER_ADDRESS: 0.0.0.0
      SERVER_PORT: 8080
  web:
    build: ./web
    ports: ["127.0.0.1:8090:80"]
    depends_on: [server]
volumes:
  board-data:
```

把两项**不同的练习密码**放在本机权限受限的 `.env`，实际应用读取的签名密钥等附加变量放入 `server.env`，都加入 .gitignore。先 `docker compose config -q` 检查格式，再 `docker compose up -d --build` 和 `docker compose ps`。等待应用完成启动，再从 `http://127.0.0.1:8090` 创建一条练习任务。空数据库卷才执行初始化脚本；再次启动同一卷会保留数据。若前端可打开但 API 返回 502，查看 `docker compose logs --tail 50 server` 和数据库健康状态。校园主机可用 SSH 本机端口转发验收。[Compose 服务就绪与启动顺序](https://docs.docker.com/compose/how-tos/startup-order/)

## 任务 149 | 编写 Dockerfile

## 任务 150 | 编写 docker-compose
用 db、server、web 三个核心服务和上一阶段需要的 redis 服务完成组装。指出容器内的 `db:3306` 和宿主机的 `127.0.0.1:8090` 分别由谁访问。提交去除凭据的配置模板、`docker compose config -q` 结果及数据卷名称。

## 任务 151 | 一键启动全栈
执行 `docker compose up -d --build`。结合 ps、服务日志和浏览器读写测试验证各服务，而不只看进程状态。交添加前后列表、重启 server 后再次查询的结果和实际可达范围。本机、校园或已有主机均可。

## 任务 152 | 容器化知识理解
