# 把试运行打包成可重建环境

第 40 关的 HTTPS 站点继续用来邀测。本关另建一个隔离的复现环境，不接现有试运行数据。**Docker Compose** 用一个文件声明多个一起运行的容器。三个容器分别承担 Nginx、Java 和 MySQL；卷是独立于容器保存的数据目录。把这份定义留给下一位同学，他可以从空环境复现同一个树洞。

**开始前**

:::windows

按 Docker 官方说明安装 Docker Desktop，选择 WSL 2 后端，从开始菜单打开 Docker Desktop。本章运行 Linux 容器。在本机 PowerShell 用 `docker version` 与 `docker compose version` 验证。若只有 Client、没有 Server 输出，先确认 Docker Desktop 已启动。［[Docker Desktop Windows 安装](https://docs.docker.com/desktop/setup/install/windows-install/)］

:::

:::mac

打开「关于本机」区分 Apple 芯片与 Intel，按官方说明下载对应 Docker Desktop，放到 Applications 后启动。用终端的 `docker version` 与 `docker compose version` 验证。若只有 Client、没有 Server 输出，先确认 Docker Desktop 已启动。［[Docker Desktop Mac 安装](https://docs.docker.com/desktop/setup/install/mac-install/)］

:::

:::linux

在自己的 Ubuntu 装 Docker Engine 与 Compose 插件，按发行版指引启动 Docker 服务。终端运行 `docker version`、`docker compose version` 验证。［[Docker 在 Ubuntu 的安装](https://docs.docker.com/engine/install/ubuntu/)］

:::

也可在获授权的另一台 Ubuntu 复现实例；这时在 SSH 窗口执行容器命令，访问方式按 [从空环境启动](/level/41?task=151) 的端口转发步骤。

## 任务 149 | 为树洞写可复现的发布定义

### 从哪里开始

在装好 Docker 的本机终端或授权练习机操作。构建物沿用 [候选发布包](/level/37?task=138)，使用单独的 `deploy/compose` 目录。下一卡里的配置仅用于隔离复现，不替换现有试运行站。

### 操作步骤

1. 在同一仓库建 `deploy/compose/`。用第 37 关的方法，把本次构建的 JAR 复制为 `deploy/compose/app.jar`，把 `web/dist/` 的内容放进 `deploy/compose/web/`，把有序结构迁移放进 `deploy/compose/db/`，同样跳过 02-sample.sql，确认其中没有写死库名或插测试用户的语句。这些是待运行文件或复制的产物。把它们和实机使用的 `.env` 排除在 Git，保留 Dockerfile、Compose、代理配置与变量模板。
2. 将 `.dockerignore` 写成三行 `**`、`!app.jar`、`!Dockerfile`，让构建只读取 Dockerfile 和 JAR。再在该目录建立 `Dockerfile`。镜像是运行容器用的文件集合。下例只将已有 JAR 放进 Java 运行镜像，使用独立数字账号 10001 启动应用。

```dockerfile
ARG JAVA_IMAGE
FROM ${JAVA_IMAGE}
WORKDIR /app
COPY --chown=10001:10001 app.jar /app/app.jar
USER 10001:10001
ENTRYPOINT ["java", "-jar", "/app/app.jar"]
```

3. 选维护中的 Java 17、MySQL 8.4 和 Nginx stable 官方镜像，首次拉取后记录它们的确定摘要。下例三条拉取命令可在自己有 Docker 权限的终端执行。

```bash
docker pull eclipse-temurin:17-jre
docker pull mysql:8.4
docker pull nginx:stable
docker image inspect --format '{{index .RepoDigests 0}}' eclipse-temurin:17-jre
docker image inspect --format '{{index .RepoDigests 0}}' mysql:8.4
docker image inspect --format '{{index .RepoDigests 0}}' nginx:stable
```

4. 按顺序把最后三条输出写为 `.env.example` 的 `JAVA_IMAGE`、`MYSQL_IMAGE`、`NGINX_IMAGE` 值，另留两个空值 `DB_ROOT_PASSWORD=`、`APP_DB_PASSWORD=`。复制它为本机受保护的 `.env` 后用不同随机字符串填密码。不同 CPU 架构若不支持这个摘要，要在对应架构构建并记录它自己的值。回到本机仓库根目录运行下面命令。

:::windows

```powershell
Set-Location deploy/compose
if (!(Test-Path .env)) { Copy-Item .env.example .env }
$rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
try {
    foreach ($n in 1..2) {
        $bytes = New-Object byte[] 24
        $rng.GetBytes($bytes)
        [BitConverter]::ToString($bytes).Replace("-", "").ToLowerInvariant()
    }
} finally {
    $rng.Dispose()
}
```

:::

:::mac linux

```bash
cd deploy/compose
if [ ! -e .env ]; then cp .env.example .env; fi
chmod 600 .env
openssl rand -hex 24
openssl rand -hex 24
```

:::

在本机编辑器把两次输出分别粘到两个密码变量值的位置。最后在仓库根目录执行 `git check-ignore deploy/compose/.env`。预期显示该路径；无输出先把它添加到原 `.gitignore`，否则不要提交。镜像摘要可以提交，口令留在本机。

**提交内容**

三条镜像摘要、JAR 对应提交、启动用户及无密钥配置模板。

## 任务 150 | 连通代理、应用和持久库

### 从哪里开始

终端先切到仓库的 `deploy/compose`。确认 [容器构建准备](/level/41?task=149) 已有 `Dockerfile`、`app.jar`、`web/index.html`、`db/` 和本机 `.env`。在这个目录写本卡的三个文件。

### 操作步骤

在 `deploy/compose/` 写 `compose.yaml`。新环境数据库初始化时会从 `db/` 读 SQL。数据库端口和 Java 端口不映射到主机。Nginx 只给主机回环地址开放 8089，本机可访问，远程可用授权 SSH 转发作验证。

```yaml
services:
  db:
    image: ${MYSQL_IMAGE:?set MYSQL_IMAGE}
    environment:
      MYSQL_DATABASE: campus_treehole_staging
      MYSQL_USER: treehole_app
      MYSQL_PASSWORD: ${APP_DB_PASSWORD:?set APP_DB_PASSWORD}
      MYSQL_ROOT_PASSWORD: ${DB_ROOT_PASSWORD:?set DB_ROOT_PASSWORD}
      TZ: UTC
    volumes:
      - data:/var/lib/mysql
      - ./db:/docker-entrypoint-initdb.d:ro
    healthcheck:
      test: ["CMD-SHELL", "MYSQL_PWD=\"$$MYSQL_PASSWORD\" mysql -h 127.0.0.1 -u \"$$MYSQL_USER\" \"$$MYSQL_DATABASE\" -e 'SELECT 1 FROM reply_notifications LIMIT 1' >/dev/null"]
      interval: 5s
      timeout: 4s
      retries: 20
      start_period: 20s
  app:
    build:
      context: .
      args:
        JAVA_IMAGE: ${JAVA_IMAGE:?set JAVA_IMAGE}
    depends_on:
      db:
        condition: service_healthy
    environment:
      SERVER_ADDRESS: 0.0.0.0
      SERVER_SERVLET_SESSION_COOKIE_SECURE: "false"
      SERVER_SERVLET_SESSION_COOKIE_HTTP_ONLY: "true"
      SERVER_SERVLET_SESSION_COOKIE_SAME_SITE: lax
      SPRING_DATASOURCE_URL: jdbc:mysql://db:3306/campus_treehole_staging?connectionTimeZone=UTC&forceConnectionTimeZoneToSession=true
      SPRING_DATASOURCE_USERNAME: treehole_app
      SPRING_DATASOURCE_PASSWORD: ${APP_DB_PASSWORD:?set APP_DB_PASSWORD}
      SPRING_JPA_HIBERNATE_DDL_AUTO: validate
      TREEHOLE_CACHE_PUBLIC_PAGES: "false"
  proxy:
    image: ${NGINX_IMAGE:?set NGINX_IMAGE}
    depends_on:
      - app
    ports:
      - "127.0.0.1:8089:80"
    volumes:
      - ./edge.conf:/etc/nginx/conf.d/default.conf:ro
      - ./web:/usr/share/nginx/html:ro
volumes:
  data:
```

在复制的 Compose 用 `db/` 最后添加 `99-app-grants.sql`，将初始化数据库账号授权收紧。保留这份 Compose 专用 SQL 模板在仓库并注明复制位置，别混入第 39 关的原生主机迁移。

```sql
REVOKE ALL PRIVILEGES, GRANT OPTION FROM 'treehole_app'@'%';
GRANT SELECT, INSERT, UPDATE, DELETE ON campus_treehole_staging.* TO 'treehole_app'@'%';
```

在同目录写 `edge.conf`。照第 38 关为实际子路由添加静态规则。下面默认 `/?post=<ID>`。

```nginx
server {
    listen 80;
    root /usr/share/nginx/html;
    index index.html;
    location / { try_files $uri $uri/ =404; }
    location ^~ /api/ {
        proxy_pass http://app:8080;
        proxy_set_header Host $http_host;
    }
    location ~ /\. { deny all; }
}
```

这份本机 HTTP 复现实例使用合成账号。第 40 关公开入口仍用 HTTPS 与 Secure Cookie。如果打算让容器接替公开站点，要先在受信任的 TLS 网关后接入它，并复测同源、转发协议和 Secure Cookie。

**提交内容**

三服务连接、数据库卷、初始化和健康等待。［参考 [Compose 依赖启动顺序](https://docs.docker.com/compose/how-tos/startup-order/)］

## 任务 151 | 从空环境重新启动一次

### 从哪里开始

保存 [完整容器配置](/level/41?task=150) 后，在本机 `deploy/compose/` 终端启动。浏览器访问 8089 的隔离环境，与第 40 关正式的试运行域名不共用数据。若把这个练习改在另一台授权 Ubuntu 主机运行，直接用下方独立的远程步骤。

### 操作步骤

在自己授权的机器进入 `deploy/compose/`。使用从未运行过的新 Compose 项目名。若示例的 `treehole-drill` 已经有卷，换新名字。

:::windows

```powershell
docker compose -p treehole-drill config --quiet
docker compose -p treehole-drill up -d --build
docker compose -p treehole-drill ps
curl.exe --retry 12 --retry-connrefused --retry-delay 2 -fsS http://127.0.0.1:8089/api/health
```

:::

:::mac linux

```bash
docker compose -p treehole-drill config --quiet
docker compose -p treehole-drill up -d --build
docker compose -p treehole-drill ps
curl --retry 12 --retry-connrefused --retry-delay 2 -fsS http://127.0.0.1:8089/api/health
```

:::

首次启动可能要等 MySQL 完成初始化。8089 暂不可用时用 `docker compose -p treehole-drill logs --tail 40 db app proxy` 定位。来自数据库的权限错误先核对数据库卷是不是从空开始，初始化脚本不会在旧卷上再执行。

**在远程 Ubuntu 运行时**

沿用 [上传候选版本的方法](/level/37?task=138) 的 SSH 账号。在本机仓库根目录运行 `scp -r deploy/compose student@203.0.113.10:~/treehole-drill`，更换账号、地址及一个尚未使用的远程私有目录名。环境文件只用于这套练习。然后在 SSH 窗口执行下方 Ubuntu 命令。首次拉取镜像的 Docker 命令也可在这台主机执行。

```bash
cd ~/treehole-drill
chmod 600 .env
docker compose -p treehole-drill config --quiet
docker compose -p treehole-drill up -d --build
curl --retry 12 --retry-connrefused --retry-delay 2 -fsS http://127.0.0.1:8089/api/health
```

回到自己的电脑，开一个本机终端运行 `ssh -L 8089:127.0.0.1:8089 student@203.0.113.10`。替换账号和地址，保持窗口打开，再在本机浏览器开 `http://127.0.0.1:8089`。这条转发只用于授权访问，不用在防火墙放开 8089。

通过入口注册两位合成同学，A 发一条标记帖，B 留评论。用 `docker compose -p treehole-drill up -d --force-recreate app proxy` 重建这两个容器，等健康恢复，再从无痕窗访问原帖。重启后可能要重新登录，但数据库内容还在。

**提交内容**

空卷启动、浏览和评论结果、重建前后同一帖和回复的证据。

## 任务 152 | 说明数据、备份和回退边界

### 从哪里开始

保留 [第一套可运行的隔离实例](/level/41?task=151)。在终端执行 `docker compose ls` 记下现有项目名。第二套实例要用另一个目录、项目名及端口。

### 操作步骤

在 `docs/deploy.md` 写清四个对象的区别：App 镜像是可重建的代码；`data` 卷是数据库正在用的文件；迁移修改表或旧记录；备份是可恢复到另一库的独立副本。应用回退只需换旧镜像并确保旧应用能读取更新后的结构。恢复数据副本使用第 45 关步骤。

执行 `docker volume ls --filter label=com.docker.compose.project=treehole-drill` 确认卷名。回到仓库根目录，在本机终端运行以下前两行，进入第二套独立文件。打开这份 `compose.yaml`，只把 `127.0.0.1:8089:80` 改为 `127.0.0.1:8090:80`。将这份 `.env` 的两个口令换成另一组本机测试值，接着运行第三、四行。

:::windows

```powershell
$second = Join-Path ([IO.Path]::GetTempPath()) ("treehole-drill-b-" + [guid]::NewGuid().ToString("N"))
Copy-Item -Recurse -LiteralPath deploy/compose -Destination $second; Set-Location $second
docker compose -p treehole-drill-b up -d --build
curl.exe --retry 12 --retry-connrefused --retry-delay 2 -fsS http://127.0.0.1:8090/api/health
```

:::

:::mac linux

```bash
second="$(mktemp -d)"
cp -R deploy/compose/. "$second/" && cd "$second"
docker compose -p treehole-drill-b up -d --build
curl --retry 12 --retry-connrefused --retry-delay 2 -fsS http://127.0.0.1:8090/api/health
```

:::

在 8089 与 8090 分别注册不同的合成账号，并分别发一个清楚的标记帖。查看两套卷及内容没有共享。浏览器 Cookie 不区分端口，用两个浏览器配置或用不同本地主机名各开一个练习环境，以免页面的会话 Cookie 名字相同造成干扰。显示「端口占用」时先检查是不是已经跑了另一套，再为本机练习选择空闲端口。停止在各自目录使用 `docker compose -p 项目名 down`；它还保留卷。

如果第一套跑在远程 Ubuntu，不用在 SSH 中贴本机平台步骤。按 [上一张卡的远程步骤](/level/41?task=151) 将本机准备好的第二份文件上传到不同目录，将端口改为 8090，然后在远程用 `docker compose -p treehole-drill-b up -d --build` 启动。本机另开 SSH 转发 8090 后再访问。

**提交内容**

两个项目名、各自入口和卷、交叉验证表、下一关可用的备份位置。
