# 准备树洞的试运行主机

你会把上章的同一份网站搬到一台能访问的机器。主线使用一台有管理权限的 Ubuntu 24.04 云主机或校内授权虚拟机。正式邀测还需要你能配置的域名或学校提供的 HTTPS 入口。先问清试运行环境是否允许对同学开放。校内机器只通 VPN 时，可以从校内网络完成本章，中后段需用符合外网验收条件的入口。

文中「本机」指写代码的电脑，「主机」指 SSH 登录后的 Ubuntu 机器。远程命令对两种电脑都一样：确认终端已连接主机，再执行带 `sudo`、`systemctl` 或 `/srv/` 的命令。将 `student` 替换为平台分配的普通管理用户，将文档演示 IP `203.0.113.10` 换成你的主机地址。第一次只用虚构内容。建议在自己的 `campus-treehole/docs/deploy.md` 记下一路使用的实际命令。

## 任务 135 | 连接授权的树洞主机

### 从哪里开始

打开本机终端，不在浏览器地址栏输入 shell 命令。先从学校或主机控制台抄下发给自己的公网 IP、普通用户和 SSH 端口。文档中的 203.0.113.10 与 student 都是占位。

### 操作步骤

1. 从云控制台或机房管理员获得主机地址、SSH 用户和主机公钥指纹。若控制台提供命令行，运行 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`，在可信渠道把输出与本机 SSH 第一次显示的指纹对比。SSH 是加密远程终端，主机指纹用于确认连的是你分配到的机器。
2. 在本机连接发给你的主机。自定义 SSH 端口用 `-p` 指定。

:::windows

在 PowerShell 运行 `ssh student@203.0.113.10`。若提示找不到 ssh，可在 Windows 的「设置 → 系统 → 可选功能」中搜索并安装 OpenSSH 客户端，或使用已装好的 Git Bash。

:::

:::mac linux

在系统终端运行 `ssh student@203.0.113.10`。Mac 通常自带 SSH 客户端。Linux 如缺少客户端，可按发行版文档安装 OpenSSH 客户端。

:::

登录后用下面三行核对远程主机、自身身份和所在位置。

```bash
cat /etc/os-release
id
pwd
```

`id` 若显示你直接以 root 登录，优先从平台获得有 sudo 权限的普通管理用户，后面服务本身也会用单独账号。超时时看实例状态和入站 SSH 规则。报 `Permission denied` 则核对登录用户、密钥和端口。

**提交内容**

系统版本、普通管理用户是否可登录、一次不含密钥的终端结果。

## 任务 136 | 区分发布文件和服务端口

### 从哪里开始

保持 [能登录自己的主机](/level/37?task=135) 的 SSH 窗口打开。在远程终端跑监听检查，连接关系则写到本机仓库的 `docs/deploy.md`。

### 操作步骤

将下表抄进实际部署文档并补上配置位置。**反向代理**是替浏览器转交请求的入口服务；它负责让前端和 API 共享域名。后端和数据库仅需要内部监听。

| 访问路径 | 目标 |
| --- | --- |
| 本机到主机 SSH | 发放的 SSH 口，例如 22 |
| 外部浏览器到 Nginx | 80 用于首次验证及跳转，443 提供 HTTPS |
| Nginx 到 Java | 主机回环地址 `127.0.0.1:8080` |
| Java 到 MySQL | 主机回环地址 `127.0.0.1:3306` |
| 维护者到内部指标 | 主机回环地址 `127.0.0.1:8081` |
| 前端和 JAR 版本目录 | `/srv/campus-treehole/releases/<版本>` |
| 正在提供服务的版本 | `/srv/campus-treehole/current` |
| 环境配置、数据库、备份 | 与公开静态根目录分开 |

在主机运行 `sudo ss -lntp`。`LISTEN` 表示某进程正在接某端口，`127.0.0.1` 只接受该主机自己的访问。本章未安装的服务可以尚未出现。把这个表和第 39 关启动后的状态再对一次。

**提交内容**

连接关系及当前已监听的地址。

## 任务 137 | 为运行账号设最小权限

### 从哪里开始

使用 [已核对的 SSH 主机与用户](/level/37?task=135)。在主机用 `id -un` 确认是管理用户，后面的 `sudo` 操作只针对本项目。主机的接口和数据库端口参照 [连接表](/level/37?task=136)。

### 操作步骤

在主机执行。若账号或目录已由平台建立，使用现有分配项。授权之前先用 `id treehole` 检查是否存在该账号。

```bash
sudo useradd --system --user-group --no-create-home --shell /usr/sbin/nologin treehole
sudo install -d -o root -g root -m 0755 /srv/campus-treehole/releases
sudo install -d -o root -g treehole -m 0750 /etc/campus-treehole
```

`treehole` 是只用于运行 JAR 的账号。确认 `sudo -u treehole test ! -w /srv/campus-treehole/releases` 返回成功。第 39 关会为数据库分配单独的读写用户，本机的 root 权限不传给应用。让云控制台入站规则仅允许你分配到的 SSH 口，以及需要提供网页时的 80 和 443。已有主机防火墙时核对它的同样规则；修改 SSH 规则前保持一个已登录窗口，并用第二个窗口确认能重新连接。

再回本机测试 8080 和 3306 无法从外部直连。使用你的主机 IP。待服务启动后再补同样证据，单独的拒绝连接也可能表示服务尚未启动。

:::windows

两次预期都是 `TcpTestSucceeded : False`。

```powershell
Test-NetConnection 203.0.113.10 -Port 8080
Test-NetConnection 203.0.113.10 -Port 3306
```

:::

:::mac linux

两次预期都是超时或连接被拒绝。

```bash
curl --connect-timeout 3 http://203.0.113.10:8080/api/health
nc -vz -w 3 203.0.113.10 3306
```

:::

**提交内容**

运行账号权限、允许的对外端口、第 39 关启动后的外部与本机对照。

## 任务 138 | 上传原作品的候选版本

### 从哪里开始

分两只终端。本机窗口在树洞仓库根目录构建并上传；连到 [已准备好的主机](/level/37?task=137) 的窗口只校验、解包。开始前确认 [发布标签](/level/36?task=134) 已存在。

### 操作步骤

1. 在本机仓库目录执行 `git switch --detach v0.6-observable`。若提示有未保存改动，先提交或将改动放在原分支再切换。完成后用 `git switch -` 返回原分支。
2. 在本机仓库根目录构建后端和前端，两项都成功才继续。从 `server/target` 找到包含 Spring Boot 运行业务类的实际 JAR，避开 `.original`。发布包里统一叫 `app.jar`。

:::windows

```powershell
Push-Location server
.\mvnw.cmd clean verify
if ($LASTEXITCODE -ne 0) { Pop-Location; throw "后端构建失败" }
Pop-Location
Push-Location web
npm.cmd ci
if ($LASTEXITCODE -ne 0) { Pop-Location; throw "前端安装失败" }
npm.cmd run build
if ($LASTEXITCODE -ne 0) { Pop-Location; throw "前端构建失败" }
Pop-Location
```

:::

:::mac linux

```bash
(cd server && ./mvnw clean verify)
(cd web && npm ci && npm run build)
```

:::

3. 在本机把下面的 JAR 文件名和服务器地址换成自己的。该目录只收构建产物和指定的迁移，排除 `.env`、测试账号和数据脚本。检查 db 仅含结构增量，不能有写死数据库名的 USE。空库跳过 02-sample.sql。

:::windows

```powershell
$version = "v0.6-observable"
$jar = "server/target/你生成的实际文件.jar"
if (!(Test-Path $jar) -or !(Test-Path web/dist/index.html)) { throw "先完成构建并检查 JAR 的实际名字" }
$stage = Join-Path ([IO.Path]::GetTempPath()) ("treehole-" + [guid]::NewGuid().ToString("N"))
New-Item -ItemType Directory -Path "$stage/web","$stage/db" -Force | Out-Null
Copy-Item web/dist/* "$stage/web/" -Recurse
Copy-Item $jar "$stage/app.jar"
Get-ChildItem server/db/[0-9]*.sql | Where-Object Name -ne "02-sample.sql" |
    Copy-Item -Destination "$stage/db/"
git rev-parse HEAD | Set-Content -Encoding ascii "$stage/commit.txt"
tar.exe -C $stage -czf "$version.tar.gz" .
if ($LASTEXITCODE -ne 0) { throw "归档失败" }
(Get-FileHash "$version.tar.gz" -Algorithm SHA256).Hash.ToLowerInvariant()
scp "$version.tar.gz" student@203.0.113.10:~/
```

:::

:::mac linux

```bash
version=v0.6-observable
stage="$(mktemp -d)"
mkdir -p "$stage/web" "$stage/db"
cp -R web/dist/. "$stage/web/"
cp server/target/你生成的实际文件.jar "$stage/app.jar"
for migration in server/db/[0-9]*.sql; do
  case "$migration" in */02-sample.sql) continue ;; esac
  cp "$migration" "$stage/db/"
done
git rev-parse HEAD > "$stage/commit.txt"
tar -C "$stage" -czf "$version.tar.gz" .
openssl dgst -sha256 "$version.tar.gz"
scp "$version.tar.gz" student@203.0.113.10:~/
```

:::

4. SSH 到主机，在上传用户的家目录核验 SHA-256，再解包到新目录。该校验值是文件内容的指纹，应该和本机完全相同。若目标版本目录已存在，用另一个新版本号重来，别覆盖别人正用的目录。

```bash
version=v0.6-observable
sha256sum "$version.tar.gz"
sudo install -d -m 0755 "/srv/campus-treehole/releases/$version"
sudo tar --no-same-owner --no-same-permissions -xzf "$version.tar.gz" -C "/srv/campus-treehole/releases/$version"
sudo chmod -R a+rX "/srv/campus-treehole/releases/$version"
cat "/srv/campus-treehole/releases/$version/commit.txt"
```

**提交内容**

版本目录结构、提交号、两边同一归档的 SHA-256。第 38 关才切换静态入口。

## 任务 164 | 用 SSH 密钥安全访问主机

### 从哪里开始

在本机另开终端，保留 [已经登录的 SSH 会话](/level/37?task=135)。首次连接已核对过主机指纹，这次只为自己的同一主机添加用户公钥。

### 操作步骤

在本机新建专用 SSH 密钥，为私钥设置口令。路径已存在时改用新名称。只把后缀 `.pub` 的公钥交给主机，无后缀文件留在本机。

:::windows

```powershell
New-Item -ItemType Directory -Force "$HOME/.ssh" | Out-Null
ssh-keygen -t ed25519 -f "$HOME/.ssh/treehole-staging"
Get-Content "$HOME/.ssh/treehole-staging.pub"
```

:::

:::mac linux

```bash
mkdir -p ~/.ssh
ssh-keygen -t ed25519 -f ~/.ssh/treehole-staging
cat ~/.ssh/treehole-staging.pub
```

如果本机已安装 `ssh-copy-id`，也能运行 `ssh-copy-id -i ~/.ssh/treehole-staging.pub student@203.0.113.10` 添加公钥，然后直接做第二个窗口的验证。

:::

在主机管理界面粘贴上一步的一整行公钥。也可用下面的手工方式写入。

用手工方式时，先在**主机**普通用户终端执行 `mkdir -p ~/.ssh && chmod 700 ~/.ssh`，再用 `nano ~/.ssh/authorized_keys` 在文件末尾另起一行粘贴本机 `.pub` 的一整行。按 Ctrl+O、回车保存，再 Ctrl+X 退出。最后 `chmod 600 ~/.ssh/authorized_keys`。已有公钥留在原位置，不覆盖文件。

保留原 SSH 窗口。在第二个本机终端验证：

:::windows

```powershell
ssh -i "$HOME/.ssh/treehole-staging" -o IdentitiesOnly=yes -o PreferredAuthentications=publickey student@203.0.113.10 'id -un'
```

:::

:::mac linux

```bash
ssh -i ~/.ssh/treehole-staging -o IdentitiesOnly=yes \
  -o PreferredAuthentications=publickey student@203.0.113.10 'id -un'
```

:::

输出是你的管理账户才算成功。登录失败时核对公钥是否进了正确用户的家目录、文件所有者和端口。若学校已规定登录策略，沿用其策略。有意关闭旧方式时从已登录窗口按平台指引处理，并再次验证独立连接。

**提交内容**

公钥登录成功证据和保留或切换的方式。密码、私钥、本机密钥文件内容都留在自己的机器。
