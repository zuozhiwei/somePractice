# 在练习主机上完成第一次可核对的交接
准备一台自己管理的 Linux 虚拟机，或学校分配的练习主机。本章所有验收都可在本机或校园内完成。以下命令里的 `student` 和 `lab-host` 替换为自己的普通账号与主机名/IP。没有现成环境时，可在本机创建 Debian/Ubuntu 虚拟机，使用主机专用网络，在虚拟机控制台安装 `openssh-server`、启动 `ssh` 服务，用 `hostname -I` 查练习网卡地址。

1. 先在虚拟机控制台运行 `hostname`、`whoami`。若是学校主机，向管理员核对 SSH 主机指纹；自己的虚拟机可在控制台用 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` 看指纹。
2. 在自己的电脑运行 `ssh student@lab-host`，确认首次提示的指纹匹配后登录。执行以下只在自己家目录内创建练习目录的命令，把信息写进本地验收记录。

```sh
whoami
hostname
pwd
mkdir -p ~/task-board-lab
cd ~/task-board-lab
ls -la
cat /etc/os-release
free -h
df -h .
```

3. 在本机新建 `proof.txt`，写一句「这是我的看板交接练习」。在**本机终端**运行 `scp proof.txt student@lab-host:task-board-lab/`；在远端用 `cat ~/task-board-lab/proof.txt` 阅读。这个方向要记清：编辑器在本地，服务要从远端磁盘读取。
4. 摘掉命令提示再试一次：让同学给你一个不同的文件名，你能说出应该在哪台机器执行上传、又该在哪里验证吗？遇到超时先核对网络/端口，遇到 Permission denied 则核对账号、密钥与目标目录权限。

## 任务 135 | 准备练习服务器并登录
写明环境来源（个人虚拟机、校园主机或已有服务器）、网络范围和普通登录方式。交同一次会话的 `whoami`、`hostname`、系统版本及 `df -h .` 输出，定位系统盘剩余空间，不提交登录凭据。

## 任务 136 | Linux 常用命令
先用 pwd 记下当前位置，再建并进入 `~/task-board-lab/test`。运行 `ls -la` 观察目录项，`cat /etc/os-release` 找发行版，`free -h` 找 available 列。把这六种操作中每一个命令对应的实际输出与含义各写一行。

## 任务 137 | 为练习主机设置访问规则
在属于自己的虚拟机检查 `ss -ltn` 及实际使用的防火墙规则，列出 22（管理）、8088（后续网页）和 8080（应用内部）的监听地址与可达范围。按选定实验路径让网页只对自己或校园测试端可达；远程调整规则时保留当前 SSH 会话并用第二窗口验证。校园托管环境由管理员维护规则，可交网络拓扑、授权规则或本机虚拟机上的等价验证；记录放行来源与内网服务的理由。

## 任务 138 | 上传文件到服务器
对 `proof.txt` 做一次 SCP 或 SFTP 上传。两端重读文件，再比对 SHA-256（Linux 用 `sha256sum proof.txt`，PowerShell 用 `Get-FileHash proof.txt`）。提交目标相对路径、两端一致的摘要与可公开的练习文字。

## 任务 164 | SSH 密钥免密登录
在自己电脑为本次练习生成专用密钥，例 `ssh-keygen -t ed25519 -f ~/.ssh/task-board-lab`，为私钥设置口令。只把 `.pub` 公钥追加到远端自己账号的 `~/.ssh/authorized_keys`（可用 `ssh-copy-id -i ~/.ssh/task-board-lab.pub student@lab-host`）。远端 .ssh 目录设 700，authorized_keys 设 600。新开窗口带 `-i ~/.ssh/task-board-lab` 登录并运行 whoami；如要求本地私钥口令属正常。交公钥指纹与成功登录结果，说明私钥保存在何处，无需展示密钥内容。
