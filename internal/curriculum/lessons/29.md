# 把树洞接口交给同伴联调

在 `docs/api.md` 按使用对象整理端点。公开读取 `GET /api/posts` 和帖子评论，只返回允许展示的帖子和评论字段。登录后可以发布内容、管理自己的帖子、查看 `GET /api/me/replies` 及举报。审核角色访问 `/api/mod/**`。把分页参数、输入约束、会话与 CSRF 处理、204 无响应体和常见错误一并写清。

开发可选用 OpenAPI 生成本地文档，并由一个测试账号验证文档示例。部署时限制开发接口文档和测试种子入口。给一位同伴四个步骤，让他用接口客户端从读取列表完成到举报与查询结果，记录哪一处文档需要修订。

### 端点契约表

打开 `docs/api.md`。**契约**指调用方和服务约定的方法、地址、输入、状态及输出。保存下面的小表，再把已有实际端点补齐。**联调**指页面和后端操作一起走一遍，确认双方对这些约定理解一致。

| 端点 | 身份 | 示例结果 |
| --- | --- | --- |
| GET /api/posts | 访客 | 200 帖子数组 |
| POST /api/auth/login | 访客，有 CSRF | 204 |
| GET /api/me/replies | 登录本人 | 200 私有数组 |
| POST /api/reports | 登录成员，有 CSRF | 201 举报回执 |
| PATCH /api/mod/reports/{id} | 审核员，有 CSRF | 200 已处理状态 |

给每个写端点一条实际可重试的命令或界面路径。浏览器复现时应从同一个 `localhost:5173` 打开测试页。记录 Cookie 与 CSRF 的字段名，正文中用合成占位符代替值。`204` 后无需解析 JSON。

## 任务 109 | 整理树洞端点与访问对象

### 操作步骤

复用 [审核台跑通的仓库](/level/26?task=101)。从 [本关参考资料「端点契约表」](/level/29?guide=1#端点契约表) 复制表头，参数和结果按自己当前的 Java 文件逐条核对。

1. 在 `docs/api.md` 新建「树洞端点」表。编辑器中分别打开 `PostController.java`、`AuthController.java`、`ReplyController.java`、`ReportController.java` 和 `ModerationController.java`。把类级路径与方法注解拼成完整地址，例如成员收件箱 `GET /api/me/replies`。
2. 每行依次写方法、路径、谁能调用、请求体、成功和常见失败。登录 POST 写表单格式，其余修改正文的接口按实际代码写 JSON。查看第 26 关审核接口，审核失败的权限状态是 403。
3. 从无痕窗口访问 `http://localhost:5173/api/posts/实际ID`，将地址里的说明字替换成数字，再打开 `/api/me/replies`。用两次请求的实际结果填写表里的身份列。

### 验收与排查

同伴只看表可判断三种身份该访问哪个路径。如果 method 和状态写成固定 200，从 Controller 里查 ResponseEntity、ResponseStatus 或删除无正文的 204。

### 提交

端点表和两种权限的实测结果。

## 任务 110 | 给关键端点补齐响应与错误

### 操作步骤

用 [刚整理的端点表](/level/29?task=109) 加真实响应。有重复或失败时，观察开发者工具「响应」的 `code` 字段，延续 [前面定义的举报错误](/level/25?task=95)。

1. 在 [端点表](/level/29?task=109) 下方新增「公开读取」「成员举报」「审核处理」三个标题。每个标题保存自己服务的一份状态与 JSON。GET 用列表中一条合成帖，举报沿用 [举报的本机请求](/level/25?task=94)，审核沿用 [事务验证](/level/26?task=99)。
2. 写一条实际错误示例。对同一帖重发举报，预期 409。对访客读取私有收件箱为 401；普通账号尝试审核为 403；错误字段如把 reason 填 `WRONG` 为 400；隐藏后旧公开地址为 404。
3. 检查 Markdown 小节是否保留 204 的无正文约定：若记录删除响应，用「204，无正文」而不是捏造 JSON。复制网络测试时只取响应，不取 Cookie 或 CSRF 值。

### 验收与排查

同一个状态和 code 能在你的本机应用再次复现。若一份样例写了 `data` 而实际列表是数组，按真实响应改文档，公共读取原数组仍供网页使用。

### 提交

三段真实示例和 400、401、403、404、409 的说明。

## 任务 111 | 让一位同学按文档联调

### 操作步骤

用 [真实响应样例](/level/29?task=110) 交给一位同伴。让他在自己机器或自己的浏览器配置用合成账号操作，无需拿大段脚本重新造同样功能。

1. 给同学一份本地 README 和合成帖 ID，不现场口头指导。请他先访问公开帖，再登录并使用页面或调试客户端提交举报。
2. 让他用同一普通账号打开 `/api/mod/reports?status=OPEN` 并写下真实结果。预期 403。若报告 401，先确认他使用了同源地址且已经登录。
3. 将同伴卡住的位置与真实错误写在文档的复现备注。改进一处说明，让同伴再走一遍。

### 验收与排查

他能读帖、举报，并得到对审核路径的 403。若卡在复制 ID，就在文档的第一条 GET 样例指出在哪个字段读 ID、哪个 URL 使用它。

### 提交

实际联调、原说明和更改后的文本。
