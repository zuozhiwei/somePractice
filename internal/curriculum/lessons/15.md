# 让树洞服务读写 MySQL

上一关用 SQL 写了数据，这一关让 Java 自己读写。**JDBC** 是 Java 连接数据库的接口，MySQL Connector/J 是相应驱动。**JPA** 把数据库表与 Java 类对应。表示一条数据库记录的 Java 类叫作**实体**。**Repository** 负责访问数据库，**DTO** 是接口公开发送或接收的数据形状。继续使用第 13 关接口的五个字段。

### 添加依赖

在 `server/pom.xml` 的已有 `<dependencies>` 内加三个依赖。Spring Boot parent 管理这些依赖的版本。

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <scope>runtime</scope>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
```

### 映射数据库

把四个类都放进 `server/src/main/java/edu/campus/treehole/`。以下是完整的帖子实体。字段上的 `@Column` 明确 Java 名和 SQL 名。`protected Post()` 提供 JPA 读库创建实体的入口。`replace` 只改允许编辑的三列。

```java
package edu.campus.treehole;

import jakarta.persistence.*;
import java.time.LocalDateTime;

@Entity
@Table(name = "posts")
public class Post {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    Long id;
    @Column(nullable = false, length = 100) String title;
    @Column(nullable = false, length = 1000) String body;
    @Column(nullable = false, length = 30) String category;
    @Column(name = "created_at", nullable = false) LocalDateTime createdAt;

    protected Post() {}

    Post(String title, String body, String category, LocalDateTime createdAt) {
        replace(title, body, category);
        this.createdAt = createdAt;
    }

    void replace(String title, String body, String category) {
        this.title = title;
        this.body = body;
        this.category = category;
    }
}
```

```java
// PostRepository.java
package edu.campus.treehole;
import java.util.List;
import org.springframework.data.jpa.repository.JpaRepository;

public interface PostRepository extends JpaRepository<Post, Long> {
    List<Post> findAllByOrderByCreatedAtDescIdDesc();
}
```

```java
// Comment.java
package edu.campus.treehole;
import jakarta.persistence.*;
import java.time.LocalDateTime;

@Entity
@Table(name = "comments")
public class Comment {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    Long id;
    @Column(name = "post_id", nullable = false) Long postId;
    @Column(nullable = false, length = 500) String body;
    @Column(name = "created_at", nullable = false) LocalDateTime createdAt;

    protected Comment() {}

    Comment(Long postId, String body, LocalDateTime createdAt) {
        this.postId = postId;
        this.body = body;
        this.createdAt = createdAt;
    }
}
```

给评论使用数据库外键 `post_id` 与普通 `Long postId` 即可。`CommentRepository.java` 之后用于按帖读取。

```java
package edu.campus.treehole;
import java.util.List;
import org.springframework.data.jpa.repository.JpaRepository;

public interface CommentRepository extends JpaRepository<Comment, Long> {
    List<Comment> findAllByPostIdOrderByCreatedAtAscIdAsc(Long postId);
}
```

## 任务 54 | 配置树洞数据源

用 [建表任务](/level/14?task=51) 的开发库与 [应用帐号](/level/14?task=50)，不要把管理员帐号交给后端。依赖片段在 [本关参考资料「添加依赖」](/level/15?guide=1#添加依赖)。

:::windows

```powershell
$env:SPRING_DATASOURCE_USERNAME = 'treehole_app'
$env:SPRING_DATASOURCE_PASSWORD = '<第14关设置的密码>'
```

:::

:::mac linux

```bash
export SPRING_DATASOURCE_URL='jdbc:mysql://localhost:3306/campus_treehole'
export SPRING_DATASOURCE_USERNAME='treehole_app'
export SPRING_DATASOURCE_PASSWORD='<第14关设置的密码>'
```

:::

保存依赖与实体文件后重新启动。`Access denied` 多半是账号或凭据；`Communications link failure` 先核对数据库是否运行及端口；`Schema-validation: missing ...` 核对启动连接的是不是已建表的开发库。

### 验收与排查

先用应用帐号直接读出 `SELECT COUNT(*) FROM posts;`。如果直接查询成功但 Java 连接失败，在 Java 启动终端核对三个变量，尤其是 URL `jdbc:mysql://localhost:3306/campus_treehole`。

### 操作步骤

打开 [本关参考资料「映射数据库」](/level/15?guide=1#映射数据库)。将四段 Java 代码分别保存。每个文件与 `TreeholeApplication.java` 同级，文件名按对应 public class/interface。

## 任务 56 | 从库读取树洞列表

### 操作步骤

[数据源](/level/15?task=54) 与 [实体](/level/15?task=55) 都能运行后做。这里提供全量控制器，直接替换之前返回固定示例的 `PostController.java`。

将旧 `PostController.java` 替换为下方完整文件。Spring 会把 Repository 传给构造函数，`view` 只复制允许返回的字段。启动后打开 `/api/posts`，合成样例应来自数据库。用 14 关的 `UPDATE ... WHERE id=...` 改标题，刷新接口即应看到变化。

```java
package edu.campus.treehole;

import java.time.LocalDateTime;
import java.time.ZoneOffset;
import java.util.List;
import jakarta.validation.Valid;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Size;
import org.springframework.http.HttpStatus;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/api/posts")
public class PostController {
    final PostRepository posts;

    PostController(PostRepository posts) {
        this.posts = posts;
    }

    @GetMapping
    public List<PostView> list() {
        return posts.findAllByOrderByCreatedAtDescIdDesc().stream()
            .map(PostController::view).toList();
    }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public PostView create(@Valid @RequestBody WritePost input) {
        Post post = new Post(input.title().trim(), input.body().trim(),
            input.category().trim(), LocalDateTime.now(ZoneOffset.UTC));
        return view(posts.save(post));
    }

    static PostView view(Post post) {
        return new PostView(post.id.toString(), post.title, post.body,
            post.category, post.createdAt.toInstant(ZoneOffset.UTC).toString());
    }

    public record PostView(String id, String title, String body,
                           String category, String createdAt) {}
    public record WritePost(@NotBlank @Size(max = 100) String title,
                            @NotBlank @Size(max = 1000) String body,
                            @NotBlank @Size(max = 30) String category) {}
}
```

### 验收与排查

找到一个真实 ID，在 MySQL 中按 [修改一条SQL记录](/level/14?task=52) 将标题改为「从数据库改的一句」。刷新同一 `/api/posts`，相同 ID 的标题须变动。没变时对比 SQL 所在数据库与 JDBC URL，检查是否仍在运行第 13 关的代码。

### 提交

SQL 改动前后的两次接口结果。若是空数组，先 `SELECT COUNT(*) FROM posts;` 看是否有合成数据。

## 任务 57 | 通过接口写一条帖子

### 操作步骤

用 [已读到数据库的控制器](/level/15?task=56)。保留 Java 运行，在第二个终端进入 `server/`。本任务从本地 JSON 文件读取请求正文，方便改动后再次发送。

`POST` 表示创建。`@RequestBody` 将请求正文变成 `WritePost`，`@Valid` 检查空值与长度。编写 `server/db/example-post.json`（虚构数据即可）。

```json
{"title":"图书馆最后一排","body":"晚上九点还会亮灯吗？","category":"DAILY"}
```

从 `server` 目录另开终端，运行下面的请求。`-i` 同时显示状态和正文，`--data-binary` 从 `@` 后的文件读取请求内容。

:::windows

```powershell
curl.exe -i -H "Content-Type: application/json" --data-binary "@db/example-post.json" http://localhost:8080/api/posts
```

:::

:::mac linux

```bash
curl -i -H "Content-Type: application/json" --data-binary "@db/example-post.json" http://localhost:8080/api/posts
```

:::

预期 201 与新的 ID。回到客户端运行 `SELECT id,title FROM posts ORDER BY id DESC LIMIT 1;`，核对同一个 ID。将正文改为空字符串再发送一次，预期 400 且行数不增加。若 415，检查 `Content-Type` 是否为 JSON。

### 验收与排查

记录一个新帖的 ID，GET 目前只有列表，在 `/api/posts` 找到同一条，同时 SQL 可读出。若返回 404 检查 `@PostMapping` 是否保存进当前的 `PostController.java`，修改 Java 后重启。

### 提交

成功、拒绝和 SQL 查回的实际结果。
