# 给树洞加私密账号

本关先让账号能安全注册。**哈希**把密码变成用于校验的固定格式结果。**BCrypt** 算哈希时包含随机盐，同一个密码两次计算可能得到不同结果。登录时用 `matches(输入, 已保存哈希)` 判断。用户名和密码只用于自己登录，树洞公开 JSON 没有用户表的数据。

### 账号表

将 Spring Boot 管理的 `org.springframework.security:spring-security-crypto` 依赖加到 `server/pom.xml` 的 dependencies。本关先使用它的密码工具，第 20 关再启用完整的登录和会话保护。

```sql
-- server/db/03-users.sql
CREATE TABLE users (
    id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(24) NOT NULL,
    password_hash VARCHAR(100) NOT NULL,
    created_at DATETIME(6) NOT NULL,
    CONSTRAINT uq_users_username UNIQUE (username)
);
```

在 `server/src/main/java/edu/campus/treehole/` 创建三个文件。第一份是实体，第二份通过用户名查询。`Optional` 表示查询可以有一个值或没有结果。

```java
// UserAccount.java
package edu.campus.treehole;
import jakarta.persistence.*;
import java.time.LocalDateTime;

@Entity
@Table(name = "users")
public class UserAccount {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY) Long id;
    @Column(nullable = false, unique = true, length = 24) String username;
    @Column(name = "password_hash", nullable = false, length = 100) String passwordHash;
    @Column(name = "created_at", nullable = false) LocalDateTime createdAt;

    protected UserAccount() {}

    UserAccount(String username, String passwordHash, LocalDateTime createdAt) {
        this.username = username;
        this.passwordHash = passwordHash;
        this.createdAt = createdAt;
    }
}
```

```java
// UserRepository.java
package edu.campus.treehole;
import java.util.Optional;
import org.springframework.data.jpa.repository.JpaRepository;

public interface UserRepository extends JpaRepository<UserAccount, Long> {
    Optional<UserAccount> findByUsername(String username);
}
```

### 注册端点

```java
// AuthController.java
package edu.campus.treehole;
import java.nio.charset.StandardCharsets;
import java.time.LocalDateTime;
import java.time.ZoneOffset;
import java.util.Locale;
import java.util.Map;
import org.springframework.dao.DataIntegrityViolationException;
import org.springframework.http.ResponseEntity;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/api/auth")
public class AuthController {
    private final UserRepository users;
    private final BCryptPasswordEncoder passwords = new BCryptPasswordEncoder();

    AuthController(UserRepository users) {
        this.users = users;
    }

    @PostMapping("/register")
    public ResponseEntity<Map<String, Object>> register(@RequestBody Registration input) {
        String username = input.username() == null ? "" :
            input.username().trim().toLowerCase(Locale.ROOT);
        String password = input.password() == null ? "" : input.password();
        if (!username.matches("[a-z0-9_]{3,24}")) {
            return ResponseEntity.badRequest().body(Map.of("message", "用户名用 3–24 位英文、数字或下划线"));
        }
        if (password.isBlank() || password.length() < 8
            || password.getBytes(StandardCharsets.UTF_8).length > 72) {
            return ResponseEntity.badRequest().body(Map.of("message", "密码至少 8 位，UTF-8 编码最多 72 字节"));
        }
        try {
            users.saveAndFlush(new UserAccount(username, passwords.encode(password),
                LocalDateTime.now(ZoneOffset.UTC)));
        } catch (DataIntegrityViolationException duplicate) {
            return ResponseEntity.status(409).body(Map.of("message", "用户名已被使用"));
        }
        return ResponseEntity.status(201).body(Map.of("registered", true));
    }

    public record Registration(String username, String password) {}
}
```

数据库的 UNIQUE 约束在两人同时注册相同用户名时也可以阻止重复。注册日志只用请求结果核对，始终使用虚构账号做练习。

## 任务 72 | 验证 BCrypt 存储

### 操作步骤

在 [注册端点](/level/19?guide=1#注册端点) 搜 `passwords.encode(password)`。学习时使用刚创建的 `learner_a`，记录哈希长度而非整个哈希。

1. 打开 `AuthController.java`，定位 `passwords.encode(password)`。画一条顺序，从收到表单到校验、计算哈希、存表，最后只返回注册状态。
2. 用 MySQL 执行 `SELECT username,CHAR_LENGTH(password_hash) AS stored_length,LEFT(password_hash,4) AS prefix FROM users WHERE username='learner_a';`。通常保存长度为 60，前缀类似 `$2a$`。查询结果里无需出现整个哈希。
3. 查看注册响应与后端日志，确认没有打印请求正文、密码或哈希。下一关用正确及错误密码验证 `matches`，就能观察哈希在登录中的作用。

### 验收与排查

查询有一行、BCrypt 前缀可能为 `$2a$`、`$2b$` 等同类格式。若数据库值大小恰好就是明文长度或被截断，核对 `encode` 的结果是否传入 `UserAccount`，表字段至少 60 位。

### 提交

调用片段和长度、前缀检查结果。

## 任务 73 | 对注册参数给出提示

### 操作步骤

从 [已完成的注册任务](/level/19?task=71) 复用 HTTP 验证。这关把提示和校验稳定下来，下两关再接真实账号表单。

1. 使用 [创建账户时的请求文件和命令](/level/19?task=71)。备份一份本地练习口令，再把临时文件的用户名分别改为 `"ab"`、密码改为 `""`，每次只改一个条件并发请求。
2. 第三次故意使用 25 个「树」字作为练习密码。UTF-8 中一个「树」是 3 字节，25 个就是 75。按同样的请求再测试一次。前两次都要恢复其他合理参数，让失败原因可单独识别。
3. 恢复一个合法的合成密码，改新用户名 `learner_b` 重发。接口可创建后记住响应的提示文本。第 21 关在原页面加注册表单时直接把这些 `message` 交给账号错误区。删除含口令的临时文件。

### 验收与排查

短用户名应提示用户名规则，空密码与超字节应给密码规则。若得到 409，使用一个尚未注册的有效用户名重试，防止被重名覆盖验证。

### 提交

三次 400 与一次 201，分别注明哪条输入触发了提示。
