# 从浏览器追踪一条任务到数据库

保留 `todo-server` 的 8080 后端和 MySQL。在前端 `todo-app` 中启动 Vite；若上一关前端只有静态文件，在此前端目录执行 `npm init -y`、`npm install -D vite`、`npm install axios`，给 package.json 添加 `"dev": "vite"`。入口页面使用 `<script type="module" src="/src/main.js"></script>`，路径应与自己的文件结构对应。

1. 在已有 `vite.config.js` 的配置中合并 `server: { proxy: { '/api': 'http://127.0.0.1:8080' } }`；保留 Vue 插件或其他既有配置。重启 Vite，打开它在终端打印的网址。从浏览器 Network 检查请求 URL，它应是前端同源的 /api/tasks，Vite 会将其转给 8080。打包后的站点需要部署端提供同样的 /api 转发。
2. 创建 `src/api.js`，让页面只调用四个函数。Axios 响应里的 `data` 是服务端返回的 JSON。

~~~js
import axios from 'axios'
const api = axios.create({ baseURL: '/api', timeout: 10000 })
export const getTasks = async () => (await api.get('/tasks')).data
export const createTask = async data => (await api.post('/tasks', data)).data
export const updateTask = async (id, data) => (await api.put('/tasks/' + id, data)).data
export const deleteTask = id => api.delete('/tasks/' + id)
~~~

3. 在页面初始化时令 `tasks = await getTasks()` 再渲染，将旧的 localStorage 写入路径移出正式数据流。点击添加时等待 `createTask({title, done:false})` 成功，再重新拉取列表，最后清空输入。勾选时把当前行的标题和新的 done 一起传给 updateTask。删除成功后重新拉取。请求中禁用对应按钮，失败时保留原输入并展示错误。

旧看板用 `task.text` 读标题，现在服务端返回 `task.title`。逐处更新列表、搜索过滤、编辑框、勾选请求中的字段，让它们统一读取 `task.title`。旧的本地 id 可能是字符串，服务端 JSON 的 id 是整数。将 DOM 的 `dataset.id` 与返回对象比较时，先用 `Number(button.dataset.id)` 转换，避免点一行却找不到任务。
4. 创建「联调样本」后按 F5，再重启 Java 服务。列表仍有同一 id，说明数据已经持久化。如果屏幕显示旧值，依次在 Network 看 GET 响应、查数据库、查看前端是否仍读取 localStorage。
