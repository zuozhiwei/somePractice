# 在入口校验任务标题，并用 JUnit 守住边界

沿用统一响应和全局异常处理。上一关给项目建立了历史，现在从 v1.0 之后的干净状态建功能分支。目标是让表单、HTTP、业务和数据库对同一份输入作出一致判断。在 `todo-server/pom.xml` 确认有 `spring-boot-starter-validation` 和 test scope 的 `spring-boot-starter-test`。

1. 新建或修改 `dto/TaskInput.java`，从 `jakarta.validation.constraints` 导入约束。POST、PUT 都使用相同的请求类型，在控制器参数上加 `@Valid @RequestBody TaskInput input`。保留数据库 title 列与接口约定一致的长度。

~~~java
public record TaskInput(
    @NotBlank(message = "任务标题不能为空")
    @Size(max = 200, message = "任务标题最多 200 个字符")
    String title,
    boolean done
) {}
~~~

2. 对 RegisterInput 的 username 加 `@NotBlank`、`@Pattern(regexp="[A-Za-z0-9_]{3,20}")` 和相应中文消息，password 至少 6 个字符，并沿用 BCrypt 72 字节上限检查。给注册控制器也加 @Valid。约束落在输入 DTO 上，不让输出对象带回密码。
3. 在 ApiExceptionHandler 或先前的 GlobalExceptionHandler 的校验分支返回 400、code=2 和第一条友好消息。字段有多个约束时，避免依赖报错顺序。对 title 的去空白规则保持一致；例如先对原输入执行上述 200 长度限制，保存成功时才 strip。
4. 直接用 Bean Validation 的 Validator 写独立 JUnit 5 测试。这些测试无需 MySQL 或启动服务器。把类放 `src/test/java/com/example/todo/dto/TaskInputTest.java` 并使用该 DTO 的包名；导入 jakarta.validation.Validation、org.junit.jupiter.api.Test 与断言类。

~~~java
@Test
void validatesTitleBoundaries() {
    try (var factory = Validation.buildDefaultValidatorFactory()) {
        var validator = factory.getValidator();
        assertFalse(validator.validate(new TaskInput("   ", false)).isEmpty());
        assertTrue(validator.validate(new TaskInput("学".repeat(200), true)).isEmpty());
        assertFalse(validator.validate(new TaskInput("学".repeat(201), false)).isEmpty());
    }
}
~~~

运行 `./mvnw -Dtest=TaskInputTest test`。测试命名、文件目录、@Test 的包错误都会导致 Maven 报“没有匹配测试”。拿同样输入发本地 API，如果单测拒绝了而 HTTP 仍接收，先查控制器上的 @Valid 是否漏掉。[Spring MVC 参数校验](https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-controller/ann-validation.html)

## 任务 106 | 使用校验注解

在任务与注册两个 DTO 声明约束，给创建、修改、注册这三个请求入口启用 @Valid。分别用一个正常和一个非法输入试每类入口，提交 DTO 和控制器签名；非法输入应在进入写库服务前获得 400。

## 任务 107 | 自定义校验消息

为空标题、超长标题和非法用户名分别给出用户能直接纠正的中文文案。用只违反单条约束的输入重复请求，提交 HTTP 400、code=2 与实际消息，说明消息怎样从字段约束进入统一响应。

## 任务 108 | 校验回归测试

准备空标题、201 字标题、空用户名与五字符密码四个样本，用 Postman 按顺序执行并记录。另测 200 字标题可创建。交每例预期/实际状态、消息及写库前后行数，确认边界两侧均覆盖。

## 任务 161 | 用 JUnit 写单元测试

将上述边界用例写入项目，补一条验证合法短标题和 null 标题的测试。只在练习分支临时将 max 改成 201，观察哪条测试变红；恢复 200 后重新运行，全部通过。交测试代码、两次运行摘要和解释：这组测试保护输入规则，HTTP 序列化、鉴权和数据库写入仍需单独联调。
