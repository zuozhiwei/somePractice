# 撤销误判并验证治理边界

补一次可重复的误判修复。审核台提供 `POST /api/mod/reports/{id}/undo`，要求理由并确认这是仍然生效的那条隐藏决定。帖子状态只能在它仍为隐藏且同一次操作仍有效时复原，作者已经删除、出现更新的审核动作或重复撤销都返回 409。事务中记录撤销人、时间、理由与原决定的 ID，把举报改为 `REVERTED`，供幂等检查使用。保留原审核记录。首版可用版本列或隐藏决定引用避免清除另一次更晚的处理。

用 JUnit 或 Spring 测试层准备不含真实个人信息的样例。至少覆盖权限、重复操作和作者已经删帖三个边界。前端用可读提示解释什么时候无法撤销，审核员可刷新状态，不必再次填写一份重复决定。

### 撤销接口

把 `ModerationPolicy.java` 保存到已有 Java 包。让 `ModerationService` 使用这一判断，测试也调用这份真实代码。两项判断分别处理已经撤销与原帖已删。较新的处理决定由事务的 SQL 比较决定。

```java
package edu.campus.treehole;

final class ModerationPolicy {
    private ModerationPolicy() {}

    static boolean canUndoReport(String reportStatus, Long postId) {
        return "ACTIONED".equals(reportStatus) && postId != null;
    }
}
```

在 `ModerationController.java` 的最后一个大括号之前增加 POST 和小请求对象。现有类级别的 `/api/mod/reports` 保持。

```java
@PostMapping("/{id}/undo")
public Map<String,Object> undo(@PathVariable Long id,
        @RequestBody UndoInput input, Principal principal) {
    return moderation.undo(id, input.reason(), principal);
}
public record UndoInput(String reason) {}
```

在 `ModerationService.java` 末尾加下面的公共方法，复用前一关的 `lockReport`、`ReportRow`、`saveAction`。恢复使用当前报告当时保存的 HIDE 审计 ID。`UPDATE posts` 最后两个条件防止以较旧的决定恢复当前由新决定隐藏的帖子。任一步没有更新一行就抛异常，Spring 会撤销本次数据库写入。

```java
@Transactional
public Map<String,Object> undo(Long id, String rawReason, Principal principal) {
    String reason = rawReason == null ? "" : rawReason.trim();
    if (reason.isEmpty() || reason.length() > 300) {
        throw new GovProblem(400, "INVALID_UNDO_REASON", "请填写 1 到 300 字的撤销理由");
    }
    ReportRow report = lockReport(id);
    if (!ModerationPolicy.canUndoReport(report.status(), report.postId())) {
        throw new GovProblem(409, "REPORT_CHANGED", "这条隐藏决定已经失效");
    }
    Long original = jdbc.query("""
        SELECT id FROM moderation_actions
        WHERE report_id=? AND post_id=? AND decision='HIDE' ORDER BY id DESC LIMIT 1
        """, (row, index) -> row.getLong("id"), id, report.postId()).stream().findFirst().orElse(null);
    if (original == null) throw new GovProblem(409, "REPORT_CHANGED", "找不到原隐藏决定");

    int reportUpdated = jdbc.update("""
        UPDATE reports SET status='REVERTED', resolution_reason=? WHERE id=? AND status='ACTIONED'
        """, reason, id);
    if (reportUpdated != 1) throw new GovProblem(409, "REPORT_CHANGED", "这条隐藏决定已经失效");
    int postUpdated = jdbc.update("""
        UPDATE posts SET status='VISIBLE', active_decision_id=NULL
        WHERE id=? AND status='HIDDEN' AND active_decision_id=?
        """, report.postId(), original);
    if (postUpdated != 1) throw new GovProblem(409, "POST_CHANGED", "帖子已有更新的决定");

    saveAction(id, report.postId(), current.id(principal), "UNDO", reason);
    return Map.of("id", id, "status", "REVERTED");
}
```

### 撤销表单

对于已隐藏的举报，在 `moderation.html` 的 `render(row)` 内，把这三行放到 `if (row.status !== 'OPEN') return` 之前。

```js
if (row.status === 'ACTIONED') {
  addUndo(item, row.id)
  return
}
```

将下面的函数放在 `render` 后、原 `state.addEventListener` 前。它使用前一关页面的 `text`、`load` 与 `write`。

```js
function addUndo(item, reportId) {
  const form = text(item, 'form', '')
  const reason = text(text(form, 'label', '撤销理由 '), 'textarea', '')
  reason.required = true
  reason.maxLength = 300
  const button = text(form, 'button', '撤销隐藏')
  button.type = 'submit'
  form.addEventListener('submit', async event => {
    event.preventDefault()
    if (!window.confirm('确认允许访客重新查看这条帖子？')) return
    button.disabled = true
    try {
      await write('/mod/reports/' + reportId + '/undo', 'POST', { reason: reason.value.trim() })
      state.value = 'REVERTED'
      await load()
    } catch (error) {
      if (error.status === 409) {
        await load()
        message.textContent = '这条决定已变更，列表已刷新。'
      } else {
        message.textContent = error.message
      }
    } finally { button.disabled = false }
  })
}
```

## 任务 107 | 保护作者删除和较新的治理决定

### 操作步骤

从 [第一次撤销](/level/28?task=106) 的端点起步，另建两条案例检验作者删除和较新的状态。回滚验证只限自己练习库。

1. 用另一条合成帖完成 HIDE，再切到作者账号在「我的帖子」执行删除。回到审核窗口在原举报上执行撤销，预期 409。
2. 为了观察较新决定，在开发库创建第二条独立举报，先撤销旧决定，用第二条重新隐藏同一帖。再尝试撤销第一条，预期 409，原帖继续隐藏。
3. 当界面得到 409，提示当前决定不可撤销，提供刷新。用 SQL 查帖子不存在或 `active_decision_id` 仍为新决定，证明没有恢复旧状态。

### 验收与排查

两条结果都是 409。若已删帖又能读取，查撤销是否误用了 INSERT；正确操作只在目标行的 HIDDEN 与原审核 ID 仍匹配时执行 UPDATE。

### 提交

两个冲突案例、错误提示及库状态。
