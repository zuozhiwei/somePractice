# 用待办业务做一组可运行的 Java 练习

从第 22 关能隔离用户的项目中，选一个熟悉的对象「任务」作为练习材料。新建 `todo-server/src/test/java/com/example/todo/practice`，放独立的练习类和 main 方法；这里的示例无需连接真实数据库。让 IDE 在 Java 17 下运行该 main，保存每次改变对象之前和之后的输出。

1. 先做对象封装。下面的练习对象有自己的状态和方法；再为 id、title、done 写读取方法，为 title 写受控修改方法，并检查空标题。

~~~java
class PracticeTask {
    private final long id;
    private String title;
    private boolean done;
    PracticeTask(long id, String title) {
        this.id = id;
        this.title = title;
    }
    void toggleDone() { done = !done; }
    boolean isDone() { return done; }
    String getTitle() { return title; }
}
~~~

2. 创建 `List<PracticeTask> tasks = new ArrayList<>();`，循环添加十个练习任务。对前三个调用 toggleDone。先用 for-each 数已完成数，再以 `tasks.stream().filter(PracticeTask::isDone).count()` 校对结果。`filter` 保留满足条件的元素，`map` 转换每个元素，`toList` 收集结果；注意流操作本身不更改原列表。
3. 建 `Map<String,Long> userIds = new HashMap<>();`，键用三个虚构用户名，值用演练 id。对比 List 中按顺序取值与 Map 中按名称查找。若按旧题示例练习字符串值，可使用纯示例标签代替口令，账号认证仍沿用 BCrypt。
4. 写一个会抛出业务异常的计算方法，并在调用处区分正常结果与异常。回到 TaskService 的构造器，画出依赖从哪里传入，想想为什么独立练习可以直接 new 对象，而生产代码希望 Spring 统一组装对象。

## 任务 86 | 面向对象三要素练习

新建两个不同 id 的对象，给一个改标题并切换 done，另一个应该维持原值。提交类、构造器、getter 和操作结果，并用自己的代码标出类、对象与封装。补充指出继承和多态各适合何种场景，这个简单任务对象无需人为增加继承层级。

## 任务 87 | 集合类练习

ArrayList 中放十个任务，试一次添加、按下标或条件查找、删除；HashMap 中放三个虚构用户名与练习编号，分别 put、get、remove。交实际输出，说明有序列表允许重复而 Map 相同键会覆盖原值。

## 任务 88 | 异常处理练习

实现 divide(a,b)；当 b 为 0 抛出自定义 DivideByZeroException。分别调用 divide(8,2) 和 divide(8,0)，用 try/catch/finally 输出结果、友好提示与清理标记。交两段输出并说明 finally 在这两条路径上的执行时机。

## 任务 89 | 注解与依赖注入理解

在真实代码中圈出 @RestController、@Service、实体仓库以及单构造器注入。指出谁创建对象、谁传入 repository，说明单构造器可省略 @Autowired，Spring Data 能为仓库接口提供实现。交一次从 HTTP 请求到 repository 的依赖图，并展示给服务传一个测试替身为何更容易。
