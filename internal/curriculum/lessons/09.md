# 给树洞存储加版本

### 开始前

先保存一份自己生成的练习数据，再改存储代码。给保存内容加版本号，以便旧格式还能被新程序认出。 [上一步](/level/8?task=32)

### 数据版本和话题统计示例

版本号告诉程序保存的数据是什么结构。比如桌面上旧 ZIP 里的一条帖子没有后来才加的话题字段，新的程序也应该能打开它。把旧记录补齐成新格式并保留正文，这个过程叫数据迁移。在原 `campus-treehole:v1` 键里写入版本 2，旧名单还能找到。先在开发者工具复制一份仅含练习内容的旧 JSON，保存进 `web` 之外的检查目录。

1. 在 `loadData` 后面加 `normalizeData` 函数。
2. 在 `loadData` 中将解析数据和赋值改成 `const saved = normalizeData(JSON.parse(raw)); state.posts = saved.posts; state.draft = saved.draft;`。对于没有 version 的旧数据，等加载和核对成功再用保存入口写成 V2。
3. 在 `saveData` 内把 `JSON.stringify(state)` 换为 `JSON.stringify({ version: 2, ...state })`。

```js
function normalizeData(value) {
  if (!value || !Array.isArray(value.posts) ||
      (value.version !== undefined && value.version !== 2)) {
    throw new Error("树洞文件格式或版本不符");
  }
  const ids = new Set();
  const posts = value.posts.map((post) => {
    if (!post || typeof post.id !== "string" || ids.has(post.id) ||
        typeof post.title !== "string" || typeof post.body !== "string" ||
        !Number.isFinite(Date.parse(post.createdAt))) {
      throw new Error("帖子资料格式不符");
    }
    ids.add(post.id);
    const category = value.version === undefined && post.category === undefined ? "DAILY" : post.category;
    const comments = value.version === undefined && post.comments === undefined ? [] : post.comments;
    if (!Object.hasOwn(categoryLabels, category) || !Array.isArray(comments) ||
        comments.some((comment) => !comment || typeof comment.id !== "string" ||
          typeof comment.body !== "string" || !Number.isFinite(Date.parse(comment.createdAt)))) {
      throw new Error("话题或评论格式不符");
    }
    return { ...post, category, comments };
  });
  const draft = value.draft ?? null;
  if (draft !== null && (!draft || typeof draft.title !== "string" ||
      typeof draft.body !== "string" || !Object.hasOwn(categoryLabels, draft.category))) {
    throw new Error("草稿格式不符");
  }
  return { posts, draft };
}
```

在 Local Storage 中，把练习数据的 version 去掉，并在一条练习帖去掉 category 或 comments。保存该值再刷新，帖子要能显示成「校园日常」或零评论。再从页面保存一次草稿，检查 version 变为 2。最后恢复你备存的练习数据。

给列表上方加 `<p id="post-stats"></p>`，在 `renderPosts` 末尾加入 `$("#post-stats").textContent = state.posts.length + " 条帖子，" + state.posts.reduce((sum, item) => sum + item.comments.length, 0) + " 条评论";`。需要分类数量时，使用 `state.posts.filter((post) => post.category === "DAILY").length`，逐个话题计算。编辑话题与评论后核对。

## 任务 33 | 声明树洞数据版本

前置：[回归发帖和评论](/level/8?task=32)。[查看版本迁移代码](/level/9?guide=1)。

### 操作步骤

1. 找到 `loadData` 与 `saveData`。将版本示例中的 `normalizeData` 追加到同一份 `app.js`，按说明在加载时调用它。把 `JSON.stringify(state)` 改为 `JSON.stringify({ version: 2, ...state })`。
2. 从同源地址刷新，发一条合成帖、加一条评论，再保存草稿触发写入。打开 Application 的存储格，找到 `campus-treehole:v1` 并检查值。
3. 找最外层的 `version: 2`、`posts` 与 `draft`，再找一条帖子里的 `comments`。如果没看到 version，确认修改的是脚本里的保存函数并实做了保存操作。

### 预期结果

最外层有 version:2，posts、comments 与 draft 各在对应位置。

交字段说明和合成样例。

## 任务 34 | 迁移旧格式树洞

前置：[声明树洞数据版本](/level/9?task=33)。

### 操作步骤

1. 在 Application 找项目存储键，选中并复制它的完整 Value。到 VS Code 新建未保存的文本页，粘贴这份合成 JSON 当作恢复用的备份。记下要观察的一条练习帖的 id。
2. 回存储面板双击 Value，只改这份练习数据，将最外层的 `"version":2,` 去掉。在一条帖子删除 `category` 或 `comments` 字段。注意同级条目间仍需逗号，最后一个条目后没有逗号。回车保存并刷新。
3. 确认该帖以「校园日常」或零评论显示，且原 id 不变。点保存草稿让程序新写 V2，刷新两次确认没有重复。误删引号而报格式错误时，把备存值贴回再重做。

### 预期结果

旧帖不重复，示例与原 ID 保留，当前存储显示版本 2。

### 提交

交旧数据和两次重开的对照。

## 任务 35 | 统计话题与回帖

前置：[迁移旧格式树洞](/level/9?task=34)。[查看统计代码](/level/9?guide=1)。

### 操作步骤

1. 在 `index.html` 搜索 `id="post-list"`，紧挨它上面加 `<p id="post-stats"></p>`。在 `renderPosts` 的最后、结束大括号之前加入「数据版本和话题统计示例」中的统计代码。保存两个文件再刷新。
2. 从「校园日常」和「校园提问」各找一帖，记两种现有数量。给其中一条评论，比较更新前后的评论总数。再把自己的一条帖编辑成另一个话题。
3. 按统计示例的 `filter(...).length` 分别取分类数量，看它们是否与当前列表一致。如果总数更新、分类不动，核对各分类的机器值 `DAILY / QUESTION / HELP`。

### 预期结果

回复数量即时更新，各话题数量与列表一致。

### 提交
