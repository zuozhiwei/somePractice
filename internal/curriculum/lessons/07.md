# 让看板刷新后还能读回昨天的任务
打开第 6 关的看板，添加一项后刷新，先亲眼看它消失。数组活在当前页面内，浏览器本地存储则按来源保存文本。为了让存储位置可复现，这关起尽量从一个固定的本机 HTTP 地址打开作品。如果电脑装了 Python 3，在 `todo-app` 打开终端执行以下命令，终端保持开启，浏览器访问 `http://127.0.0.1:5500/`。Windows 使用 `py`，其他系统可用 `python3`；也可以使用编辑器自己的本地预览服务，并记住它的端口。

```powershell
py -m http.server 5500 --bind 127.0.0.1
```

把旧的 `const tasks = [];` 替换成 `let tasks = loadTasks();`。在脚本中添加以下两个函数。在添加、切换完成、删除等写操作之后先 `saveTasks()` 再 `render()`。启动时先加载，再进行第一次渲染。

```js
function loadTasks() {
  const stored = localStorage.getItem("tasks");
  return stored === null ? [] : JSON.parse(stored);
}

function saveTasks() {
  localStorage.setItem("tasks", JSON.stringify(tasks));
}
```

在 Application（应用）面板的 Local Storage 中查看 `tasks`。增加一条任务后，键值应随之变化；刷新后观察页面是否重建。若存储有值但列表为空，检查脚本是不是在读取后又执行了 `tasks = []`。若换浏览器或端口后看不见旧任务，先回到原来的浏览器和地址。直接打开 file 地址时，各浏览器的存储行为可能不同。[MDN 的 localStorage 说明](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)

自己做对照实验：同一地址刷新、关闭后重开、临时换端口，各预测一次再看结果。以后发现数据不见时，就可以先区分是没写入、读错位置，还是读出后没渲染。
