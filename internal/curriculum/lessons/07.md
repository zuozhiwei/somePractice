# 让帖子、评论和草稿留下来

### 开始前

本章让数据在刷新后也存在。先在自己的机器搭一个固定本地地址，再决定位于这个地址的浏览器存储怎么写。 [上一步](/level/6?task=24)

### 本地网址和持久保存示例

网页以后用固定的本地地址打开，这样浏览器会把草稿放在同一处。**本地服务器**是在自己的电脑上运行的一个小程序，通过地址把项目文件交给浏览器。`127.0.0.1` 代表自己的电脑，`5500` 是这次给程序用的端口号。**终端**是可以输入命令的窗口，一行命令就是让电脑执行一次操作。这里先用 Python 3 自带的文件服务器。

请在 VS Code 左侧确认打开的是包含 `web` 的项目根目录，从顶部选「终端 → 新建终端」，光标会出现在窗口底部。选自己系统的命令，复制到光标处并按回车，保持这个窗口开着。

:::windows

```sh
py -m http.server --bind 127.0.0.1 --directory web 5500
```

:::

:::mac linux

```sh
python3 -m http.server --bind 127.0.0.1 --directory web 5500
```

:::

看到「Serving HTTP」后，在浏览器地址栏打开 `http://127.0.0.1:5500/`。如果终端提示找不到刚输入的命令，可以用编辑器来启动预览。在 VS Code 左侧点「扩展」的四方块图标，搜索 `Live Preview`，选发布者为 Microsoft 的扩展，点击「安装」。在左侧文件列表点 `web/index.html`，再点「查看 → 命令面板」，输入 `Live Preview: Show Preview (External Browser)` 并选择该命令。浏览器打开后记下地址栏的实际地址。以后固定使用同一浏览器、协议、主机和端口。看到目录列表时，从终端核对启动目录与 `--directory web`，并检查 `index.html` 在 web 中。

**本地存储**是浏览器留给当前网站的一小块存储空间，关掉页面再打开也能读出来。`localStorage` 是用它的接口。**JSON** 是把帖子写成文本的一种格式，例如 `{"title":"图书馆几点关门？"}`，左边是字段名，右边是这条帖子的实际标题。下面的 `JSON.stringify` 将数据变成文本，`JSON.parse` 将文本还原成可以使用的数据。

在 HTML 的反馈区域旁加入 `<p id="storage-status" role="status"></p>`。在 `app.js` 找到空的 `saveData`，整体替换为下面的代码。保留发帖、评论和草稿里的 `saveData()` 调用。

```js
const storageKey = "campus-treehole:v1";

function loadData() {
  try {
    const raw = localStorage.getItem(storageKey);
    if (raw === null) return;
    const saved = JSON.parse(raw);
    if (!saved || !Array.isArray(saved.posts)) throw new Error("帖子格式不对");
    state.posts = saved.posts;
    state.draft = saved.draft ?? null;
  } catch {
    $("#storage-status").textContent = "这份本地数据暂时读不了，已先显示示例帖子。";
  }
}

function saveData() {
  try {
    localStorage.setItem(storageKey, JSON.stringify(state));
    $("#storage-status").textContent = "";
  } catch {
    $("#storage-status").textContent = "浏览器没有保存本次更改，关闭页前请备份。";
  }
}
```

接着在 `app.js` 找到紧挨在一起的 `$("#post-detail").hidden = true;` 与 `renderPosts();`。这是第 4 关放在函数外的初始化代码。选中这两行并用下面的四行替换。

```js
loadData();
fillPostForm(state.draft);
$("#post-detail").hidden = true;
renderPosts();
```

先发布一条合成帖并评论，再保存一份新草稿。按刷新键，应找回帖子、回复和草稿。如果只剩样例，先比对地址栏，检查是否一处写了 `localhost`、另一处写了 `127.0.0.1`。停止本地服务器时，先点击正在运行它的终端，再按 Control+C。重新启动后仍用同一个地址。

## 任务 25 | 查看树洞本地存储

前置：[提交可试玩的树洞页面](/level/6?task=24)。[查看怎样启动本地网页](/level/7?guide=1)。

### 操作步骤

1. 先按「本地网址和持久保存示例」启动本地网页。存储练习用 Edge 或 Chrome 打开网址，地址栏应以 `http://` 开头。先前若用其他浏览器，这关第一次选择 Edge 或 Chrome 后，之后的存储练习就用同一个浏览器。打开网页空白处的快捷菜单选「检查」，再选「应用 / Application」。找不到时点标签栏右边的双箭头。
2. 左栏展开「本地存储 / Local Storage」，点与地址栏相同的来源，例如 `http://127.0.0.1:5500`。右侧空白的 Key、Value 区双击，分别输入 `test-treehole` 与 `hello`，按 Enter。
3. 刷新检查工具视图或重开应用标签，找回这一行。最后只选 `test-treehole` 那行，按 Delete 或右键「删除」。别在其他来源里操作。

### 预期结果

能在地址保留的存储表里看到自己写入的键。

### 提交

交地址与演示键所在位置，不需要提交其他站点数据。

## 任务 27 | 每次有效修改后保存

前置：[序列化树洞数据](/level/7?task=26)。

### 操作步骤

1. 从同一地址打开树洞。保存一份合成草稿，去 Application 的 Local Storage 看它是否写在 draft。恢复后补完发布，再看 posts 是否包含这条帖子。
2. 给这条帖评论一次，检查它自己的 comments 数组。刷新页面，重进同一帖子核对回复。再删自己这条练习帖，回存储面板确认对应 id 没有留在 posts 里。
3. 四项中某项仅能在当前页面显示时，在 `app.js` 找该按钮的处理函数，核对修改后调用了 `saveData()`。保存脚本并重新做那一步。

### 预期结果

新增、评论和草稿保留，删掉的本地练习帖不会回来。

### 提交

交四项操作和刷新复查。

## 任务 28 | 核对刷新和重开

前置：[每次有效修改后保存](/level/7?task=27)。

### 操作步骤

1. 先记下当前浏览器地址，在同一浏览器开一个新标签，粘贴地址。检查同一条合成帖和未发布草稿。草稿可用「恢复草稿」按钮复查。
2. 关闭两个标签中的其中一个，从地址栏重新输入同一地址。再核对一次帖子、评论与草稿。保持承载网页的终端继续开着。
3. 没有恢复时，比较两次的协议、主机和端口。 `localhost` 与 `127.0.0.1` 对浏览器而言是不同来源。无痕窗口和普通窗口的数据也分别保留。

### 预期结果

同一个浏览器和地址都能找回原数据。

### 提交

交重新开的地址和恢复后结果。
