# 验收可邀请同学的试运行

从第 40 关已经能远程打开的 HTTPS 站点继续。第 41 关的 Compose 复现可作为新机器演练，试运行正式地址仍按你的主线部署。**候选版本**是准备邀测的具体提交和发布产物。它必须说得清是哪份代码、怎么运行、失败时怎么切回。

**开始前**

自己的 HTTPS 链接、两位测试成员和一位测试审核员、两台设备或两个网络。只发虚构帖，例如「周末想学几首吉他和弦」。先建立 `docs/qa/42-staging.md` 记实际时间和结果。

## 任务 153 | 核对试运行配置及数据备份

### 从哪里开始

SSH 到 [能提供 HTTPS 的试运行主机](/level/40?task=147)，确认证书入口对应这份候选。备份和恢复共用一个主机终端，退出后需要重新设置该终端里的变量。

### 操作步骤

1. 在主机上读取版本记录和健康状态。用浏览器也打开真实域名的健康地址，对照外部请求和内部依赖。核对前端与应用是同一版本的候选产物。

```bash
readlink -f /srv/campus-treehole/current
cat /srv/campus-treehole/current/commit.txt
sha256sum /srv/campus-treehole/current/app.jar
curl -fsS http://127.0.0.1:8080/api/health
sudo systemctl status campus-treehole --no-pager
```

2. 做一份只有自己能读的数据库备份。此步骤在主机运行，备份输出位于管理用户的私人目录，不在静态根目录下。暂时不要执行结构迁移。使用 `mysqldump` 的 `--single-transaction` 获取 InnoDB 一致快照。

```bash
umask 077
mkdir -p "$HOME/treehole-backups"
backup="$HOME/treehole-backups/staging-$(date +%Y%m%d-%H%M%S).sql"
sudo mysqldump --single-transaction --no-tablespaces --set-gtid-purged=OFF campus_treehole_staging > "$backup"
test -s "$backup" && sha256sum "$backup"
```

3. 仅在导出命令成功、文件非空时，用一个没存在过的名字建恢复库，例如 `campus_treehole_restore_20261120`。改用当天日期或另一个唯一后缀。复核源库、目标库名字不同，再导入。检查恢复库能查到合成帖、评论和通知表，不对试运行库恢复旧数据。

```bash
restore_db=campus_treehole_restore_20261120
sudo mysql -e "CREATE DATABASE \`$restore_db\` CHARACTER SET utf8mb4;"
sudo mysql "$restore_db" < "$backup"
sudo mysql "$restore_db" -e 'SHOW TABLES; SELECT COUNT(*) FROM posts;'
```

看到 0 字节或导入报错先保留错误输出，检查导出权限和磁盘空间。若驱动为兼容 MySQL 的别种发行版，按它的备份工具选项调整，不直接往现有库试写。［参考 [MySQL 备份工具](https://dev.mysql.com/doc/refman/8.4/en/mysqldump.html)］

**提交内容**

运行提交、JAR 校验、备份时间与校验、在独立目标库的恢复结果。备份文件留在受控位置。

## 任务 154 | 在不同设备上验收核心路径

### 从哪里开始

准备一台已联网电脑与一台能用不同网络的手机。打开 [真实入口的验收记录](/level/40?task=148)，按这张卡逐行操作并写实测。平台课程页面的链接不是你的树洞地址。

### 操作步骤

用两台设备按表实际操作，一台用手机流量或另一网络。登录测试前先查证书及域名。若校内网或 VPN 才能访问，准确记下范围，别把它当成最终公开站点。

| 人和设备 | 做什么 | 应有结果 |
| --- | --- | --- |
| 访客，手机无痕 | 打开主链接，点分类、打开示例帖 | 页面可读，账号信息不对外显示 |
| A，电脑 | 登录，发虚构帖，复制链接 | 写入成功且刷新后还在 |
| B，手机或另一浏览器 | 打开链接，评论后举报 | A 收到站内回复，B 看不到 A 的收件箱 |
| 审核员 | 隐藏，再撤销 | 新无痕窗口先不可读，撤销后可读 |
| A，原浏览器 | 退出并刷新私有页 | 需要重新登录，没有残留私有内容 |

每次操作只抄路径、时间、状态与是否通过。若打开页面但是发帖失败，先看 Network 有没有 CSRF 响应或误连 localhost。若出现 SSL 警报先修入口，不要求同学继续填写表单。

**提交内容**

两种网络、三种角色、每个动作的结果，记录一个仍未解决的问题或说明都验证通过。

## 任务 155 | 交付可复现的邀测版本

### 从哪里开始

回本机仓库根目录。把 [试运行的版本校验](/level/42?task=153) 和 [跨设备结果](/level/42?task=154) 放在手边。标签要指向主机上已测过的代码提交。

### 操作步骤

在原仓库提交试运行文档与验收记录。将当前**实际发布的构建提交**标为 `v0.7-rc.1`，文档如晚于构建提交可明确记录两个提交。在 `docs/deploy.md` 留下实际的上一个可回退目录和检查办法。本关只记录，切换演练留到后续。若这是第一份候选、暂时没有旧版，就把当前已通过的目录作为下次发布前的回退点。

:::windows

```powershell
git status --short
$commit = "替换为已验证的实际提交号"
git tag -a v0.7-rc.1 $commit -m "Campus treehole trial release"
git show --no-patch v0.7-rc.1
```

:::

:::mac linux

```bash
git status --short
commit=替换为已验证的实际提交号
git tag -a v0.7-rc.1 "$commit" -m "Campus treehole trial release"
git show --no-patch v0.7-rc.1
```

:::

把提交号占位文字换成服务器 `commit.txt` 的十六进制提交号。若用版本标签记录的是同事先上传的包，先请对方提供同一提交的校验结果，再标记。邀请同学时给一个可直接点击的 HTTPS 地址、一个练习步骤和一条反馈入口，不公开测试账号密码。

在 README 可以填这三行，再把实际值放进去。「回退后验证」写 `curl -fsS https://你的域名/api/health` 返回 UP，并打开 [跨设备记录](/level/42?task=154) 中的一条合成帖。证书错误与 502 都表示还需排查入口，别只看进程在运行。

```text
候选标签：v0.7-rc.1
运行的提交号：从主机 commit.txt 复制
下一次发布的回退目录：主机上已验收的完整发布绝对路径
```

**提交内容**

候选标签、HTTPS 入口、可重复的合成测试步骤、限制及回退目录。
