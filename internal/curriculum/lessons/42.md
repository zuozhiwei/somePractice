# 用另一个人的浏览器做一次发布验收
选定你要交付的运行方式（systemd 或 Compose），记下可启动的版本、前后端产物摘要、练习库结构版本、使用的入口和网络范围。本机演示可交操作说明与录屏，校园入口写明需连接的网络或授权隧道。公开互联网部署并非本章必要条件。

从使用者角度写一份 `acceptance.md`。给每一步规定具体期望：用户甲新建 A、B 并改名 B2；搜索 B2 只看到一行；删除 A 后刷新只有 B2；退出后受保护 API 拒绝请求；甲再登录能看到 B2，而另一个新用户看不到。用两个浏览器配置文件隔离会话。不要把真实学生名单或登录凭据装进作业包。

再从运行端核验：`ss -ltn` 对照实际入口；数据库、Redis 只需对应用可达；外部 HTTPS 由校方入口或已有域名终止，记录证书主机名和有效期。不具备公网域名时用 SSH 隧道或仅限本机的 HTTP 演示，并在报告说明外网发布前还要配哪些条件。用 `git status --short` 和人工检查待交文件，核对示例配置只含变量名。完成一份能恢复的练习备份，在单独环境还原并从页面读取它。

留给答辩的问题：如果换一台机器，哪些文件可以从 Git 重建，哪些数据只能从备份找回？请用自己本次交接的路径来回答。

## 任务 153 | 生产环境安全加固
列出前台、SSH、后端、数据库和缓存五个入口各自的监听地址及允许来源，注明 HTTPS 或练习网的边界。将示例数据库密码和签名密钥换成这套练习环境专用值，配置与源码分开。交打码后的核对表、正常登录后查询成功的证据，不贴任何变量值。

## 任务 154 | 最终验收：从用户入口做完整测试
请同学从 README 指定入口照步骤测试注册、登录、增删改查、搜索和退出；增加一个错误输入及一次跨账号隔离验证。每行写实际结果、时间与可重复输入。交桌面和窄屏结果，明确本机、局域网或公网可达范围。

## 任务 155 | 部署答辩：提交可复现的作品
交仓库或可审阅的源码包、版本号、部署入口或可复现的本机启动步骤、验收报告和恢复说明。挑一次真实故障用「现象→证据→改动→复测」讲清楚，最后选一项还想改进的功能并说明优先级。答辩者应能依说明找到对应代码和测试。
