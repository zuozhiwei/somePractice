# 在树洞写一条帖子

### 开始前

先能在浏览器打开详情和发送评论，再往原项目添加发布与草稿。把 HTML 按钮增补齐全再运行新脚本，按钮的 id 用于找到浏览器里对应的控件。 [上一步](/level/4?task=156)

### 发帖、草稿和删除示例

**表单**就是用户填写内容并提交的那组输入框和按钮。现在要让「发到树洞」把填好的内容加入列表，让「保存草稿」保留还没写完的几句话。先在原页面填一条虚构帖子，记住这两个动作分别要用到哪个区域。

继续使用原来的帖子表单。在 HTML 的 `post-form` 内，「发到树洞」按钮旁加 `<button id="save-draft" type="button">保存草稿</button>`。type="button" 让「保存草稿」可以无条件保存未写完的内容，「发到树洞」会继续检查必填项。

把下面代码加到 `app.js` 末尾。这个阶段草稿存在页面内存，可以先返回列表，关掉页面或刷新会清除。第 7 关才实现跨刷新保存。

```js
function readPostForm() {
  return {
    title: $("#post-title").value.trim(),
    category: $("#post-category").value,
    body: $("#post-body").value.trim(),
  };
}

function fillPostForm(value) {
  $("#post-title").value = value?.title || "";
  $("#post-category").value = value?.category || "DAILY";
  $("#post-body").value = value?.body || "";
}

function saveDraft() {
  state.draft = readPostForm();
  saveData();
  $("#feedback").textContent = "草稿已保存。";
}

function publishPost(event) {
  event.preventDefault();
  const fields = readPostForm();
  if (!fields.title || !fields.body || fields.title.length > 100 ||
      fields.body.length > 1000 || !Object.hasOwn(categoryLabels, fields.category)) {
    $("#feedback").textContent = "请填写标题与正文，并选择一个有效话题。";
    return;
  }
  const post = { ...fields, id: nextId(), createdAt: new Date().toISOString(), comments: [], local: true };
  state.posts.unshift(post);
  state.draft = null;
  fillPostForm(null);
  saveData();
  renderPosts();
  showPost(post.id);
  $("#feedback").textContent = "帖子已发到树洞。";
}

function removeLocalPost() {
  const post = state.posts.find((item) => item.id === activePostId);
  if (!post?.local || !window.confirm("删除这条练习帖及其评论？")) return;
  state.posts = state.posts.filter((item) => item.id !== post.id);
  $("#detail-back").click();
  saveData();
  renderPosts();
  $("#feedback").textContent = "练习帖已删除。";
}

$("#save-draft").addEventListener("click", saveDraft);
$("#post-form").addEventListener("submit", publishPost);
$("#restore-draft").addEventListener("click", () => fillPostForm(state.draft));
$("#delete-post").addEventListener("click", removeLocalPost);
```

在 HTML 的发帖表单再加 `<button id="restore-draft" type="button">恢复草稿</button>`，在帖子详情的返回按钮旁加 `<button id="delete-post" type="button" hidden>删除我的练习帖</button>`。在第 4 关的 `showPost` 内找到设置正文的一行，后面加 `$("#delete-post").hidden = !post.local;`。确保三个新 ID 存在再刷新。先保存未完成草稿，清空输入后点击恢复，再补完整并发布。新帖进入列表，详情里的删除按钮只对自己练习帖显示。

## 任务 19 | 整理发帖和浏览入口

前置：[调试一次详情切换](/level/4?task=156)。

### 操作步骤

1. 在 VS Code 打开 `index.html`。搜索大标题「写一条帖子」，找到其上方包住发帖区的开始标签，把它改成 `<section id="write">`。同页的列表标题已有 `id="feed-title"`。
2. 在 header 的介绍文字下面加一行 `<a href="#write">写一条</a>`。在发帖段落后放 `<a href="#feed-title">回到帖子列表</a>`。保存并刷新。
3. 从页头点「写一条」，向下定位到表单，再点回到列表。如果不移动，比较 href 井号后的名称和目标 id，确认页面只有一个同名目标。

### 预期结果

可以用链接在同一页面的列表和表单之间跳转。

### 提交

交两个入口和到达的位置。

## 任务 20 | 创建并删除本地帖子

前置：[整理发帖和浏览入口](/level/5?task=19)。[查看按钮和发布脚本](/level/5?guide=1)。

### 操作步骤

1. 从「发帖、草稿和删除示例」的 HTML 增补三个按钮，并将完整 JS 片段追加到 `app.js` 末尾。再在 `showPost` 找到设置正文的一行，按示例追加决定 `delete-post` 是否显示的语句。保存两份文件后刷新。
2. 填标题「这是可删除的练习帖」，保留一个话题，填正文并点「发到树洞」。看到新详情后写一条合成评论。只给自己新增的这一条设置删除。
3. 点「删除我的练习帖」，读提示后选确认。列表应少一张卡，示例帖数量不变。页面没反应时先看控制台，核对三个新按钮的 id 及 script 链接。

### 预期结果

被删练习帖及其评论消失，示例帖保持。

### 提交

## 任务 21 | 暂存未发布输入

前置：[创建并删除本地帖子](/level/5?task=20)。

### 操作步骤

1. 在「写一条」处输入半截标题以及半段正文，选一个话题，先点「保存草稿」。记下列表卡片数量。
2. 故意临时把输入换成别的字，再点「恢复草稿」。比对标题、正文和话题是否恢复，列表卡片数字应保持。
3. 草稿恢复后补齐句子，点「发到树洞」，核对列表多出一条。若保存草稿就刷新页面，当前版本不会保留。只在同一次打开页面时做这次验证。

### 预期结果

原来那段文字回到表单，列表没有多出帖子。

### 提交

交保存、改字、恢复后的结果。

## 任务 22 | 处理发帖和回帖边界

前置：[暂存未发布输入](/level/5?task=21)。

### 操作步骤

1. 保留一段合成正文，分别用空标题、仅空格的标题尝试发布。先点按钮观察浏览器原生必填提示，再观察页面是否提示空白无效。不要清除另一字段。
2. 回一条帖试写空评论，或粘贴一段超过 500 字字符限制的虚构内容，观察浏览器限制。检查这两次尝试都没有新增错误条目。
3. 把标题或回复改成「可发布的练习」，再提交。出现问题时回 `app.js` 找 `trim()` 与本次表单的长度检查，确认它们在加入数组之前执行。

### 预期结果

浏览器长度限制或校验提示拦住错误。其他已经输入的文字可以继续编辑。

### 提交

交两个失败和一份修改后的成功结果。

## 任务 23 | 验证完整匿名体验

前置：[处理发帖和回帖边界](/level/5?task=22)。

### 操作步骤

1. 刷新打开原项目网页。先选一篇示例帖，点开详情与发表一条虚构回复。回列表继续到「写一条」，先保存草稿，改变输入再恢复。
2. 补全标题和正文，发布后立刻点开这篇新帖。对照匿名标签、标题、回复位置和按钮名称，记录一处第一次操作不明白的地方。
3. 到原项目代码只改那一处，例如把含糊的提示换成明确的「恢复本次打开页面的草稿」。再重复原来的点击路线，确认同学从界面读得懂。

### 预期结果

一条路径能从浏览到发言，页面始终用统一的匿名标签。

### 提交

交连续操作和一个根据体验修过的问题。
