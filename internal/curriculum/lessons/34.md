# 把一次导入做成能查询进度的后台任务

需求来自使用者：导入时还能继续看任务列表，回来后知道是成功还是失败。在 `todo-server` 的开发分支先做一个只有三条标题的小导入。把任务接收与处理写成两个 Spring Bean。在启动配置加 `@EnableAsync`，为后者单独指定有上限的执行器。

~~~java
@Bean("importExecutor")
ThreadPoolTaskExecutor importExecutor() {
    var pool = new ThreadPoolTaskExecutor();
    pool.setCorePoolSize(1);
    pool.setMaxPoolSize(2);
    pool.setQueueCapacity(8);
    pool.setThreadNamePrefix("todo-import-");
    return pool;
}
~~~

创建 `import_job` 表，至少包含 id、user_id、status、imported_count、error_summary。请求先存 QUEUED 并提交事务，再由另一个 Bean 调用标记 `@Async("importExecutor")` 的公开方法。工作线程只接收 jobId，在自身事务中读出所有者和暂存的标题，成功后写 SUCCEEDED，失败写 FAILED。返回响应形如 `202 {"jobId":12}`，GET 查询时按 jobId 和登录用户筛选。列表接口仍能响应。若日志全在同一线程，检查是否从本类调用自己的方法。 [Spring 异步方法指南](https://spring.io/guides/gs/async-method/)

## 任务 125 | 理解同步与异步

用前台点单、后台备餐举例，分别写出接单、开始处理、处理完成三时刻。再画出同步导入和异步导入时 HTTP 响应落在哪一刻。提交两条时间线，并解释 202 能向学生承诺什么。

## 任务 126 | 使用 @Async 异步方法

按教程创建执行器，把导入方法移到独立的 Spring Bean。从控制器调用，分别记录接收和执行时的线程名与 jobId，使用两行不同前缀的日志证明切换已发生。不要靠在主线程 sleep 制造效果。

## 任务 127 | 批量导入异步化

用三个虚构标题发起一次导入，记录返回的 jobId，再轮询自己的状态接口，成功后核对新增三条记录。快速任务可能第一次查询就已完成，可用记录时间验证先后。提交接收响应、完成响应及查询结果；再用另一个练习账号确认读不到这个作业。

## 任务 128 | 异步异常处理

只在本地测试数据中加入一个无效标题，观察 FAILED 和人能读懂的简短原因。工作服务捕获预期错误，回滚该批写入，并在独立事务落失败状态；另为未捕获的 void 异步方法配置 AsyncUncaughtExceptionHandler 记录 jobId。再导入一份正常文件，提交两次结果并核对行数。
