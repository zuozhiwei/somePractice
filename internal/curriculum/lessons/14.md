# 给帖子和回复建表

现在让树洞记住帖子与回复。**数据库**是按约定保存和查询数据的程序，关掉 Java 后端后记录还在。**MySQL** 是本课程使用的数据库服务，SQL 是向数据库发出的命令语言。数据库里的**表**可以想成有固定列的记录表。一行帖子由**主键** `id` 唯一定位。回复的 `post_id` 是**外键**，它指向一条真实帖子。写回复前必须先有帖子。

### 保存建表脚本

在 `server` 下建 `db` 文件夹，新建 `01-treehole.sql`。这份**脚本**是可以依次运行的 SQL 文本。`VARCHAR(100)` 表示最多 100 个字符。`DATETIME(6)` 保存到微秒，本项目约定写入 UTC。`ON DELETE CASCADE` 表示删除被引用的原帖时，同库自动删除它的评论。

```sql
CREATE TABLE posts (
    id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
    title VARCHAR(100) NOT NULL,
    body VARCHAR(1000) NOT NULL,
    category VARCHAR(30) NOT NULL,
    created_at DATETIME(6) NOT NULL
);
CREATE TABLE comments (
    id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
    post_id BIGINT NOT NULL,
    body VARCHAR(500) NOT NULL,
    created_at DATETIME(6) NOT NULL,
    CONSTRAINT fk_comments_posts FOREIGN KEY (post_id)
        REFERENCES posts(id) ON DELETE CASCADE
);
```

必须先建 `posts` 再建 `comments`。在自己的开发库执行完脚本后，用 `SHOW TABLES;` 查看两张表。出现 `Table already exists` 时先用 `SHOW CREATE TABLE posts;` 检查是否已经执行过。脚本按顺序应用一次。重复练习请用新建的专用测试库，保持已有项目记录。

[MySQL 8.4 执行 SQL 文件的手册](https://dev.mysql.com/doc/refman/8.4/en/mysql-batch-commands.html)

## 任务 50 | 准备树洞练习数据库

### 操作步骤

用你自己有权限的 MySQL 安装。本任务先从 VS Code 根目录开「终端 → 新建终端」，安装后给项目单独建库和帐号。建表留给下一任务。

:::windows

1. 在 [MySQL Community Server 官网](https://dev.mysql.com/downloads/mysql/) 选择 **Microsoft Windows** 下的 **MSI Installer**。遇到登录提示可点 **No thanks, just start my download**。下载并双击 `.msi`。在向导点 **Next**，阅读并接受许可，保留默认安装位置并点 **Install**。安装结束时勾选运行 **MySQL Configurator**，再点 **Finish**。若已关闭窗口，在「开始」搜索配置器。
2. 在配置器选择开发配置，连接保留 TCP/IP，端口填 `3306`。本机练习可取消开放防火墙端口。给管理员 `root` 设密码并确认，保留作为 Windows 服务运行，再点 **Execute**，等每项成功后点 **Finish**。若提示升级已有数据库，先退出，用已有练习库继续。[Windows 官方配置说明](https://dev.mysql.com/doc/refman/8.4/en/mysql-configurator.html)
3. 点「开始」，搜索并打开 **MySQL Command Line Client**，在密码提示后输入刚设的密码并回车。如果找不到入口，在 VS Code 的 PowerShell 运行下方命令。若安装位置不同，用实际路径替换引号内的路径。

```powershell
& "C:\Program Files\MySQL\MySQL Server 8.4\bin\mysql.exe" -u root -p
```

后续示例中的 `mysql` 找不到时，用上面的 `&` 和带引号的程序路径替换命令开头，保留后面的参数。

:::

:::mac

1. 在 [MySQL Community Server 官网](https://dev.mysql.com/downloads/mysql/) 选择 **macOS**，根据芯片选 **ARM** 或 **x86, 64-bit** 的 **DMG Archive**。遇到登录提示可点 **No thanks, just start my download**。打开 `.dmg`，双击窗口中的 `.pkg`。

```bash

```

后续示例中的 `mysql` 找不到时，用 `/usr/local/mysql/bin/mysql` 替换命令开头，保留后面的参数。

:::

:::linux

在自己有管理权限的电脑上，按发行版安装 MySQL Community Server 8.4 并启动服务。若已有可用的练习库，直接使用教师提供的连接方式。[Linux 官方安装说明](https://dev.mysql.com/doc/refman/8.4/en/linux-installation.html)

如果安装时给 `root` 设了密码，在终端运行 `mysql -u root -p`。若安装时选择了本机套接字认证，从有管理员权限的用户运行 `sudo mysql` 打开客户端。

:::

看到 `mysql>` 后开始建库。`-p` 让客户端另行询问密码，输入时通常看不到回显。依次运行下列 SQL，将示例口令换成自己的本地专用口令，提交时只留占位文字。

```sql
CREATE DATABASE IF NOT EXISTS campus_treehole
  CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'treehole_app'@'localhost' IDENTIFIED BY '<仅本机练习口令>';
GRANT SELECT, INSERT, UPDATE, DELETE ON campus_treehole.*
  TO 'treehole_app'@'localhost';
```

退出用 `exit`。另开连接运行 `mysql --protocol=TCP -h localhost -P 3306 -u treehole_app -p campus_treehole`，进入后输入 `SELECT DATABASE(), CURRENT_USER();`。预期库名 `campus_treehole`、账号 `treehole_app@localhost`。如果报无法连接，先检查服务与端口。如果报 Access denied，检查账号、密码和连接主机。

### 验收与排查

两种连接身份容易混淆。管理员建库与运行迁移，`treehole_app` 日常读写。连接测试的 `CURRENT_USER()` 必须显示应用帐号，若显示 root，退出并重新以应用帐号连接。

### 提交

查询结果与脱敏连接截图。建表与迁移仍用管理员连接，后端日常读写用 `treehole_app`。

## 任务 52 | 用 SQL 操作树洞内容

### 操作步骤

从 [已建表的开发库](/level/14?task=51) 的 MySQL 客户端开始。以下示例使用一个窗口到底；`@post_id` 在换窗口后会丢失。

在 MySQL 客户端中选择 `campus_treehole`。把下列语句一次一行执行，`@post_id` 只在当前连接中有效。`WHERE` 指明要影响的那一行，执行 UPDATE 或 DELETE 前，先用相同条件 SELECT 确认选中的 ID。

```sql
INSERT INTO posts(title, body, category, created_at)
VALUES ('晚自习散步', '操场哪片路灯最亮？', 'DAILY', UTC_TIMESTAMP(6));
SET @post_id = LAST_INSERT_ID();
INSERT INTO comments(post_id, body, created_at)
VALUES (@post_id, '从东门进去的那段。', UTC_TIMESTAMP(6));
SELECT id, title, created_at FROM posts WHERE id=@post_id;
UPDATE posts SET title='晚自习后散步' WHERE id=@post_id;
SELECT id, title FROM posts WHERE id=@post_id;
SELECT id, body FROM comments WHERE post_id=@post_id;
DELETE FROM posts WHERE id=@post_id;
SELECT id FROM comments WHERE post_id=@post_id;
```

结束时最后一条查询应该是空结果，说明外键把这条测试帖的评论一起处理。若 DELETE 影响的行数是 0，先用 `SELECT @post_id;` 判断是否换了连接。把新的一组不删除的测试数据写入 `server/db/02-sample.sql`，供后续课重复读。

### 验收与排查

UPDATE 只影响一行，DELETE 后该 ID 的评论查不到，另一个保留样例仍在。最后保留的 `02-sample.sql` 只用于当前版本，第 24 关新装最终结构会用网页建立合成样例。

### 提交

创建、修改和删除后三组结果。

## 任务 53 | 核对帖子和评论归属

### 操作步骤

复用 [用SQL操作树洞内容](/level/14?task=52) 的两张表和合成文字。只把下面的 A/B 标签当自己的记录标记，实际 SQL 使用 `@post_a` 与 `@post_b`。

1. 再插入两条合成帖子，每次用 `LAST_INSERT_ID()` 把它的 ID 记下来，分别保存到 `@post_a`、`@post_b`。只给 A 插入一条回复。
2. 执行 `SELECT post_id,body FROM comments WHERE post_id=@post_a;` 与 B 的同一查询。预期一个有回复，一个为空。再运行 `SELECT id,title FROM posts ORDER BY created_at DESC,id DESC;` 查列表顺序。`DESC` 表示由大到小，时间相同时由 ID 决定先后。
3. 输入 `SELECT TIMESTAMP('2026-11-20 10:20:00') AS utc_value, DATE_ADD(TIMESTAMP('2026-11-20 10:20:00'), INTERVAL 8 HOUR) AS china_value;`。预期 10:20 转为 18:20。应用存 UTC，显示时通过 ISO JSON 与浏览器转换。

### 验收与排查

两条查询的结果必须不同。若都为空，先运行 `SELECT @post_a,@post_b;`，再核对 `SELECT post_id,body FROM comments;`。UTC 转换的结果应同时展示 10:20 与 18:20。

### 提交

两条按帖查询和 UTC 转换结果。
