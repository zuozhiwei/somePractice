# 把登录、发布和救援交给第一次接手的人
找一位没参与开发的同学当接手人，给他第 45 关的项目版本、`README.md` 和独立练习环境。请他先说出使用者到底要做什么，再从零走完「登录 → 新建 → 设为重要 → 搜索 → 刷新 → 退出」。观察他停在哪里，记下原话，不替他点。只有一台电脑时可用独立用户或新检出目录模拟另一位接手者，但最终交接要记录实际验证人。

在桌面把鼠标放到一旁：用 Tab、Shift+Tab 检查焦点顺序，用 Enter 提交表单，用原生按钮切换重要状态。当提交遇到冲突，提示应说明下一步，用户输入仍在。可以用下面的 HTML 改造每条任务的按钮，状态提示区在列表外围只放一个。渲染时用 `button.setAttribute('aria-pressed', String(task.priority === 'HIGH'))` 更新按钮，将 click 绑定到第 45 关的请求，成功后用服务端值重新渲染，失败时用提示区的 textContent 写明下一步。如果使用 Vue，把按下值绑定到 `:aria-pressed`，把请求绑定到 @click，行为一致。在窄屏把筛选栏和操作按钮换行，让长任务标题可换行。

```html
<button type="button" aria-pressed="false">重要任务</button>
<p id="feedback" role="status" aria-live="polite"></p>
```

```css
button:focus-visible { outline: 3px solid #1d4ed8; outline-offset: 2px; }
.task-title { overflow-wrap: anywhere; }
.task-actions { display: flex; flex-wrap: wrap; gap: .5rem; }
```

在手机竖屏或浏览器的 360 像素模拟视口重复流程，再打开两个标签页重复第 43 关的状态冲突。听读提示是否准确、放大文字后按钮是否仍可见。示例使用固定名称「重要任务」以便读屏，aria-pressed 表示当前状态；给选中按钮加明显边框和勾选标志，去掉颜色也能辨认。检查一次失败后可以原地重试，记下实际手机或模拟器的区别。

最后在第 41 关**自己的临时 Compose 环境**制造一次短暂服务中断。先用已登录用户获取一次列表；在另一个终端观察网页请求和服务日志。依次运行以下命令，首页静态文件通常仍为 200，而依赖后端的 API 在中断期通常为 502。服务启动后，匿名访问受保护接口应恢复为 401，随后用练习用户重新登录读取列表得到 200。systemd 路线可在自己的用户实例停止、启动 todo-server 并读用户日志。

```sh
docker compose ps
docker compose stop server
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8090/
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8090/api/tasks
docker compose start server
docker compose logs --since=5m --tail=60 web server
```

在 `docs/incident.md` 写四个真实时刻：首次观察、定位、采取恢复措施、用户路径复测。把错误状态、代理的上游地址和后端启动完成的记录放在同一时间线上；日志提交前删除凭据和个人信息。请接手人按文档再做一次启动或恢复，记录他实际花的时间和你补写的那一步。校园主机、本机端口转发或本机录屏都可交付。

## 任务 177 | 用键盘和手机完成核心流程
交一次全键盘流程和一个窄屏流程，注明视口/设备、操作步骤、焦点最后所在位置。演示一次错误输入或过期页面冲突后如何恢复，附修前卡点、修后证据与真实看得见的焦点样式。

## 任务 178 | 为一次服务故障写处置记录
在隔离演练中记录停机前、代理报错、应用重启、认证读写恢复四个时间点。分别提交网页入口与 API 的状态、用于定位的两条脱敏日志、恢复命令及一项可验收的改进，例如增加只检测后端就绪的探针。写清楚哪些用户动作在中断期间仍能完成。

## 任务 179 | 完成独立交接与作品答辩
交可重建的仓库版本、环境变量名清单、空库脚本、构建与验收步骤、备份恢复及回退说明。让实际接手人从新目录启动，登录自己的练习账号，完成一条重要任务并按说明找到该版本的测试。附其结果与耗时、你据此修正的一处文档，以及答辩中对「为什么兼容旧表、为什么允许回退」的解释。
