# 从运行指标回答服务出了什么问题

给 `todo-server/pom.xml` 加入 `org.springframework.boot:spring-boot-starter-actuator`。在本机练习的 dev 配置填写下列项并重启。专用管理端口只在回环地址监听，登录权限沿用工程现有配置。

~~~properties
management.server.address=127.0.0.1
management.server.port=9091
management.endpoints.web.exposure.include=health,metrics
management.endpoint.health.show-details=never
~~~

先打开 `http://127.0.0.1:9091/actuator/health`，预期看到 status。打开 `/actuator/metrics` 查看这个版本实际返回的名称。访问一次任务列表，再打开 `/actuator/metrics/http.server.requests`，观察 measurements 中 COUNT、TOTAL_TIME、MAX 的值与单位。用 availableTags 找出本机真实的 uri 标签，再按它过滤，避免把打开指标页面的请求也算成任务请求。若返回 401，请使用已有管理账号或本机测试配置授权读取管理端点。 [Spring Boot 管理端点](https://docs.spring.io/spring-boot/3.5/reference/actuator/endpoints.html)

## 任务 129 | 引入 Actuator

记录添加的依赖、独立端口、暴露的两个端点。启动后分别访问应用的任务页和 9091 上的 health，提交对应该版本的日志与健康响应。遇到 DOWN，先核对练习用 MySQL、Redis 是否启动，再复查状态。

## 任务 130 | 查看运行指标

从本机 metrics 清单选择 http.server.requests、jvm.memory.used 与一个实际存在的线程指标。对每项写出名称、单位和采样时间。用相同 uri 标签在列表操作前后各采样一次，以总耗时增量除以次数增量求这批请求平均耗时；增量为零时重新检查标签。

## 任务 131 | 结合指标分析性能

在自己的本地应用里用相同账号重复读取列表 20 次，记录开始与结束的指标快照，并标出 SQL 日志或缓存命中记录。写出一个可以验证的判断，例如重复读减少了数据库查询，再改变一个条件复测。交操作次数、错误数、两份快照及仍无法据此证明的事。
