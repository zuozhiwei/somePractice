# 让树洞后端稳定运行

本关在第 37 关主机上准备数据库，运行已上传的 Spring Boot JAR，并让 systemd 在断开 SSH 后仍管理这个服务。`systemd` 是 Ubuntu 的服务管理程序。用一个独立试运行库，别直接连接开发机数据或其它项目的库。

**开始前**

主机有 sudo、前端已发布、`/srv/campus-treehole/current` 指向本次发布。下文固定服务名 `campus-treehole`、试运行库 `campus_treehole_staging`，后续命令都沿用。

## 任务 142 | 准备试运行 Java 与数据迁移

### 从哪里开始

在主机 SSH 窗口确认 [静态发布链接](/level/38?task=140) 所指目录还有 `db/`。以下完整建表流程只用于空的独立试运行库。已有库时先取得自己的可恢复备份并查看部署笔记，只应用明确缺失的增量。

### 操作步骤

在主机安装运行所需程序。

```bash
sudo apt update
sudo apt install openjdk-17-jre-headless mysql-server
java -version
sudo systemctl status mysql --no-pager
```

在主机执行 `sudo env MYSQL_HISTFILE=/dev/null mysql` 进入 MySQL，输入下面的 SQL。将示例密码换成在 Ubuntu 主机上用 `openssl rand -hex 24` 生成的密码，保存到后面的环境文件。角色名 `treehole_app` 用于数据库连接，与操作系统的 `treehole` 区分开。

```sql
CREATE DATABASE campus_treehole_staging CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'treehole_app'@'127.0.0.1' IDENTIFIED BY '换成你自己的随机密码';
GRANT SELECT, INSERT, UPDATE, DELETE ON campus_treehole_staging.* TO 'treehole_app'@'127.0.0.1';
SHOW GRANTS FOR 'treehole_app'@'127.0.0.1';
EXIT;
```

空库从第一个 SQL 依序应用，目录中的数字前缀用两位固定长度。本次发布的结构 SQL 顺序是 01、03、04、05、06、07、08。若存在手工迁移依赖，按项目 README 的清单逐条执行。下例用于**这次新建的空库**。

```bash
cd /srv/campus-treehole/current
for migration in db/[0-9]*.sql; do
  case "$migration" in */02-sample.sql) continue ;; esac
  echo "Applying $migration"
  sudo mysql campus_treehole_staging < "$migration" || break
done
mysql -h 127.0.0.1 -u treehole_app -p campus_treehole_staging -e 'SELECT DATABASE(); SHOW TABLES;'
```

确认表至少含 `users`、`posts`、`comments`、`reports`、`reply_events` 和 `reply_notifications`。连接不到时用 `sudo ss -lntp` 检查 MySQL。权限不足先核对调用端绑定地址和 `SHOW GRANTS`。应用账号能读写本库即可，它不负责运行 DDL（建表与改表语句）。

**提交内容**

Java 版本、迁移顺序、应用账号脱敏授权和表列表。

## 任务 143 | 构建通过测试的 JAR

### 从哪里开始

用本机终端进入 [对应提交的仓库](/level/37?task=138) 中的 `server/`。另一个 SSH 窗口用于读主机上的文件校验。先确认两边确实是同一份候选构建物。

### 操作步骤

在本机、对应版本进入 `server/` 后运行对应平台的命令。Maven Wrapper 会按仓库指定版本运行 Maven。测试数据库仍用本机隔离的测试库。测试报告通常在 `target/surefire-reports`，先修失败，再使用同一轮得到的 JAR。

:::windows

```powershell
.\mvnw.cmd clean verify
Get-ChildItem target/*.jar
```

:::

:::mac linux

```bash
./mvnw clean verify
ls target/*.jar
```

:::

留在本机 `server/` 目录，以下两个平台都要替换实际 JAR 文件名，核验并保留此次通过测试的原文件。

:::windows

```powershell
(Get-FileHash "target/实际生成的文件.jar" -Algorithm SHA256).Hash.ToLowerInvariant()
```

:::

:::mac linux

```bash
openssl dgst -sha256 "target/实际生成的文件.jar"
```

:::

若重新跑过构建，打包文件必须来自你记录的同一轮测试，不能假定两轮 JAR 字节一致。在主机比较 `sha256sum /srv/campus-treehole/current/app.jar`。若两边不同，归档时可能复制了别的构建，要核对版本和正确 JAR，重新生成候选版本目录。要额外保留 `git rev-parse HEAD`，不能拿测试通过的 A 版本为已上传的 B 版本背书。

**提交内容**

测试摘要、提交号、主机 JAR 的名称与校验值。

## 任务 144 | 在受限环境启动树洞后端

### 从哪里开始

在主机内完成。先核对 [数据库连接账号](/level/39?task=142) 与 [JAR 校验](/level/39?task=143)。不要在 Git 提交环境文件。先临时跑这一轮，成功再交给下一张卡的系统服务。

### 操作步骤

在主机用 `sudo install -o root -g treehole -m 0640 /dev/null /etc/campus-treehole/app.env` 创建新配置（已有文件不要用这条命令覆盖），再用 `sudoedit` 编辑。使用实际随机密码。这里把 Cookie 设为 Secure，登录测试留到第 40 关的 HTTPS 入口。

```text
SERVER_ADDRESS=127.0.0.1
SERVER_PORT=8080
SERVER_FORWARD_HEADERS_STRATEGY=framework
SERVER_SERVLET_SESSION_COOKIE_SECURE=true
SERVER_SERVLET_SESSION_COOKIE_HTTP_ONLY=true
SERVER_SERVLET_SESSION_COOKIE_SAME_SITE=lax
SPRING_DATASOURCE_URL='jdbc:mysql://127.0.0.1:3306/campus_treehole_staging?connectionTimeZone=UTC&forceConnectionTimeZoneToSession=true'
SPRING_DATASOURCE_USERNAME=treehole_app
SPRING_DATASOURCE_PASSWORD=换成你的随机密码
SPRING_JPA_HIBERNATE_DDL_AUTO=validate
TREEHOLE_CACHE_PUBLIC_PAGES=false
```

用独立账号临时启动。环境文件对 shell 用简单的 `键=值` 语法，JDBC URL 含有 `&` 时在环境文件中用一对单引号包住完整值。任何值都不要写 `export` 或输出到公开日志。

```bash
sudo -u treehole sh -c 'set -a; . /etc/campus-treehole/app.env; set +a; exec java -jar /srv/campus-treehole/current/app.jar'
```

另开一个主机终端检查：

```bash
curl -i http://127.0.0.1:8080/api/health
curl -i http://127.0.0.1:8080/api/posts
sudo ss -lntp
```

健康应为 200，公开列表返回 JSON（空库可能是 `[]`）。从自己的外部设备复测 8080、3306 无法访问。Schema validation 失败时通常是没执行某个迁移，参考报错的表或列和自己的迁移清单。端口被占用时找到自己的前一次进程并正常停止。完成后在临时启动终端按 Ctrl+C。

**提交内容**

应用运行身份、主机内部的健康输出、对外访问边界。

## 任务 145 | 把后端交给系统或平台管理

### 从哪里开始

在 SSH 主机确认 [临时启动](/level/39?task=144) 已成功且按 Ctrl+C 停掉，避免两个 Java 进程抢 8080。用 `sudo systemctl --version` 核对这是 Ubuntu systemd 环境，再写本卡配置。

### 操作步骤

在主机用 `sudoedit /etc/systemd/system/campus-treehole.service` 建立单元文件。没有 systemd 的学校平台，用其启动命令、运行用户、机密变量和自动重启配置替代这块。

```ini
[Unit]
Description=Campus Treehole
After=network-online.target mysql.service
Wants=network-online.target

[Service]
Type=simple
User=treehole
Group=treehole
WorkingDirectory=/srv/campus-treehole/current
EnvironmentFile=/etc/campus-treehole/app.env
ExecStart=/usr/bin/java -jar /srv/campus-treehole/current/app.jar
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now campus-treehole
sudo systemctl status campus-treehole --no-pager
sudo journalctl -u campus-treehole -n 30 --no-pager
sudo systemctl restart campus-treehole
curl --retry 8 --retry-connrefused --retry-delay 2 -fsS http://127.0.0.1:8080/api/health
```

查看重启前后同一公开帖 ID、一个举报状态和通知积压。在第 40 关还未登录前，可以从隔离库里的合成数据用只读 SQL 检查，空库计数为 0 也要写明。若服务失败，先用日志找最深层的问题，常见是 JAR 路径、环境文件权限或缺列。修复后执行 `sudo systemctl restart campus-treehole` 再复核。

**提交内容**

托管配置、重启前后结果、日志里可定位的一行状态。
