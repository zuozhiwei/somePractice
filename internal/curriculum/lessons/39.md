# 把 Java 应用作为可重启的服务运行
你已经有能工作的数据库、认证、缓存和导入功能。先在安静的时段用测试数据构建，通过后把产物复制到 `~/todo-release/app.jar`。在 `todo-server` 下运行 `./mvnw clean verify`（Windows 使用 `.\mvnw.cmd clean verify`），选择 target 里可执行的 jar，不选 .original 或源码包。前后计算 SHA-256。

在个人虚拟机准备兼容 Java 17 的运行时、MySQL 与上一章用到的 Redis。向空的 `todo_db` 导入本项目至第 36 关的完整 schema 或迁移记录，包括账号、任务归属与索引；最初第 14 关的四列表结构只代表第一版。用练习库的应用账号访问，数据库与 Redis 用本机地址。若校园主机已由教师配置，使用分配的库与凭据。先验证 `java -version`、SQL 的 `SELECT 1`、本机 `redis-cli ping`，再启动 jar。

在 `~/.config/todo-server/env` 写入项目实际需要的 `DB_USER`、`DB_PASSWORD`、签名密钥等变量，语法为每行 `NAME=value`，文件权限 600。设 `SERVER_ADDRESS=127.0.0.1`、`SERVER_PORT=8080`，必要时设置 `SPRING_DATASOURCE_URL` 与 `SPRING_DATA_REDIS_HOST`。在个人练习机使用以下用户级 unit，保存到 `~/.config/systemd/user/todo-server.service`。

```ini
[Unit]
Description=Task board practice backend

[Service]
WorkingDirectory=%h/todo-release
EnvironmentFile=%h/.config/todo-server/env
ExecStart=/usr/bin/java -jar app.jar
Restart=on-failure
RestartSec=3

[Install]
WantedBy=default.target
```

运行 `systemctl --user daemon-reload`、`systemctl --user enable --now todo-server`，再用 `systemctl --user status todo-server` 和 `journalctl --user -u todo-server -n 30` 看结果。若连接数据库失败，按日志依次区分错误数据库名、账户授权和服务未监听。用户级服务默认随用户会话运行；要在无人登录时开机启动，请在自己的 VM 开启该用户的 linger，或用校方提供的系统级服务。只选一个进程占用 8080。

## 任务 142 | 服务器安装 JDK 与数据库
核对运行时与编译目标、MySQL 版本和当前练习库。导入完整结构后，用应用账号执行 `SELECT DATABASE();` 和 `SHOW TABLES;`，核对 task 是否有用户归属字段。提交版本表和表名，注明 Redis 地址类型，无需共享密码。

## 任务 143 | 打包后端 jar
在本地执行包含测试的 Maven 构建。用与部署相同的练习配置运行 `java -jar`，访问已实现的 /hello 或授权的健康检查。交 jar 文件名、摘要、测试统计和一次成功响应。运行失败时先检查清单入口和实际 JDK 版本。

## 任务 144 | 上传并运行后端
把已验证的 jar 放进远端 `~/todo-release`。确认两端摘要一致，启动后从远端本机使用 curl 访问与本地相同的路径。交监听地址、HTTP 结果、启动日志，截去令牌等凭据。

## 任务 145 | 用 systemd 守护进程
记录练习服务的 MainPID 与 `is-enabled`。在自己的专用 VM 使用 `systemctl --user kill --signal=SIGKILL todo-server` 模拟该演练服务意外结束；稍等后验证新 PID、active 状态及 HTTP 响应。在 VM 重启/重新登录后按选定 unit 机制验证自启动。交前后 PID、恢复日志以及是否需要登录用户。
