# 验收可恢复的本地树洞

### 开始前

从这一章的第 7 关起，树洞已经能离线记录在这个浏览器里。现在证明另一个人也能从备份和说明开始用起来。 [上一步](/level/11?task=44)

### 验收步骤

把这一章的结果存为 `v0.2`。先在原树洞发一条虚构帖子、加回复、另写一份草稿，用第 10 关的导出按钮保存 JSON。README 保留实际启动步骤和运行地址，再将 ZIP 交给同学试用。

1. 请同学在一个新目录解压作品，按 README 启动，用同一地址打开网页。可用新浏览器配置或无痕窗口模拟没有原存储的访客。
2. 点「导入练习数据」选 JSON，核对导入确认提示和帖子条数。按话题及关键词找到目标帖，打开详情并发送一条虚构回复。关掉再重开同一地址，检查帖子和评论是否还在。无痕窗口彻底关闭会清理存储，可改用普通的新浏览器配置验证重开。
3. 让同学说明什么情况下需要备份。若数据找不到，先检查主机名、端口与浏览器配置。修改一处让同学卡住的说明，再将完成的 ZIP 命名为 `campus-treehole-v0.2.zip`。

下一章继续使用原项目的页面与字段，引入 Java 后端，让两个浏览器从同一个服务读取公共内容。

## 任务 45 | 提交本地树洞版

前置：[写出一页树洞试用说明](/level/11?task=44)。[查看另一设备的验收步骤](/level/12?guide=1)。

### 操作步骤

1. 创建一条合成帖子、回复和草稿，导出为 JSON。在 README 补上实际启动方式，保留你的项目名和服务对象。按第 1 关方法给完整项目打包为 `campus-treehole-v0.2.zip`。
2. 请同学解压到另一个新目录，从新目录按 README 启动并打开树洞。让他导入 JSON，搜索你写的合成帖、打开详情并评论。用第二个标签页和刷新复查。验证重开时使用普通浏览器配置，无痕窗口全部关闭可能会清除其存储。
3. 记录对方实际地址、找到的帖子与一条回复。让他指出一个疑问，再修正你原项目的一段说明。用新副本证明修正有效，后续仍在原项目里做服务器。

### 预期结果

不同设备或浏览器能用同一份说明和备份，得到正确的树洞内容。

### 提交

交同一仓库或 ZIP、README、合成 JSON 和真实验收结果。
