# 用 Git 保存一次可以复查和撤销的改动

本关在你自己的任务看板代码副本操作。在根目录运行 `git status` 了解是否已经有仓库。尚未初始化时运行 `git init -b main`，已有仓库沿用当前主分支名称。在本仓库设置练习用显示名和邮箱别名；提交记录的作者信息可能对获得仓库访问权限的人可见。

1. 建立 .gitignore，包括 `node_modules/`、`target/`、`.idea/`、`.env`、本地密钥文件与数据库备份。保留 pom.xml、Maven Wrapper、package-lock.json 和使用占位符的配置示例。执行 `git status --short`，只暂存确认要交付的源码与文档，运行 `git diff --cached` 查看实际内容，再提交基线。
2. 从 main 运行 `git switch -c feature/search`。在前端添加搜索输入和一个只读筛选函数，让空关键字恢复完整列表，不修改原 tasks 数组。搜索后新增、勾选或删除仍然调用原 API。手动验证后提交；切回 main，原版看板应能正常运行。
3. 在功能分支与主分支的 README 同一行做两个不同、但都合理的修改，分别提交。在 main 执行 `git merge --no-ff feature/search`。遇到冲突时运行 git status，打开 README，把两侧有价值的内容合并为一句，去掉冲突标记，git add 该文件后提交。查询 `git log --graph --oneline --all -10`，应能看到合并节点。
4. 用 `git tag v1.0` 标记已验证交付点。新增一条刻意错误的纯文字说明并提交，记录其短哈希；用 `git revert 错误提交的哈希` 产生反向提交。确认 README 恢复而历史仍可追踪。最后用自己可控的远程仓库进行推送和新目录克隆验证。[Git revert 官方说明](https://git-scm.com/docs/git-revert)

## 任务 102 | 初始化仓库并首次提交

让 git status 只显示应纳入版本控制的文件，检查暂存区后完成首次提交。交 git log -1 的短哈希和忽略规则，指出为什么需要保留依赖清单却排除本地凭证与构建产物。

## 任务 103 | 分支开发新功能

在 feature/search 上实现按标题过滤，分别测试空输入、匹配与零结果。提交界面表现、功能提交哈希和两分支之间的文件差异，证明筛选不改变数据库记录数。

## 任务 104 | 合并分支并解决冲突

记录冲突文件、两边意图、最终保留的文本和合并提交。重新启动页面，验证搜索与原有添加功能同时存在。交 git log --graph 的分支图和合并后的一条界面检查。

## 任务 105 | 回滚到历史版本

在练习提交上完成一次 revert，给出 tag 指向、错误提交和反向提交的短哈希，再对照最终文件。用一句话说明 revert 新增历史、reset 移动当前分支指向；此练习使用可追溯的 revert。

## 任务 160 | 推送到远程仓库（GitHub/Gitee）

创建你能管理的空仓库（可私有并单独给教师只读权限）。在本地执行 `git remote -v`，尚无 origin 时执行 `git remote add origin 你的仓库地址`，再运行 `git push -u origin main` 和 `git push origin v1.0`。用新的空目录 git clone 后检查 HEAD、标签和 README 并启动一次。交教师可访问的链接、两个目录相同的提交哈希和启动验证；凭据使用本机凭据管理器。
