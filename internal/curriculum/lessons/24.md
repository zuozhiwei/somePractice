# 验收匿名树洞与回信

这一关把四个屏幕打通。访客首先看到帖子列表，选择发表或回复才提示登录。登录成功保留原来想做的动作。用户可以打开私有收件箱，也可以退出回到访客状态。公开页面解释匿名范围，采用「账号只用于登录和你的内容管理，公开帖子只显示匿名同学」等清楚的措辞。

用三个窗口验收。正常窗口登录甲，另一个浏览器或个人配置登录乙，无痕窗口保持访客。共享同一个 `localhost:5173` 入口。保持每个人的账号与浏览器对应，避免普通窗口共享会话导致误判。

## 任务 91 | 接上登录及树洞发言界面

### 操作步骤

按 [第 21 关账号实际接线](/level/21?task=78) 和 [第 23 关收件箱入口](/level/23?task=88) 完成后，在真实首页验收，无需再新建登录函数。

1. 从页面顶部导航接到注册、登录、退出。登录表单提交用 `signIn`，注册用 `write('/auth/register','POST',{username,password})`，只在成功后收起表单。
2. 发帖与回复分别接保护后的帖子、评论 API。开启编辑框或发送按钮时，先查看 `/auth/me` 的结果。未登录提示登录并让原输入留在页面。发布成功后刷新界面与私有回复入口。
3. 主动触发一次可恢复失败，例如在模拟网络离线时点评论。恢复网络后用原有输入重试，应只产生一次成功记录。

### 验收与排查

一次成功评论只增加一条数据库回复。先用浏览器开发工具把网络模拟为 Offline，再恢复 Online。失败后如果输入被清空，查看 `#comment-form` 是否在写请求结果确认前调用 `form.reset()`。

### 提交

关键页面的三步截图及从失败到成功的记录。

## 任务 92 | 验证多人身份与回复隔离

### 操作步骤

复用 [公开字段三身份核对](/level/22?task=85) 和 [收件箱换账号](/level/23?task=90)。本轮用同一帖从创建、阅读、评论一直走到退出。

1. 甲发帖，乙回复，访客刷新原帖。三个人都能读相同的公开文字，访客无法发言。甲能在「我收到的回复」看到乙的评论。
2. 乙尝试用相同 ID 修改甲的帖子，预期被拒并且标题不变。甲可以编辑自己的帖子。切换甲为乙后，收件箱只显示乙自己的回复。
3. 退出甲账号再刷新。已经打开的公开页仍在，任何私有页都立即清空。把每次操作与「预期/实际」写到 `docs/api-check.md`。

### 验收与排查

甲能编辑，乙只能评论或编辑自己的帖子。私有回复切换后只留当前身份内容。若 A、B 行为完全一样，首先确认两个窗口使用独立浏览器会话。

### 提交

三个视角及会话失效后的行为。

## 任务 93 | 提交可试用的匿名版本

### 操作步骤

依据 [共享版本的README](/level/18?task=69) 增加本次账号与归属迁移，沿用已做好的树洞。将「空库安装」和「旧练习库升级」分成两段。

1. 更新 README 的启动顺序，增加用户表与归属迁移。升级自己的已有练习库时，先注册本地合成账户再运行 04 回填归属。供同学从空库部署时，只运行 01、03、04，跳过前一章的 02 示例数据。空表没有行要回填，先完成 04 和后续迁移再启动当前完整后端，启动成功后通过界面注册并发布合成内容。
2. 生成 `v0.4` 源码包或记录相应 Git 版本。请一位同学按文档注册虚构账号，匿名看帖、登录评论并核对是否可以找到收件箱。
3. 问对方如何理解匿名提示。按实际反馈改一句产品说明，再在匿名窗口确认没有真实用户名或用户 ID 字段。

### 验收与排查

若新同学反馈后端还没启动就需要网页注册，把说明改成先执行 01、03、04（空表无旧帖需回填），启动后再从网页注册。旧库路径按 [已有数据迁移](/level/22?task=82) 执行。

### 提交

版本、真实复现记录和修订前后的提示。
