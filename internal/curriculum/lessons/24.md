# 在前端接入登录、退出和用户切换

后端已有注册、登录、任务归属校验。前端沿用第 17 关 `todo-app/src/api.js`。先在 Postman 证明同一个测试账号可以正常登录并读取任务，再接浏览器，便于区分前端问题和权限问题。

1. 在 `src/auth.js` 提供读取、保存、删除凭证的方法。课程版用同源页面的 localStorage 实现刷新续登；只保存当前 token 和必要的展示名，不保存密码。处理用户文字时用 textContent 或框架默认转义。使用两个独立浏览器上下文进行双账号检验，因为同一源的普通标签页共享 localStorage。
2. 给现有 Axios 实例安装请求拦截器。注册和登录使用公共路径，其他 /api 请求附上 Bearer 头。用 `POST /api/auth/register` 注册，`POST /api/auth/login` 成功后从返回 JSON 的 token 字段读取凭证，再进入看板。登录表单增加 loading 状态，失败时保留用户名并显示后端消息。

~~~js
api.interceptors.request.use(config => {
  const token = localStorage.getItem('todo.token')
  const publicPath = ['/auth/login', '/auth/register'].includes(config.url)
  if (token && !publicPath) config.headers.Authorization = 'Bearer ' + token
  return config
})
~~~

3. 页面首次加载先检查 token；缺少时展示登录页或跳登录路由。收到任务接口的 401 时清理凭证和旧的任务列表，再进入登录页。退出也清除上述两项并取消尚未完成的列表请求，避免上一账号的慢响应写入新会话。简单实现可在开始请求时记下当前 token，响应回来时仅在 token 仍相同的情况下更新页面。
4. 用 A 登录新增「A 的草稿」，刷新、退出；接着 B 登录。B 初始列表只能看到 B 的记录。重复上面流程，并测试关掉后端时页面给出网络异常提示。记录状态、用户代号和响应码就足以复现，不需要截取密码或 Authorization 值。
