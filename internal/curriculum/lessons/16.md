# 用五个接口完成一条任务的完整生命周期

继续在 `todo-server` 的任务控制器工作。上一关已有列表和创建接口。这一关的请求均只操作自己创建的练习数据。在类上保留 `@RequestMapping("/api/tasks")`，方法上的路径从 `/{id}` 开始写，避免重复前缀。

1. 提取 `findTask(long id)`，调用 `repository.findById(id).orElseThrow(() -> new ResponseStatusException(HttpStatus.NOT_FOUND, "任务不存在"))`。`Optional<Task>` 表达“可能没有这一行”；把异常映射为 404 后，前端才能区分“查无此项”和服务故障。
2. 依次补齐这三个处理方法。给 Task 添加上一关用到的 setter。示例中 PUT 表示替换可编辑的标题与完成状态，因此客户端两个字段都传；上线前要校验标题不能为空且不超过数据库列宽。

~~~java
@GetMapping("/{id}")
public Task one(@PathVariable long id) { return findTask(id); }

@PutMapping("/{id}")
public Task replace(@PathVariable long id, @RequestBody TaskInput input) {
    if (input.title() == null || input.title().isBlank()
            || input.title().strip().length() > 200) {
        throw new ResponseStatusException(HttpStatus.BAD_REQUEST, "标题长度应为 1 至 200");
    }
    Task task = findTask(id);
    task.setTitle(input.title().strip());
    task.setDone(input.done());
    return repository.save(task);
}

@DeleteMapping("/{id}")
@ResponseStatus(HttpStatus.NO_CONTENT)
public void remove(@PathVariable long id) { repository.delete(findTask(id)); }
~~~

3. 在 Postman 环境保存 `baseUrl=http://localhost:8080`。POST 新建，取返回的 id 设置变量 `taskId`；GET `{{baseUrl}}/api/tasks/{{taskId}}`、PUT 同地址、DELETE 同地址，最后再 GET。预期最后一步为 404。若 PUT 后过几秒值又恢复，确认更新了同一行并调用了 save。若收到 405，先核查方法和路由；415 通常需要将 Body 设为 raw JSON。
