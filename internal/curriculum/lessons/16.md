# 提供帖子详情与评论接口

继续扩充第 15 关的 `PostController.java`。**CRUD** 指创建、读取、修改和删除。HTTP 请求由方法和路径共同确定。`{id}` 是前端从创建响应里取得的实际数字。`200` 表示正常返回数据，`201` 表示新记录已创建，`204` 表示成功且没有正文，`400` 表示数据不合要求，`404` 表示找不到这条帖子。先只在自己的本机练习写入，账号与授权将在 19–22 关补上。

| 方法与路径 | 预期 |
| --- | --- |
| GET /api/posts | 200 帖子数组 |
| POST /api/posts | 201 新帖 |
| GET /api/posts/{id} | 200 帖子详情 |
| PATCH /api/posts/{id} | 200 更新后的帖子 |
| DELETE /api/posts/{id} | 204 无正文 |
| GET /api/posts/{id}/comments | 200 评论数组 |
| POST /api/posts/{id}/comments | 201 新评论 |

### 扩充帖子控制器

先把 `import org.springframework.web.server.ResponseStatusException;` 加在文件顶部的 import 区。把原构造函数换成下方版本。在同一个类的结束大括号之前粘贴后面的公共方法，保留已有的 list、create、view 与 DTO。

```java
final CommentRepository comments;

PostController(PostRepository posts, CommentRepository comments) {
    this.posts = posts;
    this.comments = comments;
}

private Post requirePost(Long id) {
    return posts.findById(id).orElseThrow(
        () -> new ResponseStatusException(HttpStatus.NOT_FOUND, "找不到这条帖子"));
}

@GetMapping("/{id}")
public PostView detail(@PathVariable Long id) {
    return view(requirePost(id));
}

@PatchMapping("/{id}")
public PostView update(@PathVariable Long id, @Valid @RequestBody WritePost input) {
    Post post = requirePost(id);
    post.replace(input.title().trim(), input.body().trim(), input.category().trim());
    return view(posts.save(post));
}

@DeleteMapping("/{id}")
@ResponseStatus(HttpStatus.NO_CONTENT)
public void remove(@PathVariable Long id) {
    posts.delete(requirePost(id));
}

@GetMapping("/{id}/comments")
public List<CommentView> listComments(@PathVariable Long id) {
    requirePost(id);
    return comments.findAllByPostIdOrderByCreatedAtAscIdAsc(id).stream()
        .map(PostController::commentView).toList();
}

@PostMapping("/{id}/comments")
@ResponseStatus(HttpStatus.CREATED)
public CommentView createComment(@PathVariable Long id, @Valid @RequestBody WriteComment input) {
    requirePost(id);
    return commentView(comments.save(
        new Comment(id, input.body().trim(), LocalDateTime.now(ZoneOffset.UTC))));
}

static CommentView commentView(Comment comment) {
    return new CommentView(comment.id.toString(), comment.body,
        comment.createdAt.toInstant(ZoneOffset.UTC).toString());
}

public record WriteComment(@NotBlank @Size(max = 500) String body) {}
public record CommentView(String id, String body, String createdAt) {}
```

`@PathVariable` 从地址取 ID。评论请求只收正文，关联的帖子由地址决定。这个课程版本把 PATCH 定义为提交三个可编辑字段，表单打开时先填入原值。保存文件后重启后端；以下测试用的 42 要替换为你第 15 关得到的真实数字。

## 任务 58 | 修改同一条帖子

### 操作步骤

从 [写入数据库的接口](/level/15?task=57) 读回一次自己创建的 ID。先一次性按 [本关参考资料「扩充帖子控制器」](/level/16?guide=1#扩充帖子控制器) 更新 `PostController.java`，此后的详情、删除、回复都复用这段实现。

在 `server/db/example-edit.json` 记录一条新标题、原来的正文与分类，例如 `{"title":"图书馆九点的灯","body":"还有同学在吗？","category":"DAILY"}`。

切到 `server`，把下方两条命令的 `42` 都换成真实 ID。先执行第一条并记下 ID 和时间，再执行第二条修改标题。

:::windows

```powershell
curl.exe -i http://localhost:8080/api/posts/42
curl.exe -i -X PATCH -H "Content-Type: application/json" --data-binary "@db/example-edit.json" http://localhost:8080/api/posts/42
```

:::

:::mac linux

```bash
curl -i http://localhost:8080/api/posts/42
curl -i -X PATCH -H "Content-Type: application/json" --data-binary "@db/example-edit.json" http://localhost:8080/api/posts/42
```

:::

返回 200 且标题改变，ID、发布时间与先前相同。若是 400，检查 JSON 双引号及三项字段是否都给出。重新读取评论，原帖的回复仍保留。

### 验收与排查

写入后 GET 同一 ID，标题改变且创建时间与回复关系保留。如果只有 GET 200 而 PATCH 是 405，查看 `@PatchMapping("/{id}")`，不要把 PATCH 发到 `/api/posts` 列表。

### 提交

修改前后响应，并标出两个保留下来的字段。

## 任务 59 | 删除一条练习帖

### 操作步骤

用 [新增测试帖](/level/15?task=57) 建一条专门做删除的合成帖，接着用 [已有SQL评论操作](/level/14?task=52) 给这个 ID 留一句。确认 SQL 的 `post_id` 与 GET 详情的 ID 一致。

创建一条标题含「可删测试」的帖子并回复一次，记下响应 ID。把下方命令的 `42` 换成该 ID 后执行。

:::windows

```powershell
curl.exe -i -X DELETE http://localhost:8080/api/posts/42
```

:::

:::mac linux

```bash
curl -i -X DELETE http://localhost:8080/api/posts/42
```

:::

预期状态 204，最后没有 JSON。使用 GET 请求原地址，预期 404。进入 MySQL 执行 `SELECT id FROM posts WHERE id=42;` 和 `SELECT id FROM comments WHERE post_id=42;`，均无记录。

若删除时报外键错误，在练习库执行 `SHOW CREATE TABLE comments;` 查第 14 关的级联规则。修改迁移前先保存检查结果和被删除样例的 ID。

### 验收与排查

删前先在 GET 结果核对标题含「可删测试」。一个旧 ID 的详情和评论都应返回 404。若删除请求在浏览器地址栏打开仍能看到详情，地址栏默认发 GET，需用终端的 `-X DELETE`。

### 提交

204、404 和两处 SQL 结果。

## 任务 60 | 通过 ID 打开帖子详情

### 操作步骤

使用 [控制器章节](/level/16?guide=1#扩充帖子控制器) 的 `detail` 与 `listComments`。准备 A、B 两个可查 ID；用 [已有SQL评论操作](/level/14?task=52) 给 A 留一条合成评论。

1. 保持两条可见测试帖，仅给 A 留一条评论。用浏览器分别打开 `/api/posts/A的ID` 和 `/api/posts/A的ID/comments`，后者预期是含评论的一条数组。
2. 打开 `/api/posts/B的ID/comments`，预期是 `[]`。用 MySQL 确认一个不存在的正整数 ID 后，再请求它的详情和评论，二者预期都是 404。
3. 若已存在但无回复也得到 404，查控制器是否把空评论列表误当成缺少帖子。判断存在应查看帖子表。

### 验收与排查

GET A 评论是含记录的数组，GET B 的返回是 `[]`。404 必须用不存在的帖子 ID，如从表里查不到的 `999999`，而不是拼写错误的路径。

### 提交

详情、一条评论、空数组和 404 的对照。

## 任务 61 | 新增一条评论

### 操作步骤

复用 [通过接口写一条帖子](/level/15?task=57) 的终端、JSON 文件和 Content-Type 做法，本次路径多 `/{id}/comments`，请求正文只保留 `body`。

在 `server/db/example-comment.json` 写入 `{"body":"我刚从那里回来，东门那段有灯。"}`。记下 A、B 两帖评论数。

在 `server` 下运行下面的请求，把路径里的 `42` 换成 A 的 ID。预期 201，返回三个字段 `id/body/createdAt`。

:::windows

```powershell
curl.exe -i -H "Content-Type: application/json" --data-binary "@db/example-comment.json" http://localhost:8080/api/posts/42/comments
```

:::

:::mac linux

```bash
curl -i -H "Content-Type: application/json" --data-binary "@db/example-comment.json" http://localhost:8080/api/posts/42/comments
```

:::

重新读取 A、B 的评论。A 多一条，B 数量不变。再用空正文发送一次，预期 400。若多次请求后数量增加多次，核对你实际执行了几次 POST。

### 验收与排查

成功时 A 只增加一条回复，B 保持不变。如果两处显示同一条记录，查 `CommentRepository.findAllByPostIdOrderByCreatedAtAscIdAsc` 是否使用 `postId` 作过滤，检查自己在 URL 与 SQL 使用的 ID 是否相同。

### 提交

一个成功响应及两帖变动前后结果。

## 任务 62 | 完整验证树洞 API

### 操作步骤

先用 [详情和评论](/level/16?task=60) 的读取路径，以及 [编辑](/level/16?task=58) 和 [删除](/level/16?task=59) 的写入命令。新建 `docs/api-check.md` 记录一条全新的合成帖演练。

1. 在 `docs/api-check.md` 建一张含「操作、方法和路径、期望状态、实际状态」的表。
2. 用一条新帖完成整链。POST 建帖得到 ID，POST 加评论，PATCH 更改标题，GET 查详情及评论，DELETE 后再 GET。每次都记录相同 ID。
3. 另测一次超长标题、没有正文的评论、访问不存在的帖。对照 400 与 404。遇到错先在终端查同一时间点报错，再核对网络页的请求地址和请求正文。

### 验收与排查

正常流程状态依次为 201、201、200、200、204、404。若删除前的详情结果已 404，回查第一步 POST 的返回 ID；若非法输入被保存，查请求参数前是否有 `@Valid`。

### 提交

用自己的 ID 填好的验收表、一条正常和一条失败 JSON。
