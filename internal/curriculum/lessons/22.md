# 把任务归属落实到每一条数据库查询

带上第 21 关进入服务层的 currentUserId。先在练习库查 `SELECT id,username FROM user_account;`，确认两个测试账号各自的编号。给旧任务安排归属时逐条核对来源，无法确认的记录先留在备份副本里，避免误指给别的账号。

1. 导出练习库并验证可恢复，再在副本执行 `ALTER TABLE task ADD COLUMN user_id BIGINT NULL;`。为已确认归属的旧任务按其明确 id 回填 user_id，检查 `SELECT COUNT(*) FROM task WHERE user_id IS NULL;`。当所有待迁移行均确认后，添加 NOT NULL、索引以及 `FOREIGN KEY (user_id) REFERENCES user_account(id) ON DELETE RESTRICT`。脚本放入 `database/003_task_owner.sql`。如果外键失败，核对两个列的数据类型、存储引擎以及孤儿记录。
2. Task 映射增加 `@Column(name="user_id", nullable=false) private Long userId;`。创建方法接收 currentUserId、title、done，把 userId 直接写入实体。输入类型不接收 ownerId。仓库增加 `List<Task> findAllByUserIdOrderByIdAsc(long userId)`、`Optional<Task> findByIdAndUserId(long id,long userId)`。
3. 列表只用第一个方法。单个读取、更新、删除统一在事务内用归属条件查找，再修改或删除已核实的实体。若该 id 存在但归属不符，按本课接口约定返回 HTTP 403；全库没有此 id 则 404。实现可先尝试 `findByIdAndUserId`，失败时用 `existsById` 区分这两种响应。在固定所有权的这套课程中用户没有转移任务的接口。
4. 在两个独立浏览器会话或两个 Postman 环境分别登录，分别创建唯一前缀的任务，通过列表观察隔离结果。若列表展示了全库，查控制器是否还残留无条件 findAll。JPA 的方法名绑定参数，自己写 JPQL 时也用命名参数绑定 owner 和 id。[Spring Data JPA 查询方法](https://docs.spring.io/spring-data/jpa/reference/jpa/query-methods.html)
