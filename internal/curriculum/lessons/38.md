# 先让树洞的公开页面打开

这一关先检查静态构建物是否能被浏览器读取。**静态文件**是 JS、CSS、HTML 等已经构建好的文件，浏览器直接下载。首页脚本发起的接口请求还要等后端接入。试运行只有 HTTP 时，只用它检查静态资源，等第 40 关验证过 HTTPS 再填写账号密码。

**开始前**

第 37 关的发布目录已经有 `web/` 和其对应的 `commit.txt`。有域名时将文档中的 `treehole.example.org` 换成实际域名或学校分配的名字。没有域名时可暂用自有主机地址做 HTTP 查看，之后切换公网站点需要能签发证书的域名。

## 任务 139 | 构建同仓库的树洞前端

### 从哪里开始

在本机打开 [上一张发布包的提交](/level/37?task=138) 对应的源码。不要进入远程主机的静态目录执行 npm。看终端路径以 `campus-treehole/web` 结尾后再构建。

### 操作步骤

1. 在本机确认 `git rev-parse HEAD` 和发布目录 `commit.txt` 一致。进入 `web/`，执行对应平台的命令。`npm ci` 从现有锁文件安装依赖，`dist/` 是发布目录。若没有锁文件，按项目已有构建器生成并提交锁文件，再使用该命令。未引入构建器的项目可直接把网站入口及其引用的资源复制进 `dist/`。

:::windows

```powershell
node --version
npm.cmd ci
npm.cmd run build
Get-ChildItem dist
```

:::

:::mac linux

```bash
node --version
npm ci
npm run build
ls -la dist
```

:::

2. 确认 `dist/` 有 `index.html` 和页面引用资源。打开 JS 请求代码，确认它用 `/api/posts` 等相对路径。下方命令可在本机预览资源；没有后端代理时出现接口错误属于预期。

:::windows

```powershell
npm.cmd run preview -- --host 127.0.0.1
```

:::

:::mac linux

```bash
npm run preview -- --host 127.0.0.1
```

:::

3. 核对静态目录不包含环境配置、SQL 或 JAR。正常没有输出。

:::windows

```powershell
Get-ChildItem dist -Recurse -Force | Where-Object { $_.Name -match '^\.env|\.(sql|jar)$' }
```

:::

:::mac linux

```bash
find dist -name '.env*' -o -name '*.sql' -o -name '*.jar'
```

:::

若发现杂项，修正构建或复制规则并重新生成后再上传。文件上传仍沿用上关的版本目录约定。

**提交内容**

实际构建命令、版本、文件清单及本机预览结果。

## 任务 140 | 配置前端静态入口

### 从哪里开始

回到主机 SSH 窗口。先用 `ls /srv/campus-treehole/releases/v0.6-observable/web/index.html` 确认 [已有的发布包](/level/37?task=138) 中有首页。配置文件只在主机上编辑。

### 操作步骤

在主机安装 Nginx（若试运行平台已托管此部分，进入平台的静态站点设置，选择你刚上传的 web 目录作为根路径）。

```bash
sudo apt update
sudo apt install nginx
sudo ln -s /srv/campus-treehole/releases/v0.6-observable /srv/campus-treehole/current
```

如果 `current` 已存在，先用 `readlink /srv/campus-treehole/current` 记下现版本，改用第 45 关的切换方法。用 `sudoedit /etc/nginx/sites-available/campus-treehole` 写入站点。这里的 `/?post=<ID>` 是首页查询参数，静态服务本来就会返回首页，未知资源应 404。

```nginx
server {
    listen 80;
    server_name treehole.example.org;
    root /srv/campus-treehole/current/web;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }

    location ^~ /api/ {
        default_type application/json;
        return 503 '{"error":"树洞接口准备中"}';
    }

    location ~ /\. {
        deny all;
    }
}
```

若项目用真正的前端子路由，如 `/posts/42`，单独在该前缀下配置 `try_files $uri /index.html;`，其余资源仍走原规则。启用并验证如下。若链接已存在可以跳过创建。

```bash
sudo ln -s /etc/nginx/sites-available/campus-treehole /etc/nginx/sites-enabled/campus-treehole
sudo nginx -t
sudo systemctl reload nginx
curl -I -H 'Host: treehole.example.org' http://127.0.0.1/
curl -I -H 'Host: treehole.example.org' http://127.0.0.1/does-not-exist.js
```

第一条 HTTP 测试应为 200，第二条 404。看到 Nginx 欢迎页时核对命令里的 Host 与 `server_name`，以及静态根路径的 `index.html`。看到 403 时检查读取权限及目录可遍历权限，可以运行 `namei -l /srv/campus-treehole/current/web/index.html`。

**提交内容**

实际站点配置片段、校验通过输出、真实资源 200 和未知资源 404。

## 任务 141 | 用第二台设备做静态验收

### 从哪里开始

先用 [正在提供的静态入口](/level/38?task=140) 拿到访问地址。电脑在 Network 查资源状态，手机实际打开同一个名字或 IP；此时仍不测试登录。

### 操作步骤

1. 手机用项目允许的试运行网络打开首页，或请一位同学在相同测试网打开。把缩放设为默认。检查标题、分类按钮、筛选开关、详情返回按钮在窄屏上是否可读可点。
2. 电脑打开开发者工具 Network，禁用缓存再刷新。HTML 200；CSS 和 JS 200 且类型匹配。此时 `/api/...` 503 应显示清楚的加载失败或准备状态，页面仍能阅读标题和公共界面。控制台不应出现脚本文件返回 HTML、模块加载失败。
3. 若外部设备无法打开而主机 curl 成功，核对 DNS、设备所属网络和主机入口 80 规则。若 DNS 还没发布，可以在主机上用上一节的 Host 命令继续自测，再给出未完成的手机验收项。

**提交内容**

两台设备打开的入口、窄屏观察、资源状态和当前还未接上的操作。
