# 用有期限的缓存读取同一个人的任务列表

本关用 Redis 保存短期副本，MySQL 仍负责保存任务。起步时只缓存“当前用户、默认排序、第一页、未筛选”这一种列表，其余查询直接走原来的服务。可在自己的 Debian/Ubuntu 练习机安装发行版提供的 redis-server 并启动本机服务；已有 Docker 的同学也可用 `docker run --name todo-redis -d -p 127.0.0.1:6379:6379 redis:7-alpine`，再用 `docker exec -it todo-redis redis-cli` 操作。先输入 `PING`，应看到 PONG。在 Redis 命令行输入下面三行。

~~~text
SET todo:lab:ping hello EX 30
GET todo:lab:ping
TTL todo:lab:ping
~~~

引入 `org.springframework.boot:spring-boot-starter-data-redis`（版本跟随 Boot）。在 dev 配置里写 `spring.data.redis.host=127.0.0.1` 和 `spring.data.redis.port=6379`。给列表服务注入 `StringRedisTemplate`、`ObjectMapper`。用已经认证的用户 id 构造键，例如 `todo:v1:u:27:list:first`。读出字符串并反序列化现有列表 DTO；未命中时查 MySQL 并序列化结果，再写 `redis.opsForValue().set(key, json, Duration.ofSeconds(60))`。遇 Redis 连接失败，保留原查询作为可用路径。 [Spring Data Redis 官方入门](https://spring.io/guides/gs/messaging-redis/)

## 任务 121 | 安装并启动 Redis

启动 Redis 后记录 PING、SET、第一次 GET 和 30 秒后 GET 的结果，最后一次应为空。若连接拒绝，先确认 Redis 已运行及端口只映射到本机。提交不含其他键值的四行结果。

## 任务 122 | Spring Boot 接入 Redis

写一条开发环境的集成测试，注入 StringRedisTemplate，给 todo:lab:roundtrip 写入“已连接”、设置 30 秒有效期，再读取并断言同一字符串。运行单个测试，记录 Spring 使用的端口与测试结果。键不存在和连接失败要能从结果中分辨。

## 任务 123 | 缓存任务列表

给列表服务加两个仅用于观察的计数或日志 HIT/MISS，不输出令牌或任务正文。用账号 A 连续读三次、账号 B 再读一次，预期 A 首次 MISS、两次 HIT，B 首次 MISS 且只看到自己的列表。提交去除私人信息的记录、耗时与实际命中比例。

## 任务 124 | 缓存失效策略

对新建、改名、勾选、删除四种写操作，在数据库事务成功提交后删除该用户的默认列表键；可用 @TransactionalEventListener(phase=AFTER_COMMIT) 接收服务在事务内发布的事件。先命中旧缓存，再分别写入与读取，记录返回内容和新的 MISS。解释有效期如何限制删除失败时的陈旧时间。

## 任务 163 | 认识缓存穿透、击穿与雪崩

画出“收到请求→查缓存→查数据库→写缓存”的四格流程。在图上分别标记不存在的记录反复查询、热门键恰好失效、许多键同时失效的位置。给每种情形配一种本项目可用的措施（例如短时缓存空结果、合并同一个键的读取、错开过期时间），说明一个取舍。用纸笔或文档提交即可。
