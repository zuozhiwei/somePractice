# 为公开列表加可验证的缓存

第 32 关已能准确分页。**缓存**是保存一小份近期查询结果的临时存储。只在单实例开发环境试用内存缓存，目标是减少热点列表的排序查询。缓存里的候选 ID 和游标都没有访问权限。回给浏览器前仍要按数据库当前状态检查每条帖子。详情、搜索、评论、个人收件箱、审核队列全部继续走数据库。

**开始前**

留着性能库及上一关测试。先验证 `curl http://localhost:8080/api/posts?limit=20`，并记录关闭缓存时的时间。依赖版本由 Spring Boot 管理。

### 可以关闭的缓存服务

在 `server/src/main/java/edu/campus/treehole/PublicPageCache.java` 保存以下文件。方法签名里的 `Supplier` 用来把「原本怎么读下一页」交给缓存；`Function` 用来按 ID 提取或批量读取公开记录。这样能从测试中替换数据源，关闭缓存时直接调用原路径。

```java
package edu.campus.treehole;

import com.github.benmanes.caffeine.cache.Cache;
import com.github.benmanes.caffeine.cache.Caffeine;
import java.time.Duration;
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.concurrent.atomic.AtomicLong;
import java.util.function.Function;
import java.util.function.Supplier;
import org.slf4j.LoggerFactory;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Service;
import org.springframework.transaction.event.TransactionPhase;
import org.springframework.transaction.event.TransactionalEventListener;

@Service
public class PublicPageCache {
    private static final org.slf4j.Logger LOG = LoggerFactory.getLogger(PublicPageCache.class);
    private final boolean enabled;
    private final AtomicLong generation = new AtomicLong();
    private final Cache<PageKey, Candidates> pages = Caffeine.newBuilder()
            .maximumSize(64).expireAfterWrite(Duration.ofSeconds(20)).recordStats().build();

    public PublicPageCache(@Value("${treehole.cache.public-pages:false}") boolean enabled) {
        this.enabled = enabled;
    }

    public <T> PostPages.Page<T> read(String category, int limit, String cursor, String q,
                                    Supplier<PostPages.Page<T>> query, Function<T, String> id,
                                    Function<List<String>, List<T>> readVisible) {
        if (!enabled || limit != 20 || cursor != null || !q.isEmpty()) return query.get();
        var key = new PageKey(generation.get(), category, limit);
        Candidates candidate;
        try {
            candidate = pages.getIfPresent(key);
        } catch (RuntimeException cacheError) {
            LOG.warn("public_page_cache_read_failed");
            return query.get();
        }
        if (candidate == null) {
            var fresh = query.get();
            try {
                pages.put(key, new Candidates(fresh.items().stream().map(id).toList(), fresh.nextCursor()));
            } catch (RuntimeException cacheError) {
                LOG.warn("public_page_cache_write_failed");
            }
            return fresh;
        }
        if (candidate.ids().isEmpty()) return query.get();
        var byId = new HashMap<String, T>();
        for (var item : readVisible.apply(candidate.ids())) byId.put(id.apply(item), item);
        var ordered = new ArrayList<T>();
        for (var candidateId : candidate.ids()) {
            var item = byId.get(candidateId);
            if (item == null) return query.get();
            ordered.add(item);
        }
        return generation.get() == key.generation()
                ? new PostPages.Page<>(List.copyOf(ordered), candidate.nextCursor())
                : query.get();
    }

    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    void onPublicPostsChanged(PostsChanged event) {
        generation.incrementAndGet();
        try {
            pages.invalidateAll();
        } catch (RuntimeException cacheError) {
            LOG.warn("public_page_cache_invalidate_failed");
        }
    }

    long hits() { return pages.stats().hitCount(); }
    long misses() { return pages.stats().missCount(); }

    public record PostsChanged() {}
    private record PageKey(long generation, String category, int limit) {}
    private record Candidates(List<String> ids, String nextCursor) {}
}
```

在原 `PostRepository` 增加以下查询方法。它要求 `Post` 的 `status` 已按第 26 关映射。如果实体使用枚举，请将第二个参数换成该枚举，调用处用已有的 `VISIBLE` 枚举值。

```java
List<Post> findByIdInAndStatus(List<Long> ids, String status);
```

把 `PublicPageCache publicPages` 加到原 `PostController` 的字段和构造器。在第 32 关新的 `list` 方法中，保留无页长分支，仅把最后一行分页调用换成下面的代码。生产前默认关闭，因此现有接口和无页长调用继续原来的读取方式。

```java
return publicPages.read(category, limit, cursor, q,
        () -> postPages.list(category, q, limit, cursor),
        PostView::id,
        ids -> posts.findByIdInAndStatus(ids.stream().map(Long::valueOf).toList(), "VISIBLE")
                .stream()
                .filter(post -> category.isEmpty() || category.equals(post.category))
                .map(PostController::view)
                .toList());
```

在创建、编辑、删除、隐藏、撤销的写事务中，注入 `ApplicationEventPublisher`，完成数据库修改后调用 `publisher.publishEvent(new PublicPageCache.PostsChanged())`。该调用与事务提交不同，监听器会等待提交完成才切换代号。缓存代码不接手权限，也不捕获读取数据库时发生的异常。

## 任务 121 | 为树洞准备隔离的缓存配置

### 从哪里开始

在本机 `server/pom.xml` 加依赖，再打开 [可以关闭的缓存服务](/level/33?guide=1#可以关闭的缓存服务) 复制完整类。它接在 [第 32 关的分页接口](/level/32?task=118) 后，先跑关闭缓存的版本。

### 操作步骤

在 `server/pom.xml` 的 `<dependencies>` 加入以下依赖。Caffeine 是本进程里的有界内存缓存，重启后为空。

```xml
<dependency>
  <groupId>com.github.ben-manes.caffeine</groupId>
  <artifactId>caffeine</artifactId>
</dependency>
```

在 `server/src/main/resources/application.properties` 新增 `treehole.cache.public-pages=${TREEHOLE_CACHE_PUBLIC_PAGES:false}`。[缓存服务](/level/33?guide=1#可以关闭的缓存服务) 在构造器读取此开关。配置只对公开列表生效。继承原本的数据库环境。在本机 `server/` 运行下方两组，第一组验收完按 Ctrl+C，再运行第二组，记录重启前后的结果。默认保留关闭，性能实测证明确有收益再为单实例启用。

:::windows

```powershell
$env:TREEHOLE_CACHE_PUBLIC_PAGES = "false"

$env:TREEHOLE_CACHE_PUBLIC_PAGES = "true"
.\mvnw.cmd spring-boot:run
```

:::

:::mac linux

```bash
export TREEHOLE_CACHE_PUBLIC_PAGES=false
```

:::

容量和时长在 [本关参考「可以关闭的缓存服务」](/level/33?guide=1#可以关闭的缓存服务) 的代码里。若 Maven 找不到版本，先确认继承 Spring Boot 的父项目或使用它的依赖管理。

## 任务 122 | 设计无私有内容的公开键

### 从哪里开始

在 IDE 打开 [缓存服务](/level/33?guide=1#可以关闭的缓存服务) 的 `PublicPageCache.java`，用搜索功能找 `PageKey`、`Candidates` 和 `if (!enabled`。这三处决定什么能入缓存。

### 操作步骤

1. 从 [缓存服务](/level/33?guide=1#可以关闭的缓存服务) 的代码找到 `PageKey` 和 `Candidates`。键的类别来自公开分类，空串代表全部。由于只缓存首页，游标不必放进键。先只缓存首页（游标为空）、固定 20 条、无搜索词的路径。其它请求仍使用已有方法，避免为每个任意词或同学的浏览习惯留一份缓存。
2. 取最新 `generation.get()` 生成键。正常排序查询产生 `Candidates(ids, nextCursor)`。不要把帖子 DTO、会话、楼主 ID、举报原因或 Spring Security 的当前用户存进去。
3. 将有缓存资格的逻辑放在公开列表内部。普通访客读和登录用户读都取相同公开字段。授权给角色的响应仍各自通过原路由生成。

**提交内容**

写一组演示键，比如 `generation=2/category=DAILY/limit=20`，再写一个绝不进入缓存的私有 URL。

## 任务 123 | 验证一次可解释的缓存命中

### 从哪里开始

按 [缓存配置](/level/33?task=121) 启动本机服务，打开另一个终端。两次命令用同一个地址和页长，先用下面的 SQL 理解第二次的回源条件。

### 操作步骤

记住两类查询。第一次仍按状态、时间和分类排序后取一页 ID；后面的请求只按一页 ID 批量读可见记录。

```sql
SELECT id, title, body, category, created_at
FROM posts WHERE id IN (:ids) AND status = 'VISIBLE';
```

1. 可缓存的请求先用 `pages.getIfPresent(key)`。没有候选或空候选时走原分页查询。对非空候选通过 Repository 批量查询。将结果暂存为 ID 对照表，再按缓存的原序重建公开 DTO。即使缓存返回未刷新的一页，隐藏、删除记录也不会带正文回去。若某个候选从数据库消失，丢弃整个候选页，按正常查询重新计算页长及游标。
2. 重启有开关的开发服务，在 20 秒内连续访问同一页两次。记录缓存服务 `hits()` 和 `misses()` 的差值，另记按 ID 批查的次数。可以用单元测试打印这三个普通数字，避免增加公开的内部诊断页面。
3. 对照第 31 关测量。即使「命中」，仍须执行权限相关的数据读取。若总时延和查询负担没有改善，就让它维持关闭，并记录可能原因。

在仓库正常运行，另开本机终端连续执行两次同一个请求。使用性能库的合成内容。两页应有相同的条目和顺序；若立即都从原排序回源，检查启动开关、是否带了 q 或 cursor、页长是否恰为 20。验收后按需删除两份临时响应文件。

```powershell
curl.exe -fsS 'http://localhost:8080/api/posts?category=DAILY&limit=20' -o cache-second.json
(Get-FileHash cache-first.json).Hash -eq (Get-FileHash cache-second.json).Hash
```

## 任务 124 | 在变更提交后失效

### 从哪里开始

在 IDE 打开 [缓存服务](/level/33?guide=1#可以关闭的缓存服务)。同时找 [审核隐藏的事务](/level/26?task=99) 和 [撤销事务](/level/28?task=106)，这是它的两个写入入口。

### 操作步骤

1. 在发布、编辑、删除、隐藏与撤销的现有事务中，确定状态成功改变后调用 `publisher.publishEvent(new PublicPageCache.PostsChanged())`。不要在事务开始前发事件。
2. 在缓存服务中监听已成功提交的事件。先切换代号，再清理旧项，避免一条并行读在清理后又把旧结果塞回可见的键。

在完整文件的 `onPublicPostsChanged` 中可以看到这两个动作。

3. 用综合测试或两个浏览器窗口先缓存一页，再编辑其中一帖。下一请求取新正文。举报后隐藏它，列表、搜索、详情、评论应按第 28 关统一隐藏。撤销后恢复可见，再删帖，公开入口保持不可用。
4. 若事件没触发，检查目前执行路径是否由 Spring 管理并开启了事务。外部方法调用事务服务有效，在同一个对象中绕过代理调用自己的事务方法可能不生效。回滚一笔写入也不应让另一个请求看到本次未提交的值。

**提交内容**

为五个写入动作各写缓存前后的 HTTP 结果。

## 任务 163 | 模拟缓存不可用或失效失败

### 从哪里开始

只在本机测试类中模拟缓存问题。先让 [命中验证](/level/33?task=123) 正常通过，确认数据库路径本来可用，再针对缓存动作抛错。

### 操作步骤

1. 在 `server/src/test/java/edu/campus/treehole/PublicPageCacheTest.java` 保存下面的测试。它用同包测试从外部替换内存缓存，原服务方法和数据库查询入口不变。starter-test 提供 Mockito 及 Spring 的测试工具。

```java
package edu.campus.treehole;

import com.github.benmanes.caffeine.cache.Cache;
import java.util.List;
import org.junit.jupiter.api.Test;
import org.springframework.test.util.ReflectionTestUtils;

import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.mockito.ArgumentMatchers.any;
import static org.mockito.Mockito.*;

class PublicPageCacheTest {
    @Test
    void aBrokenCacheStillUsesTheOriginalQuery() {
        PublicPageCache service = new PublicPageCache(true);
        Cache<?, ?> broken = mock(Cache.class);
        ReflectionTestUtils.setField(service, "pages", broken);
        when(broken.getIfPresent(any())).thenThrow(new IllegalStateException("cache drill"));
        var fromDb = new PostPages.Page<>(List.of("42"), null);
        var result = service.read("DAILY", 20, null, "", () -> fromDb,
            text -> text, ids -> { throw new AssertionError("没有候选，不应使用批量回源"); });
        assertEquals(fromDb, result);
    }
}
```

进入 `server/` 运行对应命令。

```powershell
.\mvnw.cmd '-Dtest=PublicPageCacheTest' test
```

:::

:::mac linux

```bash

```

:::

应是一项通过，日志记录固定错误类别。没加载到测试时，先查类名和目录。数据库真的失败时仍走原来的错误响应。
2. 再暖缓存，提交隐藏动作。测试替身令 `invalidateAll()` 抛错。事件处理器捕获这类缓存异常，只记内部错误类别。由于 generation 已递增，新请求使用新键。另加一条测试直接给批量回源函数旧 ID，验证 `VISIBLE` 检查仍有效。
3. 用 `false` 重启一次运行环境，依次打开公开列表及失败前的旧地址。若两个路径中的任何一个还泄漏隐藏内容，保持缓存关闭，修复后重测。

**提交内容**

缓存读取失败、清理失败、明确关闭三组结果。
