### 按时间、话题和关键词找帖的示例

先看看要做的效果。在原页面找到一条有「自习」的标题，记下它的话题。这关完成后，输入「自习」就能找到这条帖子，清空输入框又能看到整份列表。

先把搜索和话题控件放在帖子列表上方。依据第 2 关相同写法，将 `label` 连到两个输入框。再加一个排序选项、清除按钮和导入导出。把下面代码放在 `id="post-list"` 的上方。

```html
<label for="search-posts">搜索标题或正文</label>
<input id="search-posts" type="search">
<label for="filter-category">话题</label>
<select id="filter-category">
  <option value="">全部</option>
  <option value="DAILY">校园日常</option>
  <option value="QUESTION">校园提问</option>
  <option value="HELP">互助求助</option>
</select>
<label for="sort-posts">排序</label>
<select id="sort-posts">
  <option value="newest">最新优先</option>
  <option value="oldest">最早优先</option>
</select>
<button id="clear-filter" type="button">清除筛选</button>
<button id="export-treehole" type="button">导出练习数据</button>
<label for="import-treehole">导入练习数据</label>
<input id="import-treehole" type="file" accept=".json,application/json">
```

把 `renderPosts` 的第一行改为 `function renderPosts(posts = getVisiblePosts()) {`，把原空状态文字改为「没有符合条件的帖子，可以清除筛选」。在脚本末尾加如下代码。函数声明提前可调用，渲染首页时会自动使用新的排序与筛选。

```js
function getVisiblePosts() {
  const keyword = $("#search-posts").value.trim().toLocaleLowerCase();
  const category = $("#filter-category").value;
  const direction = $("#sort-posts").value === "oldest" ? 1 : -1;
  return state.posts
    .filter((post) => (!category || post.category === category) &&
      (post.title + " " + post.body).toLocaleLowerCase().includes(keyword))
    .sort((a, b) => direction * (Date.parse(a.createdAt) - Date.parse(b.createdAt) ||
      a.id.localeCompare(b.id)));
}

for (const selector of ["#search-posts", "#filter-category", "#sort-posts"]) {
  $(selector).addEventListener("input", () => renderPosts());
}
$("#clear-filter").addEventListener("click", () => {
  $("#search-posts").value = "";
  $("#filter-category").value = "";
  $("#sort-posts").value = "newest";
  renderPosts();
});

$("#export-treehole").addEventListener("click", () => {
  const file = new Blob([JSON.stringify({ version: 2, ...state }, null, 2)], { type: "application/json" });
  const url = URL.createObjectURL(file);
  const link = document.createElement("a");
  link.href = url;
  link.download = "treehole-sample.json";
  link.click();
  setTimeout(() => URL.revokeObjectURL(url), 1000);
});

$("#import-treehole").addEventListener("change", async (event) => {
  const input = event.target;
  const [file] = input.files;
  if (!file) return;
  try {
    const data = normalizeData(JSON.parse(await file.text()));
    if (!window.confirm(`用 ${data.posts.length} 条练习帖覆盖此浏览器的数据？`)) return;
    state.posts = data.posts;
    state.draft = data.draft;
    editingPostId = null;
    $("#detail-back").click();
    fillPostForm(state.draft);
    $("#clear-filter").click();
    saveData();
    $("#feedback").textContent = "已导入练习数据。";
  } catch {
    $("#feedback").textContent = "导入失败。请检查格式和版本，原数据仍在。";
  } finally {
    input.value = "";
  }
});
```

手动检查「标题命中」「正文命中」「不存在」「话题和文字交叉」四种情况。导出前只放虚构的帖子与回帖。检验导入前可将原数据另导出一份。遇到初次渲染报错，确认所有新增元素已保存到 HTML，并且第 9 关的 `normalizeData` 在同一脚本中。

## 任务 36 | 整理新帖和编辑时间

前置：[统计话题与回帖](/level/9?task=35)。

### 操作步骤

1. 打开固定本地地址，发一条题为「时间核验」的合成帖。到 Application 的 Local Storage 找 `campus-treehole:v1`。记下该帖 id 与 `createdAt`。
2. 回到帖的详情点编辑，改正文再保存。在存储中找同 id 的记录并比较创建时间。
3. 原时间改变时，在 `publishPost` 检查编辑分支是否只在新建对象时设置 `createdAt`，更新时使用现有对象。

### 预期结果

编辑后只改内容，创建时间仍是原值。

### 提交

交同一个 ID 的两次字段结果。

## 任务 37 | 为帖子提供先后阅读方式

前置：[整理新帖和编辑时间](/level/10?task=36)。[查看筛选控件和排序脚本](/level/10?guide=1)。

### 操作步骤

1. 复制搜索示例的工具栏 HTML 到 `post-list` 紧前方，再追加脚本，并改好 `renderPosts` 的默认参数。在浏览器刷新，分别选「最新优先」和「最早优先」。比较第一张卡的时间。
2. 若要模拟相同时间，先导出合成数据备份。在 Application 把两条示例帖的 `createdAt` 改成同一字符串并刷新。多次选择排序核对两条仍有固定先后。
3. 顺序忽快忽慢时，核对 `sort` 先比较日期再比较 id 的表达式。还原刚才更改的练习时间。

### 预期结果

新旧排序能切换，相同时间仍有固定顺序。

### 提交

交按早晚排序的两份结果。

## 任务 157 | 导入和导出本地树洞

前置：[搜索标题与正文](/level/10?task=39)。

### 操作步骤

1. 先准备只有虚构内容的练习帖、回复和草稿。点「导出练习数据」。在浏览器下载列表或「下载」文件夹找到 `treehole-sample.json`，用编辑器打开核对 `version`、帖数和评论。
2. 打开另一浏览器的普通配置，用同一个网页地址加载。点导入旁的「选择文件」，选刚才保存的 JSON，核对确认窗的条数后同意。刷新检查已恢复的帖子、回复和草稿。
3. 将备份复制成 `broken-treehole.json`，打开副本，在最后多加一个逗号并保存。回网页导入坏文件，应看到提示，列表和原草稿仍在。最终保留原完好备份。

### 预期结果

正常文件恢复帖子、评论和草稿，错误文件不覆盖现有数据。

### 提交

交恢复条数、一次重新打开，以及一次失败后的结果。
