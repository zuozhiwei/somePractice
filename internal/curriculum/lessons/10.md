# 在完整数据上建立可筛选、可还原的视图
用已有看板准备三条记录，其中两条标题都含「复习」，一条已完成。数组中每项增加两个字段：`id` 用于找到原记录，`createdAt` 用于比较创建先后。在本机 HTTP 的 localhost 或 127.0.0.1 来源上可以用 `crypto.randomUUID()` 生成 id。新建记录使用 `new Date().toISOString()` 存时间，显示时再转本地格式。旧存档若缺少 id 或时间，在加载时补齐并保存一次；没有记录过的真实创建时刻无法还原，可把旧记录按原顺序保留且显示「时间未知」。

在 `script.js` 的渲染部分分清「所有数据」与「当前可见数据」。以下函数返回一个新的展示数组；对它排序、切片后，行按钮仍应按 id 定位原数据。

```js
function visibleTasks(all, mode, word, oldestFirst) {
  const needle = word.trim().toLowerCase();
  const result = all.filter(task => {
    const matchesStatus = mode === "all" || (mode === "done" ? task.done : !task.done);
    return matchesStatus && task.text.toLowerCase().includes(needle);
  });
  const time = task => Date.parse(task.createdAt || "") || 0;
  return result.sort((a, b) => oldestFirst ? time(a) - time(b) : time(b) - time(a));
}
```

渲染时调用 `visibleTasks(tasks, mode, word, oldestFirst)`，全局统计仍从 `tasks` 计算。如果只显示 B、D 两条时，点 D 却删掉原数组第二条，用 `tasks.findIndex(t => t.id === row.id)` 换掉视图下标。用这个反例自行验证编辑与删除。

完成导入导出后，清空前先导出，恢复后复核同一组标题、id 和完成标记。这样你就有能带走的第一份用户数据备份。

## 任务 157 | 数据导出与导入
点击导出时用 `new Blob([JSON.stringify(tasks, null, 2)], {type:"application/json"})` 建下载文件，生成对象 URL，赋给链接的 href，设置 download 后点击；下载触发后释放该 URL。用文件输入框选择 JSON，读取 `await file.text()`，先解析，再验证是数组、每行有非空文本且状态有效。校验通过且用户确认覆盖后才整体替换并保存。提交「导出→清空→导入」的数量与状态对照，再用损坏文件验证有提示且原数据仍在。
