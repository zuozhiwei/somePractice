# 每次改动都验证发布边界

之前用不同浏览器验了权限和分享。现在挑四个最容易被改坏的点做成自动检查。**CI** 是每次提交或发起合并时由另一台干净机器重复跑的检查。它读取表结构与虚构数据，测试后丢弃环境，不连接试运行站点。

**开始前**

本机先建 `campus_treehole_test`。给能建表的测试账号仅授权这个库。按 README 对空测试库应用编号迁移。从本关开始，确认脚本中没有 `USE campus_treehole` 或写真实库名的语句，库名由 `mysql --database=...` 指定。

### 可放进项目的发布边界测试

将下方文件保存为 `server/src/test/java/edu/campus/treehole/ReleaseBoundaryTest.java`。用实际的 Java 包名和原接口，示例沿用第 28 关的隐藏和撤销。MockMvc 在测试中调用真实 Controller、安全规则及数据库，但不在电脑上打开新端口。每个测试使用事务回滚，先用 `SELECT DATABASE()` 确认在专门的测试库才插数据。

```java
package edu.campus.treehole;

import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.AutoConfigureMockMvc;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.http.MediaType;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.test.web.servlet.MockMvc;
import org.springframework.transaction.annotation.Transactional;

import static org.hamcrest.Matchers.containsString;
import static org.hamcrest.Matchers.not;
import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.springframework.security.test.web.servlet.request.SecurityMockMvcRequestPostProcessors.csrf;
import static org.springframework.security.test.web.servlet.request.SecurityMockMvcRequestPostProcessors.user;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.*;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.*;

@SpringBootTest(properties = "treehole.replies.enabled=false")
@AutoConfigureMockMvc
@Transactional
class ReleaseBoundaryTest {
    @Autowired MockMvc mvc;
    @Autowired JdbcTemplate jdbc;
    @Autowired PasswordEncoder passwords;

    private long visiblePost;
    private long hiddenPost;
    private long reporter;

    @BeforeEach
    void prepare() {
        assertEquals("campus_treehole_test", jdbc.queryForObject("SELECT DATABASE()", String.class));
        String hash = passwords.encode("only-local-fixture");
        long owner = addUser("qa_owner", hash, "MEMBER");
        reporter = addUser("qa_other", hash, "MEMBER");
        addUser("qa_moderator", hash, "MODERATOR");
        visiblePost = addPost("QA-visible-title", owner, "VISIBLE");
        hiddenPost = addPost("QA-hidden-title", owner, "HIDDEN");
        jdbc.update("""
            INSERT INTO comments(post_id,body,created_at,owner_id)
            VALUES (?,?,UTC_TIMESTAMP(6),?)
            """, visiblePost, "QA-only-in-owner-inbox", reporter);
    }

    private long addUser(String name, String hash, String role) {
        jdbc.update("""
            INSERT INTO users(username,password_hash,role,created_at)
            VALUES (?,?,?,UTC_TIMESTAMP(6))
            """, name, hash, role);
        return jdbc.queryForObject("SELECT id FROM users WHERE username=?", Long.class, name);
    }

    private long addPost(String title, long owner, String status) {
        jdbc.update("""
            INSERT INTO posts(title,body,category,created_at,owner_id,status)
            VALUES (?,?,'DAILY',UTC_TIMESTAMP(6),?,?)
            """, title, "合成内容", owner, status);
        return jdbc.queryForObject("SELECT id FROM posts WHERE title=? AND owner_id=?",
                Long.class, title, owner);
    }

    @Test
    void publicReaderSeesOnlyVisiblePost() throws Exception {
        mvc.perform(get("/api/posts/{id}", visiblePost)).andExpect(status().isOk());
        mvc.perform(get("/api/posts/{id}", hiddenPost)).andExpect(status().isNotFound())
           .andExpect(content().string(not(containsString("QA-hidden-title"))));
    }

    @Test
    void onlyOwnerSeesPrivateReply() throws Exception {
        mvc.perform(get("/api/me/replies").with(user("qa_owner").roles("MEMBER")))
           .andExpect(status().isOk())
           .andExpect(content().string(containsString("QA-only-in-owner-inbox")));
        mvc.perform(get("/api/me/replies").with(user("qa_other").roles("MEMBER")))
           .andExpect(status().isOk())
           .andExpect(content().string(not(containsString("QA-only-in-owner-inbox"))));
        mvc.perform(get("/api/me/replies")).andExpect(status().isUnauthorized());
    }

    @Test
    void authorDeletionCannotBeUndone() throws Exception {
        mvc.perform(post("/api/reports").with(user("qa_other").roles("MEMBER")).with(csrf())
                .contentType(MediaType.APPLICATION_JSON)
                .content("{\"postId\":" + visiblePost + ",\"reason\":\"SPAM\",\"note\":\"synthetic\"}"))
           .andExpect(status().isCreated());
        long reportId = jdbc.queryForObject(
            "SELECT id FROM reports WHERE post_id=? AND reporter_id=?", Long.class, visiblePost, reporter);
        mvc.perform(patch("/api/mod/reports/{id}", reportId)
                .with(user("qa_moderator").roles("MODERATOR")).with(csrf())
                .contentType(MediaType.APPLICATION_JSON)
                .content("{\"decision\":\"HIDE\",\"reason\":\"synthetic hide\"}"))
           .andExpect(status().isOk());
        mvc.perform(delete("/api/posts/{id}", visiblePost)
                .with(user("qa_owner").roles("MEMBER")).with(csrf()))
           .andExpect(status().isNoContent());
        mvc.perform(post("/api/mod/reports/{id}/undo", reportId)
                .with(user("qa_moderator").roles("MODERATOR")).with(csrf())
                .contentType(MediaType.APPLICATION_JSON)
                .content("{\"reason\":\"synthetic undo\"}"))
           .andExpect(status().isConflict());
        mvc.perform(get("/api/posts/{id}", visiblePost)).andExpect(status().isNotFound());
    }
}
```

如果你第 26 关的处理接口使用了其它既定状态码，先对照 [接口契约](/level/29?task=110) 再调整断言，不要为让测试变绿而放宽权限。测试中的三个用户名只存在于专用测试库。

## 任务 172 | 配置一次合并前自动检查

### 从哪里开始

先跑过 [同样的本地接口测试](/level/44?task=171)，再在原仓库根目录新建工作流文件。不要把试运行服务器的数据库地址或账号放进 CI。

### 操作步骤

以下以同学自己的 GitHub 仓库为例。学校平台可用等效 CI。建 `.github/workflows/check.yml`，每次尝试合并和推送主分支运行。示例口令只对应 CI 内的临时服务，不能换成实际站点口令。测试和打包不需要服务器 SSH 权限。

```yaml
name: Treehole checks
on:
  pull_request:
  push:
    branches: [main]
permissions:
  contents: read
jobs:
  verify:
    runs-on: ubuntu-24.04
    services:
      db:
        image: mysql:8.4
        env:
          MYSQL_ROOT_PASSWORD: only-ci-root
          MYSQL_DATABASE: campus_treehole_test
          MYSQL_USER: treehole_ci
          MYSQL_PASSWORD: only-ci-db
        ports:
          - 3306:3306
        options: >-
          --health-cmd="mysqladmin ping -h 127.0.0.1"
          --health-interval=5s --health-timeout=3s --health-retries=20
    env:
      SPRING_DATASOURCE_URL: jdbc:mysql://127.0.0.1:3306/campus_treehole_test
      SPRING_DATASOURCE_USERNAME: treehole_ci
      SPRING_DATASOURCE_PASSWORD: only-ci-db
      SPRING_JPA_HIBERNATE_DDL_AUTO: validate
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-java@v5
        with:
          distribution: temurin
          java-version: '17'
      - uses: actions/setup-node@v5
        with:
          node-version: '22'
      - name: Prepare isolated database
        run: |
          if ! command -v mysql >/dev/null; then
            sudo apt-get update
            sudo apt-get install -y default-mysql-client
          fi
          export MYSQL_PWD="$SPRING_DATASOURCE_PASSWORD"
          for attempt in {1..30}; do
            if mysql -h 127.0.0.1 -u treehole_ci campus_treehole_test -e 'SELECT 1'; then break; fi
            if [ "$attempt" = 30 ]; then exit 1; fi
            sleep 2
          done
          for migration in server/db/[0-9]*.sql; do
            case "$migration" in */02-sample.sql) continue ;; esac
            mysql -h 127.0.0.1 -u treehole_ci campus_treehole_test < "$migration"
          done
      - name: Test and package server
        working-directory: server
        run: bash mvnw --batch-mode verify
      - name: Build frontend
        working-directory: web
        run: |
          npm ci
          npm run build
```

自己的前端如固定了另一个受支持 Node 主版本，就在工作流用相同版本。在本机仓库根目录执行以下命令前，先用 `git remote -v` 确认 `origin` 指向你自己的课程仓库。测试文件已提交时，`git add` 它一次也安全。

```bash
git switch -c ci/treehole-checks
git add .github/workflows/check.yml server/src/test/java/edu/campus/treehole/ReleaseBoundaryTest.java server/pom.xml
git diff --cached --stat
git commit -m "Verify the treehole before release"
git push -u origin ci/treehole-checks
```

在 Git 仓库页面点 Pull requests → New pull request，base 选主分支，compare 选刚推的分支，创建检查用的合并请求，先不合并。因为这份工作流的 `push` 只匹配 main，练习分支未立合并请求前可能没有运行。在 Actions 点进 `Treehole checks` 展开 `verify` 中的具体步骤。若 Git 平台须先开启 Actions，按仓库的 Actions 页面提示启用；学校平台只要求本地 CI 时，在干净副本逐行执行同样的程序与测试库迁移并保存输出。若负责设置仓库，按平台界面可把 `verify` 设为合并前必过。［参考 [GitHub Actions 工作流语法](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax)］

**提交内容**

工作流文件、一次真实成功运行、失败时该看哪个步骤。

## 任务 173 | 演练失败、修复与复测

### 从哪里开始

从 [检查已经通过的分支](/level/44?task=172) 开始。在本机仓库执行下面步骤前记住当前分支和通过的提交号，便于演练后回去。

### 操作步骤

1. 本机新建只用于演练的分支 `git switch -c qa/check-failure`。将「隐藏帖子返回 404」测试里的期望临时改为 200，只改测试，不移除可见规则。
2. 保存后在本机仓库根目录运行下方命令。在从自己仓库打开的草稿合并请求中等状态检查。记下失败提交号、失败方法和「应有 200、实际 404」的测试输出。不发布、不合并这次提交。

```bash
git add server/src/test/java/edu/campus/treehole/ReleaseBoundaryTest.java
git commit -m "Drill a failing hidden-post assertion"
git rev-parse --short HEAD
git push -u origin qa/check-failure
```

3. 将期望改回 404，用第二个提交修正，再看 CI 通过。若失败来自数据库未启动而非断言，先让数据库步骤通过，再重试故障演练。合并前确认测试文件中的期望正确。
4. 已共享的练习分支可使用正常提交撤回改动，不用强推。把成功与失败是两个不同提交写清楚。

**提交内容**

失败和恢复各一份输出、它们的提交号、为何失败版本未进入发布。
