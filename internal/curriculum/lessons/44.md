# 让每次合并都证明「重要」不会被旧页面覆盖
接着第 43 关的接口约定，把变化拆成输入规则、数据库写入、HTTP 响应三层。在 `todo-server/src/main/java/com/example/todo/Priority.java` 写下实际会被接口调用的领域类型。新接口拿到字符串后调用 parse，只允许两个精确拼写；将抛出的无效输入明确转换为第 26 关的 HTTP 400。列表读取数据库旧行时单独将 NULL 映射为 NORMAL，不要把缺失的请求参数也当作普通。

```java
package com.example.todo;

public enum Priority {
    NORMAL, HIGH;

    public static Priority parse(String value) {
        if ("NORMAL".equals(value)) return NORMAL;
        if ("HIGH".equals(value)) return HIGH;
        throw new IllegalArgumentException("优先级只接受 NORMAL 或 HIGH");
    }
}
```

在 `todo-server/src/test/java/com/example/todo/PriorityTest.java` 建一个同包测试（pom 要有 test 范围的 spring-boot-starter-test）。在后端目录运行 `./mvnw -Dtest=PriorityTest test`，应显示两个测试通过；主动把 "HIGH" 那行返回值改成 NORMAL，再跑应有一项失败，修回后应恢复。

```java
package com.example.todo;

import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

class PriorityTest {
    @Test void acceptsBothValues() {
        assertEquals(Priority.HIGH, Priority.parse("HIGH"));
        assertEquals(Priority.NORMAL, Priority.parse("NORMAL"));
    }
    @Test void rejectsMissingAndUnknownValues() {
        assertThrows(IllegalArgumentException.class, () -> Priority.parse(null));
        assertThrows(IllegalArgumentException.class, () -> Priority.parse("urgent"));
    }
}
```

把第 43 关的条件更新写入同一事务，在**独立测试库**建带 priority 的表。可在第 45 关迁移之前先将该列放入测试用 schema。写 HTTP 集成测试：每轮创建独立的虚构账号与任务，用登录所得 token 先发一次正常 PATCH，再重复旧请求；断言 200、409 和最终 HIGH。用乙的练习账号再发一次，断言 403，数据库中的所有者和值保持原样。每轮种子用新名字，或在用例结束时只清理该用例创建的行。直接验证 SQL、接口、缓存后重读的结果，避免只测试辅助枚举。

把当前**完整的空表结构**保存为 `database/ci-schema.sql`，包括 user_account、task、归属外键和 priority；从空库导入后验一次。测试配置读取下例环境变量。已有 Maven Wrapper 和前端 package-lock.json 需要入库。使用 GitHub 类的仓库时，可以在 `.github/workflows/verify.yml` 配置示例；校园 GitLab/Jenkins 同样可在每个合并请求触发下方导表、Maven 和 npm 三步。校园自建运行器只需使用隔离的练习服务，无需购买云服务。

```yaml
name: verify-board
on: [pull_request, workflow_dispatch]
permissions:
  contents: read
jobs:
  verify:
    runs-on: ubuntu-latest
    services:
      db:
        image: mysql:8.4
        env:
          MYSQL_DATABASE: todo_db
          MYSQL_USER: ci
          MYSQL_PASSWORD: ci-ephemeral-only
          MYSQL_ROOT_PASSWORD: ci-admin-ephemeral-only
        ports: ["3306:3306"]
        options: >-
          --health-cmd="mysqladmin ping -h 127.0.0.1"
          --health-interval=5s --health-timeout=3s --health-retries=30
      redis:
        image: redis:7-alpine
        ports: ["6379:6379"]
    env:
      SPRING_PROFILES_ACTIVE: test
      SPRING_DATASOURCE_URL: jdbc:mysql://127.0.0.1:3306/todo_db
      DB_USER: ci
      DB_PASSWORD: ci-ephemeral-only
      SPRING_DATA_REDIS_HOST: 127.0.0.1
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '17'
          cache: maven
          cache-dependency-path: todo-server/pom.xml
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
      - name: 初始化本次任务的空库
        run: MYSQL_PWD="$DB_PASSWORD" mysql -h 127.0.0.1 -u "$DB_USER" todo_db < database/ci-schema.sql
      - name: 执行后端全部测试
        working-directory: todo-server
        run: JWT_SECRET="$(openssl rand -base64 32)" bash ./mvnw -B verify
      - name: 构建前端
        working-directory: todo-app
        run: |
          npm ci
          npm run build
```

已更换目录或 Node 主版本时按自己锁文件和开发环境调整。CI 中的数据库密码专供临时服务，任务结束即销毁；本机运行时同样连接自己新建的测试库。若本机绿灯而 CI 缺表，在日志中从导表步骤往后读；若前端找不到构建脚本，核对 package.json 的 scripts 和 working-directory。新开合并请求后再推一个提交，确认两次都产生对应提交号的记录。[GitHub Actions 的 Maven 构建示例](https://docs.github.com/en/actions/tutorials/build-and-test-code/java-with-maven)

## 任务 172 | 让每个合并请求自动验证

## 任务 173 | 用失败样例演练代码评审
