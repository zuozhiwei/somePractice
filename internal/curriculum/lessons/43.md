### 操作步骤

3. 用「给定—操作—预期」写成一句可验收的条件。例如「给定一篇可见帖，点击复制并在新无痕窗粘贴，页面直接展示这篇帖和返回列表按钮」。先用旧版跑一遍，让记录说清以前怎样失败或需要几步。

## 任务 169 | 确定公开帖子链接与错误状态

### 从哪里开始

在本机仓库打开 [现有 API 文档](/level/29?task=109) 和上一卡的反馈。先写状态和可公开字段，再开始改分享入口。

### 操作步骤

在已有接口文档中补一个小表。先明确数据合约再改界面。

| 场景 | 链接或结果 |
| --- | --- |
| 分享 | `https://你的实际域名/?post=数据库帖ID` |
| 公开可见 | 详情 API 200，仅公开 DTO 字段（例如 id、标题、分类、正文、时间） |

## 任务 170 | 实现并回测分享入口

### 从哪里开始

打开 `web/app.js` 中 [原来的详情显示代码](/level/17?task=65)，同时核对 [上张卡的分享合约](/level/43?task=169)。只在自己的试运行站验证这次改动。

### 操作步骤

1. 在 `web/` 原来的详情模块增加复制按钮，并给失败兜底准备 `<label>` 和只读输入框。下面只展示可复用函数。传入当前公开帖 ID、兜底输入框和可读的状态元素。状态元素可用 `role="status"`。

```js
function publicPostUrl(id) {
  if (!/^[1-9][0-9]*$/.test(String(id))) throw new Error('帖子不可用')
  const url = new URL('/', window.location.origin)
  url.searchParams.set('post', String(id))
  return url.href
}

async function copyPublicPost(id, field, status) {
  const url = publicPostUrl(id)
  try {
    await navigator.clipboard.writeText(url)
    status.textContent = '链接已复制'
  } catch {
    field.closest('label').hidden = false
    field.value = url
    field.focus()
    field.select()
    status.textContent = '请复制已选中的链接'
  }
}
```

2. 在页面启动时读 `new URL(location.href).searchParams.get('post')`。存在有效 ID 时使用原 `GET /api/posts/{id}` 详情方法渲染；无效或 404 显示不可用说明和返回列表按钮。502 或网络中断显示重试，和「帖子不可用」区分开。收到不可用结果时清空旧标题、正文与评论节点。
3. 从列表打开详情前，用 `history.replaceState` 为当前条目保留筛选和 `window.scrollY`，并用 `history.pushState` 进入详情地址。在 `popstate` 读取恢复。直接打开详情没有此前的列表条目，返回按钮让同域首页可用，别要求受邀同学用浏览器后退。
4. 请同伴复跑最初任务。再测两次：拒绝浏览器复制权限时手动复制可用；审核隐藏后在新无痕窗访问原链接不可用。若复制成功但打开首页，先看地址有没有 `post`，再看启动代码有没有在第一次渲染时读它。

**提交内容**

实际代码、一次同伴复测、两个边界验证，以及接受或继续修改的结论。
