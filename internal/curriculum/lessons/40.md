# 让一个入口同时提供网页和看板接口
浏览器里的 `localhost` 始终指浏览器所在的电脑。若前端 URL 写成 `http://localhost:8080`，同学的浏览器会向他自己的电脑要数据。用第 38 关的 Nginx 做统一入口：网页从本站下载，`/api/` 请求经同一站点转交练习后端。

在原 `server` 块中加入下面一段，保留静态资源和页面 fallback 的配置。你的后端控制器已经声明 `/api/tasks`，这里的代理目标不带 URI，原路径会保留。测试配置通过后，在 `~/todo-site` 用 `nginx -p "$PWD/" -c nginx.conf -s reload` 重新加载。[Nginx 的 proxy_pass 说明](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_pass)

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Real-IP $remote_addr;
}
```

在浏览器的 Network 里按一次登录。核对请求发给网页同一个主机和端口，路径为 `/api/auth/login`。前端统一请求工具可以用 baseURL `/api` 加 `/tasks`，或者直接请求 `/api/tasks`，挑一种，避免两个 api 叠在一起。状态码、JSON 的 `code/message/data` 和请求方法都要核对。

先从远端本机测试后端路径，再从 Nginx 测同一路径，最后从浏览器测试。502 优先看应用是否正常和 upstream 地址；如果返回 HTML 首页则检查 location 是否匹配；401 或项目定义的未登录响应说明请求已经抵达鉴权层。当前练习继续使用同一入口和测试数据，无需购买域名。
