# 交付隐私可验证的树洞版本

现在同一个仓库已有分页、可选缓存、可重试的站内回复和基本观测。本关产物是可以带到下一台机器的 **v0.6-observable**。先在开发库验收，再打版本标签。记录实际结果即可，耗时没有变好也可以如实说明。

## 任务 132 | 写一份可对照的性能复盘

### 从哪里开始

在本机把 [基线记录](/level/31?task=117) 和 [索引复测](/level/32?task=119) 打开并排。保留同样的数据和请求参数。若已经换了电脑，先在这台电脑重新测可比较的基线。

### 操作步骤

在仓库根目录建 `docs/performance/36-report.md`。用第 31 关同样的机器、数据量、预热 5 次与采样 30 次测这四组。数据 ID 改变时记下新 ID。只把匹配的请求放在同一比较行。

| 场景 | 对照 | 新实现 | 记录 |
| --- | --- | --- | --- |
| 列表首屏 | 相同 limit 下的未建立索引版本 | 建了索引的 20 条 | 字节数、median、p95 |
| 长楼后的 20 条 | 相同边界的 LIMIT/OFFSET | 双字段游标 | EXPLAIN 节点、扫描数、p95 |
| 热点列表 | 关闭缓存 | 20 秒内重复命中 | 命中量、批量回源次数、p95 |
| 旧全量路径 | 第 31 关整页数据 | 当前无 limit 路径 | 兼容响应和大小 |

在 MySQL 运行 `SHOW INDEX FROM posts;` 和 `SHOW TABLE STATUS LIKE 'posts';`。后者的 `Index_length` 是该表索引空间的近似总大小。若报告的是磁盘变化，需记是否重新建表，别把总大小误写成某个索引的大小。在小数据上抖动明显就重复三轮，保留范围。写出哪项有证据可以保留，哪项目前默认关闭。

**提交内容**

完整表格、复测命令、保留或关闭的一个具体理由。

## 任务 133 | 验收并发场景中的隐私边界

### 从哪里开始

在本机照 [三角色治理回归](/level/28?task=108) 准备窗口，再加一位无痕访客。打开性能版树洞，不使用正式数据库。

### 操作步骤

1. 在同一个应用准备四个窗口：访客无痕、楼主 A、成员 B、审核员 C。用明显的虚构标记 `QA-36-并发帖`，避免拿真实内容做测试。
2. A 发帖，B 回复。A 在 `/api/me/replies` 能见对应回复，B 与访客不应读到属于 A 的回复。保存虚构帖的公开详情地址。
3. 访客热读列表，B 提交举报，C 处理。C 收到处理成功响应之后，访客立即再发新请求，按列表、搜索、评论、详情逐一检查。之前已经显示的内容可能仍在旧页面；关闭旧窗口，用无痕窗口验证新请求不能获取被隐藏的正文。适当给已打开的详情设计刷新失败提示。
4. 从作者私有页检查状态，但网络响应不应展示举报人的身份。审核撤销后再用访客刷新。删除后再尝试走已验收的撤销路径并记录结果。
5. 核对本次相关的后台日志和指标。以 `X-Request-Id` 找日志，确认没有会话、正文或个人资料。将结果写为「身份 → 操作 → 应有结果 → 观察到的结果」。

若一条允许的路径也返回 403，先查角色和 CSRF 请求头。若隐藏后新请求还能读正文，从第 32、33 关的统一可见条件和缓存回源检查起。

**提交内容**

并发操作时序、所有新请求的状态、收件箱隔离和日志证据。

## 任务 134 | 为部署准备可观测版本

### 从哪里开始

先修完 [性能记录](/level/36?task=132) 与 [隐私回归](/level/36?task=133) 失败项。终端切到有 `web/` 与 `server/` 的原仓库根目录。这里打的标签会在下章构建使用。

### 操作步骤

在仓库根目录整理 `README.md`、`server/db/`、配置示例及本章报告。README 写明从空开发库开始的迁移顺序、运行 `web` 和 `server` 的命令、公开 `/api/health` 与本机管理口的区别。标记合成样本脚本只在性能库使用。将密码、Cookie jar、数据库备份、编译输出排除在 Git 外。

在仓库根目录运行 `git status --short`，看清待提交文件，再分别执行后端测试和前端构建。两项都通过后才提交。

:::windows

```powershell
Push-Location server
.\mvnw.cmd test
Pop-Location
Push-Location web
npm.cmd ci
npm.cmd run build
Pop-Location
```

:::

:::mac linux

```bash
(cd server && ./mvnw test)
(cd web && npm ci && npm run build)
```

:::

```bash
git add README.md server web scripts docs
git diff --cached --stat
git commit -m "Prepare the observable campus treehole release"
git tag -a v0.6-observable -m "Pagination, privacy tests and deployment checks"
git show --no-patch v0.6-observable
```

若上面没有需要提交的改动，可在已验收的提交上打标签。若标签已存在，先查看它指向哪个提交；新增复测版本需用新标签，不覆盖已发给别人的版本。明文密码或数据库文件意外进入暂存区时，先从暂存区移出并更新 `.gitignore`，复核再提交。

**提交内容**

标签与提交号、启动顺序、迁移列表和简短的性能报告。
