## 任务 115 | 生成可重置的树洞样本

### 从哪里开始

在本机 IDE 打开你打了 v0.5-governance 标签的仓库，另开 MySQL 管理终端。照 [准备树洞练习数据库](/level/14?task=50) 创建新的 campus_treehole_perf，并对它应用既有结构迁移。此卡从性能库开始，原开发库保持可用。

### 操作步骤

1. 用第 14 关的 MySQL 管理账号为本项目另建 `campus_treehole_perf`，按仓库 README 应用第 30 关以前的建表和结构增量（01、03、04、05、06）。跳过旧结构用的 02-sample.sql。每个迁移由命令参数选中练习库。给本机练习账户授权这个库。不要从正在使用的网站导出帖子和实名账号。
2. 用性能库配置启动已有 Spring 服务。通过原注册界面创建虚构用户 `bench-author`，用一个只在本机使用的密码。退出后在 MySQL 中运行 `SELECT id FROM users WHERE username='bench-author';`，应返回一行。后面只借用这个账号的数字 ID 满足外键要求。
3. 在 `server/db/fixtures/perf.sql` 写下这些语句。这里用编号作为固定生成种子。每次相同编号生成同样的标题和时刻。练习库中的 `[bench]` 前缀专门留给脚本。

```sql
START TRANSACTION;
SET @author = (SELECT id FROM users WHERE username = 'bench-author');
DELETE FROM comments
WHERE post_id IN (SELECT id FROM posts WHERE title LIKE '[bench]%');
DELETE FROM posts WHERE title LIKE '[bench]%';
SET SESSION cte_max_recursion_depth = 4000;

INSERT INTO posts (title, body, category, created_at, owner_id, status)
VALUES ('[bench] 练习长楼', '虚构内容', 'DAILY', '2026-01-01 08:00:00', @author, 'VISIBLE');
SET @long_post = LAST_INSERT_ID();

INSERT INTO posts (title, body, category, created_at, owner_id, status)
WITH RECURSIVE numbers(n) AS (
  SELECT 1 UNION ALL SELECT n + 1 FROM numbers WHERE n < 400
)
SELECT CONCAT('[bench] 帖子 ', n), CONCAT('虚构内容 ', n), ELT(MOD(n, 3) + 1, 'DAILY', 'QUESTION', 'HELP'),
       TIMESTAMPADD(SECOND, n DIV 2, '2026-01-02 08:00:00'), @author,
       IF(MOD(n, 20) = 0, 'HIDDEN', 'VISIBLE')
FROM numbers;

INSERT INTO comments (post_id, body, created_at, owner_id)
WITH RECURSIVE numbers(n) AS (
  SELECT 1 UNION ALL SELECT n + 1 FROM numbers WHERE n < 3000
)
SELECT @long_post, CONCAT('虚构回复 ', n),
       TIMESTAMPADD(SECOND, n DIV 2, '2026-01-03 08:00:00'), @author
FROM numbers;
COMMIT;

SELECT status, COUNT(*) FROM posts WHERE title LIKE '[bench]%' GROUP BY status;
SELECT p.id, COUNT(c.id) AS replies FROM posts p
JOIN comments c ON c.post_id = p.id WHERE p.title = '[bench] 练习长楼' GROUP BY p.id;
```

如果项目分类名不同，把 SQL 中的三种分类换成已有的公开分类。若帖子新增了无默认值的必填列，按 `SHOW CREATE TABLE posts\G` 补列。把所用平台的命令记录在项目 README。填写性能库账号后，从仓库根目录运行。脚本固定库名，并靠该账号的授权进一步隔离其他库。

## 任务 116 | 读懂一次长楼查询计划

### 从哪里开始

### 操作步骤

**EXPLAIN** 显示 MySQL 打算怎么查。带 `ANALYZE` 的版本会执行查询并报告实测，请在性能库使用。

1. 在代码里找到公开列表和评论查询，把立刻要用的排序、筛选和参数记下来。示例假设帖子最新在前，评论最早在前。把下面的 `42` 改成生成样本时打印的长楼 ID。
2. 打开连接性能库的 MySQL 交互窗口，运行两条语句。复制到 `docs/performance/31-baseline.md`，留做下一关对照。

```sql
EXPLAIN SELECT id, title, category, created_at FROM posts
WHERE status = 'VISIBLE' AND category = 'DAILY'
ORDER BY created_at DESC, id DESC LIMIT 20;

EXPLAIN SELECT id, body, created_at FROM comments
WHERE post_id = 42 ORDER BY created_at ASC, id ASC LIMIT 20 OFFSET 2500;
```

3. 从输出抄出 `key`（选中的索引）、`rows`（估计要检查的行数）、`type`（如何访问记录）和 `Extra`。例如 `Using filesort` 表示查询需要额外排序，不能据此断言已经写入磁盘。`OFFSET 2500` 表示跳过前 2500 条符合排序的记录。
4. 如果用的是 MySQL 8，重复其中一个查询，将 `EXPLAIN` 改为 `EXPLAIN ANALYZE`。记录实际行数和最慢的节点。仍可使用普通 `EXPLAIN` 完成任务。

## 任务 117 | 固定基线与复测方式

### 从哪里开始

先让本机的树洞后端指向 [本章的性能练习库](/level/31?task=115)。终端用 `curl -i http://localhost:8080/api/posts` 确认 200。然后回到包含 `web/` 和 `server/` 的根目录写测量脚本。

### 操作步骤

1. 在仓库根目录建 `scripts/measure-http.py`。需要 Python 3。工具会完整读取响应，测到的是客户端等待整个响应的时间。
2. 先跑下面的公开列表，再用长楼评论路径跑一次。若上一关没有分页参数，原样测试整个列表，并标记为「旧接口全部返回」。查询层的深页对照单独保留上一步的 `LIMIT/OFFSET`，别把全量响应当成分页的公平对照。

```python
import math
import statistics
import sys
import time
import urllib.request

url = sys.argv[1]
warmups, repeats = 5, 30
samples, byte_count = [], 0
for i in range(warmups + repeats):
    start = time.perf_counter()
    with urllib.request.urlopen(url, timeout=5) as response:
        assert response.status == 200, response.status
        byte_count = len(response.read())
    if i >= warmups:
        samples.append((time.perf_counter() - start) * 1000)
samples.sort()
p95 = samples[math.ceil(0.95 * len(samples)) - 1]
print(f"n={len(samples)} bytes={byte_count} median={statistics.median(samples):.1f}ms p95={p95:.1f}ms")
```

:::windows

```powershell
py -3 scripts/measure-http.py http://localhost:8080/api/posts
py -3 scripts/measure-http.py http://localhost:8080/api/posts/42/comments
```

:::

:::mac linux

```bash
python3 scripts/measure-http.py http://localhost:8080/api/posts
python3 scripts/measure-http.py http://localhost:8080/api/posts/42/comments
```

:::

把 `42` 换成自己的长楼 ID。

:::windows

若 `py -3` 不存在，运行 `python --version` 检查是否装了 Python 3；已安装时可将 `py -3` 换成 `python`。

:::

`median` 是样本中间位置的时间，`p95` 是 95% 样本不超过的时间。写明机器、JDK/MySQL 版本、样本规模、参数、缓存与预热方式。结束后写一条可验证的目标，例如「保持同样 20 条及同样的顺序，深页扫描量显著下降；隐藏帖仍查不到」。运行报 404 时先确认长楼 ID，报连接失败时还原第 30 关的启动命令和性能库变量。

**提交内容**

两项测量输出、可复跑的脚本、一条性能与可见性目标。
