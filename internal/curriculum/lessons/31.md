# 给同一条查询留一份可复查的基线

在自己电脑上新建独立练习库 `todo_bench`。本关只放虚构数据。保留前面开发库的结构和账号，测试表自带 user_id，用来模拟十位用户的任务。第一次执行下面脚本前确认 `SELECT DATABASE()` 返回 todo_bench；录入之后再次练习时复用同一批数据。

~~~sql
CREATE DATABASE IF NOT EXISTS todo_bench;
USE todo_bench;
CREATE TABLE bench_task (
  id BIGINT PRIMARY KEY AUTO_INCREMENT, user_id BIGINT NOT NULL,
  title VARCHAR(200) NOT NULL, done TINYINT NOT NULL
);
INSERT INTO bench_task(user_id,title,done)
WITH RECURSIVE digit(n) AS (SELECT 0 UNION ALL SELECT n+1 FROM digit WHERE n < 9)
SELECT 1+MOD(n,10), CONCAT('练习-',n), MOD(FLOOR(n/10),2)
FROM (SELECT a.n+10*b.n+100*c.n+1000*d.n+10000*e.n AS n
      FROM digit a CROSS JOIN digit b CROSS JOIN digit c
      CROSS JOIN digit d CROSS JOIN digit e) numbers;
SELECT COUNT(*), COUNT(DISTINCT user_id) FROM bench_task;
~~~

结果应为 100000 行、10 位模拟用户。研究的问题是“第 3 位用户最近添加的 20 条未完成任务”。保存 `SELECT id,title FROM bench_task WHERE user_id=3 AND done=0 ORDER BY id DESC LIMIT 20;`。复制一份，在开头加 `EXPLAIN`。关注 key、rows、Extra，其中 rows 是估计行数；想看实际行数可以在本地 MySQL 8.0.18+ 用 `EXPLAIN ANALYZE`，它会运行这个查询。 [MySQL 查询计划](https://dev.mysql.com/doc/refman/8.4/en/explain.html)
