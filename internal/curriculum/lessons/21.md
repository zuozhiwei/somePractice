# 让游客阅读、登录者发言

**授权**回答「已经确认身份的人能做什么」。注册、登录和退出是认证相关动作。匿名读帖子、登录才能写是授权规则。请求要先满足会话要求并通过写入校验，实际作者判断在下一关完成。此阶段公开的返回字段始终用第 16 关的两个 DTO。

### 保护写操作

在 `web/auth.js` 中保留 `signIn`，追加以下函数。`write` 是从任何已有表单发出有会话保护的写请求的公共入口。退出时清空内存中的登录状态与私有内容，未发布草稿仍按原先规则保留在这台设备。

```js
export async function write(path, method, data) {
  const csrf = await api('/auth/csrf')
  return api(path, {
    method, data,
    headers: { [csrf.headerName]: csrf.token }
  })
}

export async function signOut() {
  await write('/auth/logout', 'POST')
  await api('/auth/csrf')
  return api('/auth/me')
}
```

`401` 表示需要认证或会话过期，`403` 表示当前请求不能执行。用户不可重复提交时禁用按钮，finally 中恢复。表单填入匿名内容时，标题、正文和回复都用 `textContent` 写到页面，保留文字显示。

### 发布账号区

在 `web/index.html` 页头之后加下方账号区域，原 `post-form` 和 `comment-form` 保持在原处。

```html
<section id="account-panel" aria-labelledby="account-title">
  <h2 id="account-title">树洞账号</h2>
  <p id="account-status" role="status">正在检查登录状态…</p>
  <form id="account-form">
    <label for="account-username">用户名</label>
    <input id="account-username" required autocomplete="username" maxlength="24">
    <label for="account-password">密码</label>
    <input id="account-password" type="password" required autocomplete="current-password">
    <button type="submit" value="login">登录</button>
    <button type="submit" value="register">注册</button>
  </form>
  <button id="account-logout" type="button" hidden>退出</button>
  <p id="account-error" role="alert"></p>
</section>
```

在 `web/app.js` 的 import 区加入 `import { signIn, signOut, write } from './auth.js';`。找到第 17 关的 `function send`，用代码中的异步版本替换。其他代码加在原有事件绑定之后。这样原帖表单和回复表单仍使用第 17 关的写法，但写请求会统一带上 CSRF。按 Enter 默认走第一个按钮「登录」。

```js
let signedIn = false;
let accountEpoch = 0;

function renderAccount(value) {
  signedIn = value;
  accountEpoch++;
  $("#account-form").hidden = value;
  $("#account-logout").hidden = !value;
  $("#account-status").textContent = value ? "已登录，可匿名发言。" : "访客可以浏览帖子。";
  const inbox = $("#replies-panel");
  if (inbox) inbox.hidden = true;
  $("#reply-list")?.replaceChildren();
}

$("#account-form").addEventListener("submit", async (event) => {
  event.preventDefault();
  const form = event.currentTarget;
  const mode = event.submitter?.value || "login";
  const username = $("#account-username").value.trim();
  const password = $("#account-password").value;
  const buttons = form.querySelectorAll("button");
  buttons.forEach((button) => { button.disabled = true; });
  $("#account-error").textContent = "";
  try {
    if (mode === "register") {
      await write("/auth/register", "POST", { username, password });
      $("#account-status").textContent = "注册成功，请用同一用户名登录。";
    } else {
      const result = await signIn(username, password);
      renderAccount(result.signedIn);
      $("#account-logout").focus();
    }
    $("#account-password").value = "";
  } catch (error) {
    $("#account-error").textContent = error.message;
  } finally {
    buttons.forEach((button) => { button.disabled = false; });
  }
});

$("#account-logout").addEventListener("click", async () => {
  const button = $("#account-logout");
  button.disabled = true;
  try {
    await signOut();
    if (!editingPostId) {
      const draft = readPostForm();
      if (draft.title || draft.body) {
        state.draft = draft;
        saveData();
      }
    }
    renderAccount(false);
    $("#account-error").textContent = "";
    editingPostId = null;
    fillPostForm(state.draft);
    $("#account-username").focus();
  } catch (error) {
    $("#account-error").textContent = error.message;
  } finally {
    button.disabled = false;
  }
});

async function send(path, method, data) {
  try {
    return await write(path, method, data);
  } catch (error) {
    if (error.status === 401) {
      renderAccount(false);
      $("#account-username").focus();
      throw new Error("请先登录，再继续发表。当前输入仍在。");
    }
    throw error;
  }
}

api("/auth/me").then((state) => renderAccount(state.signedIn)).catch((error) => {
  $("#account-error").textContent = error.message;
});
```

刷新后先看「访客可以浏览帖子」。无痕窗口提交原发帖表单时焦点应移动到账号输入，正文保留。新建并登录一个合成账号，再点击同一发帖按钮，帖子才会创建。退出后确认公开帖子还可阅读。

## 任务 78 | 配置游客阅读和登录发言

### 操作步骤

从通过 [本机登录练习](/level/20?task=75) 的 `auth.js` 开始。本关把账号入口放回自己原来有 `post-form` 的首页。

1. 在 `web/auth.js` 保留第 20 关的 `signIn`，按 [本关参考资料「保护写操作」](/level/21?guide=1#保护写操作) 追加 `write` 和 `signOut`。再按 [发布账号区](/level/21?guide=1#发布账号区) 修改自己的 `web/index.html`、`web/app.js`。不要让第 20 关练习页替代首页，完成后可以在本地删掉 `dev-auth.html`。
2. 从 Vite 首页打开已有帖子并查看评论。再用无痕窗口执行同样阅读，记录这三条 GET 的状态。
3. 在首页注册一个虚构账号。注册成功后再点「登录」，输入原来写在帖子框的测试文字，提交一条新帖和一条评论。

### 验收与排查

两个窗口都能读相同公开内容，只有登录窗口产生帖子与回复。如果改完之后点击无效，打开 Console 检查是否还保留了两个 `send` 函数或找不到 `#account-form`。

### 提交

## 任务 79 | 保护树洞变更请求

### 操作步骤

用 [账号入口接线](/level/21?task=78) 后的 Vite 首页，本地复现三条写入请求。

1. 在访客窗口从同源首页写一条「权限验证帖」再点发送。正常的 `send` 会从 `write` 取 CSRF。观察返回 401、焦点到登录且输入保留。
2. 再用 [第 20 关的缺少令牌验证方式](/level/20?task=77)。登录后若要检查帖子写入口，可在 `web/app.js` 末尾临时增加以下一次性测试。这个请求只在本机课件记录下 HTTP 状态，完成后移除。

```js
api('/posts', {
  method: 'POST',
  data: { title: '本机令牌测试', body: '合成测试', category: 'DAILY' }
}).then(() => console.log('请检查写入保护'))
  .catch(error => console.log('没有请求令牌，HTTP', error.status))
```

3. 刷新一次应记录 403，移除临时代码，再用原表单发送练习帖，网络页应显示 201。

### 验收与排查

401 没有身份且有请求令牌，403 是登录但缺少令牌，201 是两项俱全。若都 403，先查请求标题中的实际令牌字段，而不是关掉服务端检查。

## 任务 80 | 处理退出与过期状态

### 操作步骤

在 [发布账号区](/level/21?guide=1#发布账号区) 找 `#account-logout` 事件和 `renderAccount`。用两个场景分别核验主动退出和会话失效。

1. 把顶部退出按钮接到 `signOut`。成功后立即设置 `signedIn=false`，移除个人内容，把焦点移回登录入口。列表维持可读取。
2. 在编辑框输入一条草稿后退出，刷新公开列表。再点发送，应提示登录且草稿仍在。登录后由你再次确认发送。
3. 若处理会话过期分支，可以登录后用开发者工具「应用/存储 → Cookies」删除自己本地窗口的 `JSESSIONID`，再点发送。预期返回 401 后跳至登录，保留当前表单。网络失败应提示重试。

### 验收与排查

普通阅读继续，私有状态被清空。未发布的新草稿保留。若退出后正文为空，检查 logout 监听里是否先把 `readPostForm()` 的结果放入 `state.draft` 再重绘。

### 提交

退出前后状态、读写结果与恢复前表单内容。

## 任务 81 | 检查公开数据字段

### 操作步骤

以 [第 16 关公开视图](/level/16?guide=1#扩充帖子控制器) 的 `PostView` 和 `CommentView` 为准核对字段。使用同一 ID 的访客与成员请求。

1. 在无痕窗口逐一打开三个公开 GET。浏览器「网络 → 响应」中把一条帖子与一条合成回复的字段名抄到 `docs/api-check.md`。
2. 检查 `PostController.PostView` 五项与 `CommentView` 三项，查看控制器返回语句引用哪个 DTO。若响应出现整份实体，先把结果转换成 `view/commentView` 对象再返回。
3. 页面用「匿名同学」显示作者位置。登录者读取公开详情时得到相同字段。比较访客和成员各一份 JSON，遮住任何不应进入作业的个人内容。

### 验收与排查

帖子是 `id/title/body/category/createdAt`，评论是 `id/body/createdAt`。若 API 出现用户表字段，将返回实体的地方换回对应的视图 DTO，不靠浏览器把字段藏起来。

### 提交
