# 在请求进入任务控制器前核验身份

第 20 关能签发 token。本关用同一个 TokenService、密钥、算法和签发者建立入口校验。练习范围是自己编写的待办 API。访问主页、登录和注册不需要身份，所有 /api/tasks 及其子路径都要先验证凭证。

1. 在 TokenService 增加方法，从经过签名校验的 payload 读用户 id。要求 issuer 为 todo-server，使用签名的 claims 格式并检查过期时间存在。JJWT 在解析时会拒绝已过期的凭证。读取 subject 后转换成正的 long。

~~~java
public long verifiedUserId(String token) {
    var claims = Jwts.parser().verifyWith(key).requireIssuer("todo-server")
        .build().parseSignedClaims(token).getPayload();
    if (claims.getExpiration() == null) throw new IllegalArgumentException("缺少有效期");
    long id = Long.parseLong(claims.getSubject());
    if (id <= 0) throw new IllegalArgumentException("无效用户");
    return id;
}
~~~

2. 在 `security/TaskAuthFilter.java` 继承 `OncePerRequestFilter`，声明 `@Component` 并构造器注入 TokenService。实现 `shouldNotFilter`，根据 `request.getServletPath()` 只对恰为 /api/tasks 或以 /api/tasks/ 开头的路径做检查。使用 `jakarta.servlet` 的类型。读取 Authorization 头，要求 `Bearer ` 前缀和非空内容。解析成功后 `request.setAttribute("currentUserId", id)`，最后一次调用 `chain.doFilter(request,response)`。
3. 头缺失或解析抛出 `JwtException`、`IllegalArgumentException` 时，立即返回 401 和 JSON 消息，结束该分支。只在解析部分捕获这些异常，控制器自己的异常仍由框架处理。用 `@RequestAttribute("currentUserId") long currentUserId` 接收可信 id，将其传给创建任务的服务。下一关会把它写入外键列。
4. 在 Postman 中设置本地环境变量 token，在 Authorization 选择 Bearer Token 并引用 `{{token}}`。先去掉头验证拒绝，再正常登录并重新请求。若正确登录后仍是 401，检查 Bearer 后有且只有一个空格、两个服务共用相同配置、系统时间一致。

## 任务 80 | 处理无效与过期 token

给过滤器写负例，用普通无效字符串代替凭证，预期 401；用测试配置签发有效期一秒的本地样本，在它过期后再请求，也应 401。再用另一个测试实例不同密钥签发的正常样本验证校验器拒绝不同签名。交三条状态与随后正常登录成功的记录，敏感值用占位符替代。
