# 让同学从空目录启动你的全栈看板

准备一个新的测试目录和自己的练习数据库。把第 17 关能运行的前后端放入 `task-board/todo-app` 和 `task-board/todo-server`。创建 `database/` 放建库表脚本，`README.md` 记录运行顺序，`docs/verification.md` 记录验收证据。源码里所有 DB 密码继续从环境变量读取。

1. 为一次点击写下完整的调用链，例如 `新增按钮 → createTask → POST /api/tasks → TaskController → TaskService → TaskRepository → MySQL task`。如果上一关控制器直接调用仓库，现在把创建、查询、更新、删除移入 `@Service`，由控制器负责 HTTP 参数和响应。构造器注入便于下一关单独测试。
2. 把环境条件写成能实际执行的步骤：Java 17、可用的 MySQL、项目要求的 Node 版本；导入 `database/schema.sql`；设置 DB_USER/DB_PASSWORD；在后端根目录运行 `./mvnw spring-boot:run`；在前端目录运行 `npm ci`（首次没有锁文件先 npm install）及 `npm run dev`。注明两个进程分别在哪个终端、哪个地址访问。
3. 在页面依次新建「验收 01」至「验收 05」，勾选其中两项。按 id 查询并记下五行的标题与状态。关闭前后端，重新启动相同数据库和这两个服务，在新的浏览器窗口复核同样五行。若任务消失，检查 JDBC 的库名、Hibernate 建表策略和接口是否仍使用内存集合。
4. 从新的目录独立按 README 运行一次。压缩包包含源码、POM、Maven Wrapper、前端锁文件、SQL 和文档，排除 target、node_modules、环境文件及个人账号信息。

## 任务 67 | 项目结构梳理

在 README 放简明目录树，给 controller、service、repository、entity 各选一个实际类名说明职责；在前端标出入口、渲染和请求封装文件。交目录树和自己项目的新增任务数据流图，让同学从一次点击能定位到具体源码。

## 任务 68 | 数据库持久化验证

分别保存重启前后五行的 id、title、done，以及数据库客户端对这些行的查询画面。提交两次观察和结论，指出为什么仅看到相同标题还不足以确认打开的是同一批记录。

## 任务 69 | 提交前后端分离作品

上传源码压缩包或教师可读取的仓库地址，附 SQL、启动文档和调试演示。提交时写清「从空库到打开任务列表」的操作及实际耗时；检查另一台设备或新的目录能访问交付内容，配置示例中只出现变量名。
