# 交付共享树洞

现在可以交一份同学可在自己的电脑打开的树洞。**可复现**表示同学只用仓库与说明就能达到同一个结果。把演示内容写进 SQL 脚本，运行用的数据库密码通过环境变量传入。此阶段的写接口仍是本地练习功能，后端继续绑定本机 127.0.0.1。

### 项目结点

```text
campus-treehole/
├── README.md
├── docs/api-check.md
├── web/
│   ├── index.html
│   ├── api.js
│   ├── package.json
│   ├── package-lock.json
│   └── vite.config.mjs
└── server/
    ├── db/01-treehole.sql
    ├── db/02-sample.sql
    ├── pom.xml
    ├── mvnw
    ├── mvnw.cmd
    └── src/
```

README 按「安装 JDK、MySQL、Node → 创建数据库 → 导入脚本 → 设置环境变量 → 分开两终端运行 → 验收」的顺序写。`npm ci` 用锁文件安装与仓库相同的项。若你还没有开始用 Git，可先交标记为 v0.3 的代码压缩包。Git 分支和标签的完整操作在第 27 关。

## 任务 67 | 整理同一份树洞项目

### 操作步骤

打开 [项目结点示意](/level/18?guide=1#项目结点)。把 [本地库和建表](/level/14?task=51)、[后端数据源](/level/15?task=54) 与 [Vite代理](/level/17?task=63) 三个已经验证的步骤整理在同一 README。

1. 在 VS Code 项目目录核对上面每个路径。新增 `docs/run-local.md` 或扩充 README。为新同学列端口 3306、8080、5173，标明每个端口对应的进程。
2. 从干净的练习目录核对后端三项环境变量、数据库脚本执行顺序和前端 `npm ci`、`npm run dev`。如果数据库文件已有真实练习数据，可以在另一个专用 MySQL 开发库试跑，执行脚本前在 MySQL 客户端选择这个库，并修改后端 JDBC URL。
3. 检查准备交付的目录，移除 `node_modules/`、`target/`、数据库导出、私人凭据和 Cookie 文件。保留锁文件、Wrappers、SQL 与源码。

### 验收与排查

一位首次接手的人根据文档能分别开 Java 和 Vite。若同伴默认在 `web` 执行 Java 命令，在说明里为每段加「从仓库根目录打开第几个终端」。

### 提交

目录树及文档中的两终端启动命令。

## 任务 68 | 验证服务重启保留回复

### 操作步骤

使用 [同一网页写入数据库](/level/17?task=66) 的操作。先在两台浏览器打开同一个 `http://localhost:5173`，新帖标题可写「停服务复查」，回复写「记住这条」。

1. 从 `http://localhost:5173/` 新建一条合成帖并评论。记下帖子和评论 ID。另开窗口请求详情及评论。
2. 在后端终端按 Ctrl+C，确认前端收到暂时无法访问的提示。保持 MySQL 运行。再在设过环境变量的终端用 Wrapper 启动。
3. 刷新两窗口，ID、标题和评论应一致。若记录消失，在新的终端核对 `SPRING_DATASOURCE_URL`，用 MySQL 在那个库里按 ID 查询，并确认 `ddl-auto` 为 `validate`。

### 验收与排查

Java 重启后原 ID 保留。若只记得标题，打开「网络」点对应详情或评论，记录 URL 中的 ID。仍读不到时确认起的是第 15 关接库版本，没启动早期 Java 固定响应。

### 提交

重启两端的同一 ID 及一次失败提示。

## 任务 69 | 提交共享树洞版本

### 操作步骤

完成 [整理运行目录](/level/18?task=67) 和 [重启留存记录](/level/18?task=68) 后交接。分享一份明确叫 v0.3 的源码和合成 SQL。

1. 把当前版本交给一位同学，在他电脑的新目录按 README 从空库启动。如果当前可用 Git，记录提交号和 v0.3 标签。也可以分享命名为 `campus-treehole-v0.3.zip` 的源码包。
2. 请同学创建一条虚构帖子并回复。只记录设备、目录、实际命令、看到结果的时间和一处卡点。
3. 根据卡点改一次说明，让对方只看更新后的一段再走一次。典型问题是运行命令处于错误的目录，或在没有环境变量的新终端运行后端。

### 验收与排查

同伴应在他自己的环境创建新 ID，并能刷新看到回复。若只有你自己的截图，交接还没复现，请对方至少回传启动失败或成功的实际结果后补写 README。

### 提交

版本与复现结果，以及实际修订的那段文档。
