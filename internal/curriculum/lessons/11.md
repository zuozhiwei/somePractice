# 打磨匿名发帖体验

### 开始前

本关按同学实际的使用路线验收本地树洞。先备份合成数据，再小步整理代码、试窄屏和键盘、恢复练习数据。 [上一步](/level/10?task=157)

### 窄屏、键盘和读取错误的参考

这关先复用已有代码，别同时更换框架。先导出练习数据，再按实际功能查四种状态。

1. 折叠或搜索 `renderPosts`、`showPost`、`publishPost`、`loadData` 与 `saveData`。按「显示、写入、存储」给有关函数加一行短注释。调整顺序时保留初始化和事件绑定位置，分一次小改动就保存刷新一次。
2. 在 `detail-title` 的 HTML 上加 `tabindex="-1"`，在 `showPost` 的结尾加 `$("#detail-title").focus();`。在 `feed-title` 上也加相同属性，点击返回时把焦点放回 `feed-title`。这让用键盘的同学知道新内容打开在哪里。
3. 用浏览器设备预览切换 360px，再打开长标题和多行正文检查。想让正文换行如实显示，可将 `#detail-body { white-space: pre-wrap; overflow-wrap: anywhere; }` 加入样式。用 Tab、Shift+Tab、Enter 走一遍列表、详情、回复、返回。
4. 在 Application 中先备份当前存储值，再用一份测试副本触发损坏 JSON，例如只留一个左大括号。刷新应显示示例和错误说明。把原值贴回来，刷新后应该恢复。不要修改其他键。

最后在 README 的打开方式补固定本地地址和启动命令。写清哪些数据只在本浏览器、如何导出练习数据，以及如何用键盘打开详情。请一位同学照做并记录他的第一个卡点。

## 任务 40 | 整理树洞网页代码

前置：[导入和导出本地树洞](/level/10?task=157)。

### 操作步骤

1. 在 VS Code 左侧依次打开 `index.html`、`styles.css` 和 `app.js`。用关键词搜索列表、发帖与保存函数。列出「看内容在哪里生成」「按钮在哪里监听」「数据在哪里保存」三处。
2. 给对应函数加一句简短的说明，像 `// 成功提交后将新帖子保存到本地`。每改一处先保存，然后用同样的合成帖发一条评论验证。当前练习保持初始化语句和事件绑定顺序。
3. 若注释后功能坏了，去控制台看第一条报错并定位行号，排除注释符号误删。将一处改坏的语句修正后再继续。

### 预期结果

函数职责能从代码看清，原流程仍可完成。

### 提交

交文件树和一次写帖后保存的路径。

## 任务 41 | 让手机也容易回帖

前置：[整理树洞网页代码](/level/11?task=40)。[查看窄屏和换行验证](/level/11?guide=1)。

### 操作步骤

1. 打开网页，在 Edge 或 Chrome 右键「检查」，点设备工具栏小手机图标，切到响应式 360px。选一条长标题的练习帖，打开详情并滚到评论表单。
2. 写一句评论并发送。文字、按钮和返回链接都应该在视口内。若正文中的换行没有按原样显示，在 `styles.css` 末尾加窄屏参考里 `#detail-body` 的样式规则。
3. 保存刷新复测，最后关掉设备模式观察桌面版本。如果移动端无意横向滚动，先看很长的单词、图片或按钮是否越过卡片，再用窄屏参考里的换行和宽度规则修正。

### 预期结果

窄屏能读全文、发送评论和返回，桌面布局未破坏。

### 提交

交两个宽度下的详情及发送结果。

## 任务 42 | 处理损坏的数据

前置：[让手机也容易回帖](/level/11?task=41)。

### 操作步骤

1. 点「导出练习数据」，在下载列表确认能找到完好的 JSON。到 Application 只修改当前来源的 `campus-treehole:v1`。把值换成一个左大括号，回车并刷新。
2. 记录提示与页面能否继续浏览。再把 Value 改成合法 JSON 但未知版本，例如 `{"version":99,"posts":[]}`，刷新。比较两种提示。
3. 回网页用完好 JSON 导回，确认帖数、草稿和回复恢复。如果选错来源，回浏览器地址栏读出当前协议、主机与端口，重新定位存储面板。

### 预期结果

读取失败有提示与示例，导入备份后原数据恢复。

### 提交

交两种提示和恢复后结果。

## 任务 43 | 用键盘走完整流程

前置：[处理损坏的数据](/level/11?task=42)。[查看焦点设置](/level/11?guide=1)。

### 操作步骤

1. 给 HTML 的详情标题和列表标题加 `tabindex="-1"`，按键盘操作参考在 `showPost` 与返回事件里加焦点定位。保存后关闭开发者工具并刷新。
2. 不碰鼠标，按 Tab 逐个定位搜索框、话题和「打开详情」。看见按钮焦点后按 Enter，定位应落在详情标题。继续 Tab 到评论框和发送按钮。
3. 可用 Shift+Tab 回到上一个控件。从返回按钮回列表后，核对下一次 Tab 的位置。若焦点完全看不见，检查 CSS 的 `:focus-visible` 是否被去掉或覆盖。

### 预期结果

每一步有可见焦点，详情打开后焦点落在标题。

### 提交

交实际按键顺序和可见焦点。
