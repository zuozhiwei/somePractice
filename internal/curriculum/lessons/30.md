# 把一份可以交接的代码交给同学

进入 `task-board`。找一位同学扮演第一次拿到仓库的维护者；独自学习时，用一个新目录模拟。先把当前版本提交，在仓库中新建 `docs/regression.md`，写下提交编号、Java 与 Node 版本、练习库初始化步骤。运行前后端各自的构建和测试。接口能成功还不够，例如将空标题发给新建接口后，列表里也不应多一行。

| 场景 | 操作 | 核对 |
| --- | --- | --- |
| 合法创建 | A 创建“验收一” | 返回成功，A 的列表能按 id 找到 |
| 空标题 | A 提交空格 | 返回输入错误，记录数未增加 |
| 会话过期 | 退出后查列表 | 要求重新登录 |
| 用户隔离 | B 打开自己的列表 | 找不到 A 新建的任务 |

多环境练习可先用无副作用的例子。在 `src/main/resources/application-dev.properties` 写 `server.port=8081`，在 `application-prod.properties` 写 `server.port=8082`。在终端切换 `SPRING_PROFILES_ACTIVE` 后重新启动；两个 profile 在本次练习均指向独立的本机练习库。真正交付时从环境读取数据库地址、用户名和密码，示例配置只列变量名。

## 任务 112 | 代码规范复查

挑选一个控制器及其服务，检查同一概念是否有两种叫法、是否遗留调试输出、返回值与实际内容是否一致。每次只改一类问题，再运行已有测试。提交至少三项检查结果及一段修正前后对照；原本合格的项目写出核对依据。

## 任务 113 | 接口与异常回归测试

将表中四种场景加上编辑、删除和资源不存在，逐一记录请求、状态码、可重复的数据和预期。用第二个新建账号复核隔离，截图隐藏令牌。提交回归表，并展示发现问题后重新运行的那一行。

## 任务 114 | 提交规范化系统

用新目录获取自己的提交，按 README 启动前端、后端与本机练习库。请一位同学用文档完成新增和删除；独学可录下从干净目录到首次成功的全过程。交提交编号、启动说明、回归报告，以及当时必须补写的一句说明。

## 任务 162 | 多环境配置（dev/prod）

在 PowerShell 输入 $env:SPRING_PROFILES_ACTIVE='dev'（Linux/macOS 用 export SPRING_PROFILES_ACTIVE=dev），启动并核对日志与 8081 端口。停掉该进程，改为 prod 再从 8082 访问。提交两个 profile 的非敏感片段与两次结果；数据库配置用占位变量，整份环境文件留在本机。
