# 交付第一个可治理版本

合并第 28 关的治理边界和第 29 关的接口文档，选一条帖子走完访客浏览、登录后评论、作者查看回复、第三方举报、审核隐藏和审核撤销。用户身份不能从公开响应、错误内容或客户端缓存的数据中读出。确认作者的会话被其他测试账号取代时，私有页面会清除并重新获取数据。

开发环境用合成数据及本地数据库。试运行使用独立的数据库和环境变量。给仓库打一枚 `v0.5-governance` 标签，记录迁移顺序、初始审核角色的配置方式、测试结果和暂缓功能。

### 配置与空库预演

测试只使用开发库及合成账号。**环境配置**决定一个应用去哪里找数据库和使用哪个端口。**Profile** 是 Spring Boot 中给特定环境追加配置的名称。新建根目录 `.env.example`，写下三个数据库变量、运行端口和 Spring profile 名，值保留例子。一份真实配置仅留本机。没有通过脚本加载时，Spring Boot 不会自行读取 .env 文件，仍按第 15 关方式设置环境变量后启动。

```properties
# server/src/main/resources/application-staging.properties
server.address=127.0.0.1
spring.jpa.hibernate.ddl-auto=validate
server.servlet.session.cookie.http-only=true
```

这个配置用于本机的试运行预演，正式 HTTPS 与安全 Cookie 在第 40 关设置。全新空库按 `01 → 03 → 04 → 05 → 06` 执行。跳过旧阶段的 02 合成样例，启动后通过页面注册和发布，再在自己的开发库单独配置审核员。另建本地的试运行库时，先在客户端选择该库再执行迁移并设置正确的 JDBC 地址。

在仓库根目录保存 `.env.example`。实际的运行值仍按 [第15关设置环境变量](/level/15?task=54)，文件只帮助同学知道有哪些参数。

```dotenv
SPRING_PROFILES_ACTIVE=staging
SERVER_PORT=8082
SPRING_DATASOURCE_URL=jdbc:mysql://localhost:3306/campus_treehole_stage
SPRING_DATASOURCE_USERNAME=treehole_stage_app
SPRING_DATASOURCE_PASSWORD=<在自己的终端填写>
```

用专门启动本机试运行后端的终端执行下面的两条命令。三个数据库变量按上面链接设置为试运行库和账号的实际值。

:::windows

```powershell
$env:SPRING_PROFILES_ACTIVE = 'staging'
$env:SERVER_PORT = '8082'
```

:::

:::mac linux

```bash
export SPRING_PROFILES_ACTIVE=staging
export SERVER_PORT=8082
```

:::

## 任务 112 | 复查公开和私有的数据边界

### 操作步骤

按 [第28关治理流](/level/28?task=108) 在单一作品里重跑。如果你已经有 `docs/moderation-check.md`，继续添加一张「正式交付前」表，无需另开项目。

1. 用 `docs/moderation-check.md` 建一张访客、成员甲、举报人乙和审核员的对照表。用同一帖走发帖、评论、新回复、举报、隐藏、私有处置理由、撤销。
2. 在网络面板看公开列表、详情、评论和旧链接。公开字段只包含约定内容。私有页切换账号立即清空旧值。若旧结果在切换后回来，修复第 23 关会话序号判断。
3. 用合成数据测一遍隐藏帖 API 的 404，并对照审核记录与私有状态。公开结果中不出现后台审核备注或个人账号。

### 验收与排查

围绕一个帖子 ID 能定位全部操作，匿名读路径不会返回隐藏正文，换账号不会显示旧回复。如果私有从另一个账号可读，先复看第 23 关的 `p.owner_id=?` 等约束。

### 提交

表格和一处隐私问题的检查来源。

## 任务 162 | 为试运行准备一份可读配置

### 操作步骤

[本地运行说明](/level/18?task=67) 已有基础。本次作为第 37 关部署前的预演，在自己电脑并行区分新的库和端口。

1. 按 [本关参考资料「配置与空库预演」](/level/30?guide=1#配置与空库预演) 建 `.env.example` 和 `application-staging.properties`。用 [已经掌握的建库操作](/level/14?task=50) 在同一个开发 MySQL 创建一个新的练习库 `campus_treehole_stage` 和权限受限的应用账号。迁移用独立管理员连接，先确认 `SELECT DATABASE();` 显示新库。
2. 从 01、03、04、05、06 依次运行迁移。按 [数据源变量方法](/level/15?task=54) 配置这个终端的 URL、账号和密码，使它连接试运行库。用本关参考资料「配置与空库预演」中的两条命令启用 `staging` 和端口 8082。用同一终端运行 Java，从 `http://localhost:8082/api/posts` 应读到新环境。
3. 在专用终端停止该副本后，执行下面的命令移除 URL，再启动一次。预期是无法确定数据源，记下一句可读错误。恢复正确变量，再重启成功。

:::windows

```powershell
Remove-Item Env:SPRING_DATASOURCE_URL
```

:::

:::mac linux

```bash
unset SPRING_DATASOURCE_URL
```

:::

### 验收与排查

正确配置下 `8082/api/posts` 成功，URL 缺失时明确启动失败。若 8082 被占用，先停止你此前自己启动的副本，或换成 8083 并更新验证 URL。

### 提交

只含占位符的配置模板、迁移顺序和一次诊断后恢复的证据。
