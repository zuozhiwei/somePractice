# 交付树洞原型

### 开始前

本关的用户是第一次拿到你作品的同学。先保存一个完整的版本，再从一个空目录试，不用编辑器里已经打开的原始路径。 [上一步](/level/5?task=23)

### 试用步骤

现在同一项目应该包含 `index.html`、`styles.css` 和 `app.js`，三份文件都在 `web` 内。根目录的 README 是同学第一次接手时的入口。在原说明后添加试用步骤。

1. 从 `web/index.html` 打开网页。
2. 找一篇示例帖，点「打开详情」，写一条用来测试的回复。
3. 回到列表，点「写一条」，先保存未发草稿，试「恢复草稿」，再补全发布。
4. 关闭或刷新时，当前版本产生的回复和草稿会清除。下一章会保存这些操作。

请同学用你给的 ZIP 复现这四步。用第 1 关方法整体压缩，再在一个新的检查文件夹解压。倘若页面没有样式或按钮不动，先看解压副本里是否漏掉 CSS、JS，地址栏应该指向解压目录中真正的 `index.html`。将已验收的压缩包命名为 `campus-treehole-v0.1.zip`，继续在原项目写下一章。

## 任务 24 | 提交可试玩的树洞页面

前置：[验证完整匿名体验](/level/5?task=23)。[查看同伴的试用步骤](/level/6?guide=1)。

### 操作步骤

1. 在 VS Code 左侧展开 `campus-treehole/web`，检查 `index.html`、`styles.css`、`app.js` 都在。双击根目录的 `README.md`，把「试用步骤」里的流程逐行写进去，再补一行当前版本刷新会清除本次新评论。保存。
2. 按第 1 关做法在外层打包整个目录，文件名用 `campus-treehole-v0.1.zip`。先在与原项目分开的空文件夹解包，确认副本的三个源文件与 README 都在，再双击网页。
3. 把这份练习包交给一位同学。请他从自己的新目录解压，照 README 完成打开详情、评论、保存/恢复草稿和发帖。记录他停住的一步。
4. 在原来的项目改一处说明或交互，重新打包复核同一步。副本没有样式或按钮没反应时，先检查是否只压缩了 index.html、或者地址栏打开了还没解压的归档。

### 预期结果

同学照文档从空目录复现，页面显示自己的练习帖子和回复。

### 提交

交 ZIP 或仓库版本，附复现步骤、成功证据和你实际改过的一点。
