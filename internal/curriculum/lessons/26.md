# 让审核员能处理举报

建立开发专用的审核员账号。Spring Security 在服务端保护 `/api/mod/**`，不接受由浏览器传来的角色。新增 `GET /api/mod/reports?status=OPEN` 和 `PATCH /api/mod/reports/{id}`，后者接收 `decision`（`DISMISS` 或 `HIDE`）与 `reason`。区分举报状态 `OPEN/DISMISSED/ACTIONED` 与帖子状态 `VISIBLE/HIDDEN`。审核员驳回时帖子保持可见。确认隐藏时在事务中写帖子状态、举报结果与审核记录。用条件更新锁住尚未处理的举报，晚到的第二个决定返回 409。

集中维护公开可见条件。匿名列表、搜索、直接链接和评论路径都要排除隐藏帖子。提供 `GET /api/me/posts`，通过当前会话读取自己的帖子，在私有页面显示处理原因和时间。治理后台输出供审核所需的字段，审核人员的账号和举报人的身份只留在内部审计记录里。

### 增加审核角色与处理记录

将以下迁移保存到 `server/db/06-moderation.sql`。`MEMBER` 是普通帐号，`MODERATOR` 是审核员。在已注册的本地练习账号中选一个专用账号，将角色设置为 MODERATOR。切换角色后重新登录，让新会话读取数据库的角色。

```sql

                  ADD COLUMN active_decision_id BIGINT NULL;
CREATE TABLE moderation_actions (
    id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
    report_id BIGINT NOT NULL,
    post_id BIGINT NOT NULL,

    reason VARCHAR(300) NOT NULL,

);
```

运行脚本前在管理员客户端选中开发库。脚本完成后，另在这个本地连接运行 `UPDATE users SET role='MODERATOR' WHERE username='moderator_demo';`，账号换成你刚注册的合成审核员。正式环境单独分配审核角色。

在 `ModerationService` 的公共 `decide` 方法添加 `@Transactional`。事务内查阅 OPEN 举报和仍存在的帖子，执行一次 `UPDATE reports ... WHERE id=? AND status='OPEN'`，返回行数必须等于 1。然后写一行审核记录。HIDE 时检查帖子仍可见，用这次审核 ID 更新 `posts.status` 与 `posts.active_decision_id`；如果条件失败，抛出运行时异常返回 409，让已改记录一起撤销。DISMISS 时保留帖子原状。

在 `ModerationService` 的类体末尾添加下段。用 `FOR UPDATE` 锁住当前举报行直至本事务结束。`LAST_INSERT_ID()` 在同一数据库连接中读取刚写的记录 ID。`@Transactional` 为该调用保持连接并在业务异常时回滚。这样已经发生的写入不会留下一半。

```java
private record ReportRow(Long postId, String status) {}

private ReportRow lockReport(Long id) {
    var rows = jdbc.query("SELECT post_id,status FROM reports WHERE id=? FOR UPDATE",
        (row, index) -> new ReportRow(row.getObject("post_id", Long.class),
            row.getString("status")), id);
    if (rows.isEmpty()) throw new GovProblem(404, "REPORT_NOT_FOUND", "找不到这条举报");
    return rows.get(0);
}

private Long saveAction(Long reportId, Long postId, Long actorId, String decision, String reason) {
    jdbc.update("""
        INSERT INTO moderation_actions(report_id,post_id,actor_id,decision,reason,created_at)
        VALUES (?,?,?,?,?,UTC_TIMESTAMP(6))
        """, reportId, postId, actorId, decision, reason);
    return jdbc.queryForObject("SELECT LAST_INSERT_ID()", Long.class);
}

@Transactional
public Map<String, Object> decide(Long id, ModerationController.Decision input, Principal principal) {
    boolean hide = "HIDE".equals(input.decision());
    if (!hide && !"DISMISS".equals(input.decision())) {
        throw new GovProblem(400, "INVALID_DECISION", "请选择隐藏或驳回");
    }
    String reason = input.reason() == null ? "" : input.reason().trim();
    if (reason.isEmpty() || reason.length() > 300) {
        throw new GovProblem(400, "INVALID_DECISION_REASON", "请填写 1 到 300 字的处理理由");
    }

    ReportRow report = lockReport(id);
    if (!"OPEN".equals(report.status()) || report.postId() == null) {
        throw new GovProblem(409, "REPORT_CHANGED", "这条举报已更新");
    }
    String status = hide ? "ACTIONED" : "DISMISSED";
    int changed = jdbc.update("""
        UPDATE reports SET status=?, resolution_reason=? WHERE id=? AND status='OPEN'
        """, status, reason, id);
    if (changed != 1) throw new GovProblem(409, "REPORT_CHANGED", "这条举报已更新");

    Long actionId = saveAction(id, report.postId(), current.id(principal), input.decision(), reason);
    if (hide && jdbc.update("""
        UPDATE posts SET status='HIDDEN', active_decision_id=? WHERE id=? AND status='VISIBLE'
        """, actionId, report.postId()) != 1) {
        throw new GovProblem(409, "POST_CHANGED", "这条帖子当前无法隐藏");
    }
    return Map.of("id", id, "status", status);
}
```

## 任务 101 | 在审核台解释治理状态

### 操作步骤

[治理事务](/level/26?task=99) 和 [隐藏验证](/level/26?task=100) 通过后接页面。正常从现有账号区登录，审核入口使用同源地址。

1. 在 `web/moderation.html` 保存 [本关参考资料「审核台接线」](/level/26?guide=1#审核台接线) 的完整页面。以审核账号从首页登录，再在同源地址打开 `http://localhost:5173/moderation.html`。
2. 点一条 OPEN 举报，选择隐藏、输入「处置界面演练」并确认。完成后选择 ACTIONED，检查同一条举报的状态。普通账号打开同一个页面只会得到无权限提示。
3. 两个独立审核窗口都先打开同一条待处理举报。第一个处理后，第二个提交应提示状态变更。要测试离线时保留理由，用浏览器开发者工具把网络切成 Offline，恢复后使用同一输入。

### 验收与排查

屏幕显示处理结果或能重试的失败，重复操作是 409，有缘由。若请求 403，按 [身份核对方法](/level/26?task=98) 确认当前角色，勿改开放规则。

### 提交

操作前的确认、成功状态及一次恢复后的实际结果。
