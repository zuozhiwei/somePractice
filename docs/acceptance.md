# 迁移和部署验收记录

测试日期：2026-11-01。以下测试均未对现有生产 PostgreSQL 写入，也未在生产服务器安装或切换服务。

- 从生产 PostgreSQL 的只读一致性快照迁移：17 张表、1806 行；表记录数与逐行规范化内容摘要一致，SQLite `integrity_check` 为 `ok`。
- 发现 2 条聊天成员指向已删除用户。`skilltree-repair` 在离线副本归档后移出活跃表，随后成功启用 schema 3 的关系触发器及关键唯一索引。未修复的副本和旧库保留；正式切换必须先停写并重新迁移最新数据。
- `go test ./...`、`go vet ./...` 通过；在 Ubuntu 环境运行 `go test -race ./internal/api ./internal/store` 通过。
- 自动化覆盖密码登录、注册权限、关卡解锁、作业提交、人工审核、AI 模拟响应和次数限制、经验防重、师徒与聊天授权、30 个 WebSocket 接收端、SMTP STARTTLS 模拟服务、七牛上传策略和签名、SQLite 备份及迁移异常归档。
- 在 Ubuntu 用户级 systemd 的隔离目录中验证 Linux amd64 程序：注册、地图、任务、提交、人工审核、经验、重启持久化与在线备份恢复通过。该测试使用临时合成数据，不等同于目标机器 systemd 单元的现场安装。
- 在 Ubuntu 隔离环境使用生产数据副本进行读取压测：90 个请求、30 个并发工作线程，覆盖进度、关卡树和冒险任务；本次中位数 0.034 秒、P95 0.147 秒、最大 0.161 秒，服务 RSS 约 20.3 MiB。数字仅代表当前测试环境和当次负载，不是目标 2 核 2 GB 服务器的保证。
- 已用只读请求对照 Java 生产接口：资料、地图列表、进度、地图详情、任务、NPC 指引和冒险任务匹配。排行榜经验相同的用户采用稳定 ID 排序；七牛地址的签名依赖实际环境配置。

- 七牛、DeepSeek、SMTP 已用本地模拟测试；本环境未取得可用于实际 DeepSeek 和 SMTP 联调的配置，七牛真实上传也未执行。生产部署后须配置实际密钥、域名和邮箱并做连接验证。
